## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) C5；
[API 规格](../../docs/backend/api-spec.md) §5、[安全架构](../../docs/architecture/security.md)、
[数据库设计](../../docs/backend/db-design.md)。

实现元库组织管理与 ACL 管理平面：

1. **持久层**（`ptmcp-persistence` 新包 `local.ptmcp.persistence.org`）：
   - `V5__admin_org_management.sql`：sys_dept/sys_role 版本列与 CHECK；sys_role_permission；
     sys_user_profile（status ACTIVE/DISABLED、乐观锁 version）。
   - `OrgStore`：部门（建/改/移树含环检测与后代 ancestors 重建/删含占用阻断/查）、
     角色（role_key 规则与去重、权限码、删除被成员或 ACTIVE ACL 占用阻断）、
     用户（用户名归一化小写、部门/角色校验、登录名唯一、profile 写入）。
   - `AclGrantStore`：授权草稿校验、主体/资源存在性与代次匹配、归一化内容重复 →
     `DUPLICATE_GRANT`、撤销幂等（同版本重放返回现值，旧版本 → `VERSION_CONFLICT`）、过滤列表。
   - `IdempotencyRecorder`：(actor, route, key) 占据协议——request_hash 不符
     `IDEMPOTENCY_KEY_REUSED`，SUCCEEDED 重放，RUNNING 未过期 `OPERATION_IN_PROGRESS`，
     FAILED/过期删除重占，完成态回写（0 行 → `OPERATION_UNKNOWN` 概念由调用方兜底）。
   - `AclDirectory`：主体 scope（部门祖先链 + 启用角色）、ACTIVE 授权投影为
     `common.authz.GrantRow`、DATASOURCE→NAMESPACE→OBJECT 资源树、`preview` 仅判定不借业务
     连接（未知资源闭式拒绝；平台封顶 `platform_scope` 走祖先链覆盖判定）。
   - `SelfEscalationGuard`：变更前后全树 `expand+evaluate` 对比，meta/read 任一增益 →
     `SELF_PRIVILEGE_ESCALATION`。
2. **API 层**（`ptmcp-admin` 新包 `local.ptmcp.admin.api`）：
   - `/api/v1/admin/departments|roles|users|users/{id}/status|roles|department`、
     `/api/v1/admin/acl/grants`（POST/PUT/DELETE=撤销）、`/api/v1/admin/acl/preview`。
   - 写路径 `If-Match` 乐观锁（缺失 `PRECONDITION_REQUIRED`，失配 `VERSION_CONFLICT`），
     响应 ETag；DELETE 撤销返回 REVOKED 实体。
   - `AdminPrincipal`（请求属性）+ `TestPrincipalFilter`（仅测试通道，X-Test-User-Id/
     X-Test-Platform-Admin；正式会话由 T17-api-b 替换）；非平台管理员
     `MANAGEMENT_SCOPE_DENIED`，匿名 `AUTHENTICATION_REQUIRED`。
   - `AclGrantAdminController` 对 ACL 授予/替换先过 `SelfEscalationGuard`（以调用者现存授权
     为 before，变更后集合为 after），403 拦截且不落任何行。
   - `AdminStoresConfiguration` 以 `@ConditionalOnProperty("ptmcp.admin.datasource.url")` 装配
     Hikari 元库连接与各 Store/Controller，A4 无数据源启动用例不受影响。
3. **不做**：R<T> 响应封装（A4 未落地，DTO 直出，待封装接入）；Idempotency-Key 头部接入
   controller 层（Store 层协议已测，接缝记录在交接）；用户角色分配/部门移动路径的自增权
   复查（记录为后续）；会话鉴权（T17-api-b）。

## 结果与证据

- `OrgManagementStoreTest`：12/12 绿（多轮，最终一轮 21.5s）。
- `AdminApiTest`：5/5 绿；`AdminApplicationHttpStartupTest`：2/2 绿。
- 本轮修复的真问题（非环境）：`deleteRole` 成员查询漏绑 `role_id` 参数（SQLException
  被外层映射为 DEPENDENCY_UNAVAILABLE）；duplicate grant 归一化比对从 `valid_from =`
  改为时间窗重叠；自增权预演使用 `Long.MAX_VALUE` 占位 grantId；控制器组件扫描与
  配置重复装配改为条件装配。
- 环境抖动：WSL Docker TLS 转发多次瞬断（Communications link failure / Could not find a
  valid Docker environment），失败点每轮不同且单跑即绿，未改断言、未降阈值。
- 测试夹具加固（仅传输层）：`OrgManagementStoreTest` 与 `AdminApiTest` 对
  `CommunicationsException`/`ConnectException`/`SocketTimeoutException` 做最多 5 次、
  2s×次数退避的连接重试；Flyway 迁移同样只对传输层失败重试。用例集合、断言与失败条件不变，
  非传输层 SQL 错误仍立即失败。
- `python scripts/check.py --all --maven-cache-seed D:/config/ptmcp/cache/maven`：
  PASS（2026-10-25 02:46，文档检查、Maven verify、pnpm lint/format/typecheck/build 全通过）。

## 交接

- user_id 采用 MAX+1 单实例假设，并发建用户可能冲突，正式会话接入后如需并发扩容
  再引入序列或租约。
- 自增权守卫仅覆盖 ACL 授予/替换/撤销；`PUT /users/{id}/roles` 与部门移动可间接改变
  主体授权集合，按 api-spec §5 记为后续增强。
- Idempotency-Key 头部尚未在 controller 接线，`IdempotencyRecorder` 协议已在 Store 层
  验证；接入点为 POST /acl/grants 与各 POST 创建端点。
- TestPrincipalFilter 仅测试通道，T17-api-b 以 PTMCP_ADMIN_SESSION 会话 + CSRF 替换。
