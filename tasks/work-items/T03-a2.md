## 实施与验证

冻结小合同（实施前）：

- 包内 `SecurityChangeTransaction(DataSource primaryMetadata)`，唯一写方法 `execute(SecurityEvent, Change)`；Change 为包内 JDBC 回调，先锁 singleton 后才交同一 Connection。DataSource 必须为独占新借出的元库主库连接，拒绝已在事务中的连接和 read_only/super_read_only 端点；固定 READ_COMMITTED、readOnly=false、autocommit=false、UTC，5 秒全局锁等待/协调器语句预算。调用方提供的仓储命令必须是有界本地 DML，不允许事务控制/DDL/反向锁/网络/Redis；跨用户与聚合按 db-design §7 排序。包内回调是受信代码能力，不是防恶意 Java 的沙箱。
- SecurityEvent 仅 UUID eventId、受限事件类型（类型同时固定聚合类型及 ID 种类）、正 long 或 UUID 聚合 ID、正 version。payload 仅固定 schemaVersion/aggregateId/version，无自由 Map、reason、secret 或 SQL。ID 是服务端仓储身份，不认证外部请求。非法参数在借连接前拒绝。
- singleton FOR UPDATE → 受信行回调 → epoch 增一 → 事件插入 → commit。缺 singleton/非正或溢出 epoch 失败关闭；事件重复拒绝而非成功重放。UTC 由数据库 UTC_TIMESTAMP(6) 生成，合法变更显式 update_time，事件初始时间相同。
- Receipt 只在 commit 确认后返回 eventId/epoch/cleanupFailed。提交异常一律 OPERATION_UNKNOWN，即使随后 rollback 成功也不猜未提交；非提交阶段错误整组 rollback（rollback 无法确认也 UNKNOWN）。已确认提交不被 close 异常覆盖，清理失败反映在 receipt。不自动重试、不透传底层异常文本/cause/suppressed；外部发布/Redis只能 receipt 后进行，不由协调器执行。
- 错误仅复用已登记 DomainException：INVALID_ARGUMENT、SECURITY_STATE_UNAVAILABLE、IDEMPOTENCY_KEY_REUSED、DEPENDENCY_UNAVAILABLE、INTERNAL_ERROR、OPERATION_UNKNOWN。

TDD：先可执行失败测试，再最小实现，再 formatter/定向 verify/root check/自审。独立 MySQL 8.4 Testcontainers 合成库，无 Docker 必须失败，不 skip。保留 a1 原 7 测试及断言；本片独立 fixture，不抽取/修改 a1。成功与新连接核验、回调失败/重复 eventId 整组回滚、并发 epoch 不丢失且先锁全局、溢出/缺 singleton/非法输入、真实 Connection 包装注入 commit 前后异常及 close 异常。主 Agent 负责集成后 --all 和独立安全评审。

- 失败原子性：回调 SQLException/RuntimeException/DomainException/AssertionError、重复 eventId 后新连接核验整组无残留；重复事件发生在行变更和 epoch 更新之后，仍全部回滚。缺 singleton、Long.MAX_VALUE 耗尽在回调前拒绝；Long.MAX_VALUE-1→Long.MAX_VALUE 成功，下一次拒绝不绕回。非法/null/非正 ID/version/ID 类型不匹配在借连接前拒绝；已有事务不加入、不提交。
- 故障注入仅包装真实 JDBC Connection：commit 之前抛错（服务端未提交）和真实 commit 之后抛错（服务端已提交）都返回 OPERATION_UNKNOWN，commit 调用各一次、不重试；真实 rollback 后确认丢失也 UNKNOWN。真实 close 后抛错时，已确认提交仍返回 receipt 且 cleanupFailed=true；回调失败+close 失败不覆盖原错误。所有 DomainException 仅注册错误码，message=码名、cause=null、suppressed 为空，合成敏感文本不透传。包装不是替代实库事务的 mock。
