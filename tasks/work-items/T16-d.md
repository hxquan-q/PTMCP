## 目标与边界

来源/父任务：T16 父任务；[API 规格](../../docs/backend/api-spec.md) §5（/audit 端点）、
[审计设计](../../docs/backend/audit.md) §5（访问控制与解密审计）、
[数据库设计](../../docs/backend/db-design.md) §6（audit_sensitive_access）、
T09-c（SqlFieldCipher）、T16-b（DelegationStore）。

实现审计管理 API：GET /api/v1/admin/audit（列表）、GET /{requestId}（详情）、
POST /{requestId}/decrypt（受控解密）。三权限分离（audit:list/read/decrypt），
默认只返回脱敏 SQL，解密需独立委派+资源范围+reason(10..500)，解密访问先持久
audit_sensitive_access（ALLOW/DENY）再返回 no-store 明文，保留期 180 天外 404，
列表窗口 ≤31 天。不做：CSRF（T17-api-b 会话切片）；审计事件外发；guard OutputPlan。

## 实施与验证

### 生产代码

- `AuditAdminStore`（persistence/audit 新增）：列表（全部过滤在 SQL 内含游标分页，
  不返回密文列）；详情（不含密文列，保留期外 RESOURCE_NOT_FOUND）；sensitive_access
  持久化；decrypt 输入加载（cipher/key_id/startedAt）。
- `AuditAdminController`（admin/api 新增）：三个端点 + 解密流程（先持久审计→解密→
  no-store 返回）；委派门控（AuditGate.isAllowed）。
- `AuditGate`（admin/api 新增）：audit:list/read/decrypt 三权限分离；平台管理员对
  list/read 直通；decrypt 始终需要委派（allowedActions 含 "audit:decrypt"）覆盖
  审计记录的 datasource。
- `SqlFieldCipher`：新增 `decryptForAudit` 方法（API 字段名 "sqlRaw"/"sqlFinal" 到内部
  列名映射）。
- `AdminStoresConfiguration`：+AuditAdminStore Bean + auditKeyResolver Bean（KMS 待
  T19-b 接线，本切片注入配置化 stub）。

### 测试（真实 MySQL 8.4 容器 + MockMvc，9 例，`AuditAdminApiTest`）

1. 列表返回摘要（不含密文）✓ 编写
2. 列表窗口 >31 天拒绝 ✓ 编写
3. 详情返回脱敏 SQL 不含密文/原文 ✓ 编写
4. 平台管理员解密 → no-store + 明文 + ALLOW 审计 ✓ 编写
5. 非平台管理员无委派解密 → 拒绝 ✓ 编写
6. 委派含 audit:decrypt → 允许 + ALLOW 审计 ✓ 编写
7. reason < 10 字符 → 400 ✓ 编写
8. 不存在 requestId → 404 ✓ 编写
9. 保留期外（>180 天）→ 404 ✓ 编写
