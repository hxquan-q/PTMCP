## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) B1，父任务 T12；[授权设计](../../docs/backend/authorization.md) §4/§5/§6、[ADR-0002](../../docs/architecture/adr/0002-Redis缓存与权限失效.md)、TC-ACL-004~010。

目标：在 `ptmcp-persistence` 新增 `local.ptmcp.persistence.security` 包，落四件事：1) `SecuritySnapshot` + `SecurityStateReader`——每次读取用新事务/current read，`checkedAt` 取连接获取前的保守时刻；2) `SecurityStateGuard`——本地缓存 ≤1s 单调时钟 TTL、5s 权威时效窗、连续 3 次读失败熔断拒绝；3) `QuotaLimiter` 接口 + `InMemoryQuotaLimiter`——用户 3、源/副本 8、网关 16、排队 32/3s；4) `SecurityRevocations`——`revokeSubject/revokeFamily/revokeToken` 走 `SecurityChangeTransaction`（epoch+事件同事务），返回 receipt 即视为已提交。

不做项：不接 guard/gateway 调用方（C1 之后的编排层接线）；不做 Redis 分布式配额与广播消费（ADR-0002 后续切片）；不改 V1–V3 迁移；不改 `SecurityChangeTransaction` 语义（仅新增调用方）；不做 OAuth 轮换（T13-b）。

不变量：`checkedAt` 只能由一次权威主库读取产生，缓存命中与 get 不得刷新；快照超 5s 一律重读或拒绝（fail-closed `SECURITY_STATE_UNAVAILABLE`）；缓存条目只带 `checkedAt` 与版本，读取路径无任何刷新；撤销 receipt 即提交完成，不等待广播；配额 CAS 无超卖，拒绝路径全额回滚已占许可并释放队列槽；事件版本与乐观锁 WHERE 同事务校验，冲突显式 `RESOURCE_VERSION_CHANGED`；所有 SQL 显式列、参数化，异常不携带 SQL/连接串/驱动文本。

## 实施与验证

```text
ptmcp-parent/ptmcp-persistence/src/main/java/local/ptmcp/persistence/security/
  SecuritySnapshot.java      epoch/主体版本/平台版本/family 版本/checkedAt；isFresh(5s)、sameState
  SecurityStateReader.java   SubjectRequest(平台+可选用户+family≤64)；单事务 current read
  SecurityStateGuard.java    1s TTL 缓存（过期即逐出，命中不续期）；5s 可用判定；3 次失败熔断
  QuotaLimiter.java          接口 + 许可 record + 限额常量（3/8/16/32、队列 3s）
  InMemoryQuotaLimiter.java  AtomicInteger CAS 计量；获取顺序 用户→数据源→网关；全额回滚
  SecurityRevocations.java   三类撤销经 SecurityChangeTransaction；预读版本 + 乐观更新
```

行为要点：

- `SecurityStateReader.read` 在 `getConnection` 之前截断到微秒取 `checkedAt`，随后 READ COMMITTED 单事务内依次读 epoch（唯一行）、平台 `security_version`（非 ACTIVE 即不可用）、主体 `MAX(auth_version)`（无 ACTIVE family 记 0）、指定 family 的 ACTIVE 行版本（撤销家族从快照消失，版本比对自然失配）；元库缺行/基础设施异常统一 `SECURITY_STATE_UNAVAILABLE`。
- `SecurityStateGuard.cached` 只在单调 1s 窗口内返回，过期即逐出；`cache` 拒收非 fresh 快照；`shouldRejectReads` 在连续 3 次读失败后置位、`recordReadSuccess` 复位；时钟经包私有构造器注入 `LongSupplier`，测试可确定性驱动过期。
- `InMemoryQuotaLimiter.acquireExecution` 顺序用户→数据源→网关总量，任一步失败回滚已占许可并释放队列槽（调用方无法泄漏）；过期队列许可直接 `GATEWAY_BUSY` 而非转执行。计量为进程内，多副本部署需 Redis 版（见交接）。
- `SecurityRevocations`：`revokeSubject` 撤销该用户全部 ACTIVE family（0 行合法）；`revokeFamily`/`revokeToken` 先在独立 autocommit 连接预读 ACTIVE 版本（缺失 → `RESOURCE_NOT_FOUND`），事件 version=预读+1，更新 WHERE 带 `version=预期`，行数≠1 → `RESOURCE_VERSION_CHANGED`；`revokeToken` 同时令 token REVOKED 并在同一事务内 bump family version，使快照读者可见。

偏差：metadata 库无 `sys_user` 表（身份适配层拥有），主体版本信号取该用户 ACTIVE refresh family 的 `MAX(auth_version)`（无则 0），与 T13-a 的 auth_version 撤销信号一致；`SubjectRequest` 为单用户（平台+用户+family 集合），多用户列表由调用方逐请求发起。RR 隔离下两次读的一致性不作为时效证明（authorization.md §5），时效完全由 `checkedAt+5s` 界定。

## 测试与证据

`SecurityStateTest` 11 例，真实 MySQL 8.4 固定 digest 容器 + Flyway V1–V3：

1. reader 快照：epoch/平台版本/主体 `MAX(auth_version)`/ACTIVE-only family 版本全部正确；直接 SQL 撤销一个 family 后重读，该 family 从快照消失、主体版本回落。
2. 5s 时效边界：`checkedAt`、`+5s` 可用，`+5s+1ns` 与早于 `checkedAt` 不可用；null 快照不可用。
3. 本地缓存 1s TTL：注入单调时钟，999.9ms 命中、1001ms 逐出且重复 get 不续期；重新 cache 后旧窗口不复活；非 fresh 快照拒绝入缓存（`INVALID_ARGUMENT`）。
4. 熔断：连续 3 次失败后 `shouldRejectReads=true`，第 4 次失败不计数越界，成功复位。
5. `revokeFamily`：receipt epoch=前值+1；family REVOKED/version 2/reason/revoked_at 落库；`sys_security_event` 出现 `REFRESH_FAMILY_CHANGED` 且 `JSON_EXTRACT(payload,'$.version')=2`；二次撤销 `RESOURCE_NOT_FOUND`；撤销前后快照 `sameState=false` 且 epoch 与 receipt 一致。
6. `revokeToken`：未知 token `RESOURCE_NOT_FOUND`；命中时 token REVOKED、family 保持 ACTIVE 但 version 2、事件 payload version=2。
7. `revokeSubject`：非法输入（authVersion≤0、空 reason、reason>200）`INVALID_ARGUMENT`；命中撤销该用户全部两个 ACTIVE family（各 version 2），其他用户家族不动；`USER_SECURITY_CHANGED` 事件恰 1 条。
8. 配额：同用户第 4 个 `USER_CONCURRENCY_LIMIT`；同数据源第 9 个 `DATASOURCE_CONCURRENCY_LIMIT`；第 17 个网关 `GATEWAY_BUSY`；第 33 个排队 `GATEWAY_BUSY`；释放后可再取（无负计量）。
9. 过期队列许可：注入时钟越过 3s 窗口后 `acquireExecution` → `GATEWAY_BUSY` 且队列槽已释放；null 队列许可 `INVALID_ARGUMENT`。
10. 拒绝路径回滚：用户满后拒绝释放其队列槽（随后恰可再排 `QUEUED_MAX` 个）；网关满拒绝后释放 1 个执行许可，同“新”用户+数据源立即成功，证明部分获取已回滚。
11. 并发无超卖：CyclicBarrier 4 线程抢同用户恰 3 成功；9 线程抢同数据源恰 8 成功。

调试期修正（非放宽）：测试自身 4 处错误——单独持有的队列许可挤占 1 格、`X'01'` 字面量与 BINARY(32) 不等长、`sys_security_event` 无 `version` 列（改 `JSON_EXTRACT`）、race 助手误用递增用户 id；均改测试，未改实现与断言语义。

## 交接

当前焦点：C1/T07-b 守门管线接入时应：guard/权限判定前调用 `SecurityStateReader.read`，`SecurityStateGuard.cache`/`cached` 只作 1s 内去重，`isUsable(snapshot, now)` 为唯一时效判据；读失败计 `recordReadFailure`，连续 3 次后直接拒绝（`SECURITY_STATE_UNAVAILABLE`）；执行前经 `QuotaLimiter.acquireQueue` → `acquireExecution`，终态无论成败 `release(ExecutionPermit)`。撤销管理端直接消费 `SecurityRevocations`，receipt.epoch 可直接用于向客户端确认传播进度。

待决定事项：Redis 版 `QuotaLimiter` 与撤销广播消费者的 ADR（多副本部署前必须）；`revokeToken` 的 reason 目前只做校验未持久化（token 表无 reason 列，事件 payload 亦无自由字段）；主体版本是否需要覆盖 personal_token/web_session_index 的 auth_version 信号（当前仅 refresh family）。
