## 目标与边界

来源：用户明确委派 T01 启动验证切片，依赖公共基线 cec14ae。将三个已有 Boot 应用的框架健康与安全错误响应固化为可重复的真实 HTTP 回归，不新增产品行为。

Given 各应用独立启动于随机端口，When Java HttpClient 请求 /actuator/health，Then HTTP 200 且返回最小健康形状 status=UP（允许框架 liveness/readiness 组名，不允许组件详情或额外字段）；When 请求专用不存在的探测路径，Then HTTP 404 且不泄漏 message、trace、stacktrace 或 exception。请求尝试显式开启错误详情也不能披露。

不改 common/guard/POM、主工作树、tasks/plan 或共享契约；不新增账户、业务控制器或查询旁路，不断言 /api/v1 路径永久不存在。认证、OAuth、MCP、SQL 和业务验收均不在范围。内部工程回归无需产品体验人工接受，不能替代安全专项评审。

## 结果与证据

首次 Spotless 误把 spotlessFiles 当 glob（src/test/java/**/*.java）导致正则解析失败，退出 1，未运行测试；改用 .*ApplicationHttpStartupTest[.]java 后 Spotless 实际格式化三文件成功，退出 0。

首次 verify 退出 1：admin 共 2 测试、1 失败；404 安全响应通过，health 的“仅 status”假设被真实 HTTP 证据推翻，Boot4.1.2 返回 {"groups":["liveness","readiness"],"status":"UP"}。authz/gateway 因 reactor fail-fast 未运行。按已有框架行为修正测试为允许上述已知组名但禁止组件详情/额外字段；不改生产配置，不将假设错误记为新功能 RED，不隐藏失败。

最终验证环境：Windows11 / Java21.0.10（Wrapper --version 实测）/ Maven3.9.9 / Boot4.1.2 / Python3.14.7。所有下列 Maven 命令均在隔离工作区 PowerShell 执行 `. ./scripts/Enter-Dev.ps1; Set-Location ptmcp-parent` 后运行：

- `./mvnw.cmd --version`：退出 0，确认 Maven 真正使用 Java21。
- `./mvnw.cmd -pl ptmcp-admin,ptmcp-authz,ptmcp-gateway spotless:apply '-DspotlessFiles=.*ApplicationHttpStartupTest[.]java'`：退出 0；实际 google-java-format AOSP，范围仅三份独占测试文件。
- `./mvnw.cmd -pl ptmcp-admin,ptmcp-authz,ptmcp-gateway -am verify`：修正健康响应假设后退出 0，六个 reactor 项目 SUCCESS；Spotless、Checkstyle（零违规）、Java/Maven Enforcer、依赖收敛和模块边界通过，三个应用编译/打包通过。
- `python scripts/check.py`（工作区根、已加载开发环境）：退出 0，75 份 Markdown / 341 处本地链接、工作流/配置检查和 26 个检查器回归通过；完成状态和记录更新后再次执行以覆盖文档变更。

HTTP 测试：admin=2、authz=2、gateway=2，共 6，failures/errors/skipped 均 0。真实监听随机端口分别为 28162 / 36456 / 45846；每应用独立 Surefire JVM 和上下文。报告在对应应用 `target/surefire-reports/TEST-local.ptmcp.<模块>.<应用>ApplicationHttpStartupTest.xml`（构建产物不提交）。每应用验证 health=200、JSON 最小形状、不泄漏组件详情，以及专用缺失路径在 trace=true/message=true 下仍 404、不含 message/trace/stacktrace/stackTrace/exception。HttpClient 连接超时 5 秒、每次请求超时 10 秒，客户端显式关闭；没有 mock HTTP。

评审为作者自审：核对三份测试仅包名/应用类不同；没有生产源码或配置覆盖，无固定端口、业务路由永久 404 断言或默认账号，没有增加共享测试基类/依赖。健康响应使用 JSON 树而非字符串顺序判断；允许探针组名但限制顶层字段数量，不能混入组件详情。已处理健康形状假设和 formatter 参数两个失败，不放宽生产安全配置。

限制：starter-test 触发 Mockito/Byte Buddy 动态 agent 警告（JDK21 下测试通过）；未修改依赖/POM 或隐藏警告。common/guard 在 cec14ae 基线没有测试，其构建成功不代表领域功能完成。不启动数据库、不读取秘密、不运行 UI 全量检查或远端 CI。认证/OAuth/MCP/SQL、ASVS 专项、产品人工接受与发布均未验证，框架回归不能替代；主 Agent 合并 common 等后须集成重验。内部工程回归完成不需要产品体验人工接受。
