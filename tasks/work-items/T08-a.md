## 目标与边界

父任务 T08；来源 authorization §2/§3/§4、总体方案 §4/§7、FR-07/FR-08、TC-ACL-001～005（判定子集）、ADR0002。目标是在 common 中以纯函数判定"某主体在某资源上此刻是否可 META / READ"，并把最近未来边界暴露给调用方。

不做：主体/角色/部门继承展开、资源树 descendant 展开、Token Scope 计算、数据源停用、快照/版本核验、缓存与 ≤5 秒撤销（T12）、REST `acl/preview`、审计。输入必须是调用方已按继承与资源树展开、且已与平台 Scope 相交前的 grant 列表；本函数只做"同资源上的 Allow/Deny + 时间窗 + 平台上限"。

## 实施与验证

`common.authz.PermissionGrant(grantId>0, effect, action, validFrom, validTo?)`：半开窗口 `[from, to)`，`validTo` 必须晚于 `validFrom`，null 表示开放；`covers(at)` 为纯判定。

`PermissionEvaluator.evaluate(grants, platformMeta, platformRead, now)`：

- 默认拒绝；`READ` Allow 隐含 META Allow；`META` Deny 同时阻断 READ；`READ` Deny 不阻断 META；同动作 Deny 优先于 Allow（与顺序无关）。
- `ResourceRead = UserRead ∩ PlatformRead`，`META = (UserMeta ∪ UserRead) ∩ PlatformMeta − MetaDeny`：平台无 META 时仍可读行但不得披露结构。
- 过期 grant 不计入；未来 grant 只在自身起点后生效；`nextBoundaryAt` 取所有相关 grant 的最近未来起点或终点（含未来 Deny 与即将到期 Allow），调用方据此失效缓存而不依赖消息。

先写测试再实现；真实失败 2 项：一是断言误写（active grant 集合应为被未来 grant 排除后的 `[2]`），二是把"平台无 META"错误地当成也禁止 READ——按契约 READ 只与 `PlatformRead` 相交，改为分别断言 `read=true, meta=false`。没有放宽实现，只修正测试对契约的表述。

## 结果与证据

`.\mvnw.cmd -B -ntp -pl ptmcp-common -am test` 退出 0：common 203 项（本片 9），0 失败/错误/跳过；日志 `.local/verification/t08-a-tests2.log`（首轮失败 `t08-a-tests1.log`）。

覆盖：无 grant 全拒；READ Allow 在窗口内同时给出 META；窗口起点前拒绝且 `nextBoundaryAt=起点`；终点为排他且到期后无边界；META Deny 阻断 READ、READ Deny 保留 META；未来 Deny 现时为 true、到点转 false 且边界为 Deny 起点；最近边界跨 grant 取最小（忽略过期）；平台 READ 上限与平台 META 缺失分别验证；Deny 与 Allow 顺序无关；非法窗口/ID/null 拒绝。

作者自审：纯 Java、无新依赖、无 Spring/若依；`Instant` UTC 比较，不涉本地时区；返回列表不可变；provenance 只含 grantId。限制：不做继承/资源树展开、不校验快照版本与主体状态、不含缓存与撤销时效；未接 REST 预览或网关；无独立安全评审。
