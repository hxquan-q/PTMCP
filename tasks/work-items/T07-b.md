## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) B1，父任务 T07；[SQL 防护设计](../../docs/backend/sql-guard.md) §6/§7。

目标：在已绑定 `ColumnBindingResult` 之上把物理关系改写为方言限定名（MySQL `database.table`、PG `schema.table`），同步改写所有限定列与 `t.*`，并在重解析后证明物理资源多重集、列来源、输出列顺序与外层 LIMIT 均符合预期。

不做项：不产生 `ApprovedQuery`（C1/T07-c 负责）；不做权限判定、审计、`max_rows` 请求参数解析；不改 `LimitRewriter` 任何断言；不改 A2 的 `ScopeTableBinder`/`ColumnBinder`/`ColumnBinding` 与其断言；不执行 SQL、不连业务库；不改共享契约/错误码/父 POM。

不变量：只改写 `physicalBindings` 中的 FROM 关系及其限定引用；显式别名保留，无别名物理表生成全语句唯一的 `__ptmcp_r<n>`；CTE/派生别名绝不改成物理表；不做字符串替换，只改 AST；未限定列与输出别名保持原样（避免混淆范围别名与输出别名两个命名域）；任何结构不一致以 `REWRITE_VALIDATION_FAILED`（150008）拒绝，且返回文本不可执行。

## 实施与验证

### 新增文件

```text
rewrite/QualifiedRewriter   AST 改写：物理 FROM 限定 + 列/星号别名同步 + 内部别名生成
rewrite/RewritePlan         重解析需保持的事实：物理关系多重集、列来源（物理别名归一）、输出列名
rewrite/RewrittenSql        text + plan；明确标注仍需 FinalSqlValidator
rewrite/FinalSqlValidator   重解析 → 只读/白名单门 → ScopeTableBinder → ColumnBinder → 逐项比较
```

### 关键实现

- 改写遍历按 A2 绑定器的同一作用域顺序进行（CTE 定义先于外层、FROM 先于投影/子句、JOIN ON 最后）；作用域 id 与范围消费数量都与绑定结果核对，错位即拒绝。这样每个 `Column`/`AllTableColumns` 都能从所属作用域解析到唯一范围，不依赖“表集合相同”。
- 限定名：MySQL 输出 `catalog.object`（解析为 `schemaName`），PG 输出 `schema.object`；对象名与别名原样写回，不改显示列标签。
- 别名：显式别名优先；无别名物理表生成 `__ptmcp_r1..n`，预扫描保留表名、显式别名与 CTE 名，生成名全语句唯一，避免相关子查询被内层同名别名遮蔽。
- 列引用：带限定符的 `table.column` / `db.table.column` 与 `t.*` 改为范围别名；未限定列与 ORDER BY/GROUP BY 输出别名不动，交由重解析保持原有绑定。
- 校验器：字节上限 → `SqlStatementGate` → `SqlAllowlistGate` → 重解析 SELECT → 比较物理关系**计数多重集**、规范化列来源有序列表、输出列名有序列表 → 外层 LIMIT 必须为期望常量；解析失败、门禁失败或任一项不等都映射为 `REWRITE_VALIDATION_FAILED`，不输出驱动/解析细节。
- MySQL 重解析：两段式 `database.table` 在 JSQLParser 中落到 `schemaName`，而 A2 的 `ResourceNamespace` 要求 MySQL schema 为空；校验器只对“刚解析的校验树”把无 database 的 schema 归一为 catalog，再绑定。SQL 文本与交给执行边的对象不受影响。

改写前后证据（测试断言）：

```text
SELECT orders.id FROM orders WHERE orders.id > 0
→ SELECT __ptmcp_r1.id FROM sales.orders AS __ptmcp_r1 WHERE __ptmcp_r1.id > 0

SELECT users.id, __ptmcp_r1.name FROM users JOIN users __ptmcp_r1 ON users.id = __ptmcp_r1.id
→ SELECT __ptmcp_r2.id, __ptmcp_r1.name FROM sales.users AS __ptmcp_r2
  JOIN sales.users __ptmcp_r1 ON __ptmcp_r2.id = __ptmcp_r1.id

WITH recent AS (SELECT o.id FROM orders o) SELECT recent.id FROM recent
→ WITH recent AS (SELECT o.id FROM sales.orders o) SELECT recent.id FROM recent

SELECT orders.id FROM orders        （MySQL）
→ SELECT __ptmcp_r1.id FROM shop.orders AS __ptmcp_r1
```

偏差与处理：

- MySQL 两段式 `database.table` 输入目前无法通过 A2 绑定（`schemaName` 非空与 MySQL 空 schema 约束冲突）。本切片只覆盖 MySQL **输出**限定与重解析归一；输入解析属 A2 契约，未擅自修改，交 C1/E1 决定是否在绑定器或方言层补齐。
- 输出标识符未强制加引号（JSQLParser `toString` 不自动 quote）；快照名若必须引用则重解析/绑定会失败并转 `REWRITE_VALIDATION_FAILED`，属 fail-closed。真实方言执行验证留待 D/E 阶段。
- LIMIT 仍由调用方复用 `LimitRewriter` 施加；校验器只验证最终文本的外层 LIMIT 精确等于期望值。`SetOperationList` 仍按 `LimitRewriter` 现状拒绝，未在本片扩展。
