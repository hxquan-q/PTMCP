## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) A2，父任务 T06；[SQL guard 契约](../../docs/backend/sql-guard.md) §4/§6。

目标：把每个列引用绑定到确定的 range 与快照列，并按快照列序展开 `*`/`t.*`；为后续改写与等价校验提供带物理来源的绑定结果。

不做项：不实现 SQL 改写（B1/T07-b）、不授权资源、不执行 SQL、不连接数据库；不改变 `ScopeTableBinder` 的 R1 行为或断言；不修改 POM。

不变量：未限定列仅当当前块候选唯一时绑定，多候选返回 `RESOURCE_AMBIGUOUS`，当前块无候选才沿相关子查询 parent 链查找，仍无返回 `INVALID_ARGUMENT`；`t.*` 只展开指定别名；CTE/派生表保留来源列集合且不冒充物理表；unresolved 非空时不进入列绑定；重复输出列名按输出 index 保留。

## 实施与验证

新增 `guard/scope` 列绑定类型：
- `ColumnDef(ordinal,name,databaseType,nullable)`、`RelationColumns.columns(ResourceRef)`：列快照由调用方提供，guard 不连库。
- `ColumnBinding(rangeAlias,kind,resource,columnName,ordinal)`、`OutputColumn(ordinal,name,sources)`、`RangeBinding(alias,kind,resource,columns,sources)`、`ScopeColumns(scopeId,parentScopeId,ranges,outputs,bindings)`、`ColumnBindingResult(primaryScope,scopes,bindings)`。
- `ColumnBinder.bind(Select, ScopeTableBinder.BindingResult, RelationColumns)`：按与 ScopeTableBinder 相同遍历顺序消费物理引用，构建 PHYSICAL/CTE/DERIVED range；展开 `*`/`t.*`；绑定 SELECT/ON/WHERE/GROUP BY/HAVING/ORDER BY；支持限定名、`catalog.schema.table.column`、相关子查询外层列；单层集合运算按列位置合并来源；CTE 显式列名数量/重名校验；遍历结束校验物理引用全部被消费，否则 `INTERNAL_ERROR`；未解析关系直接拒绝。

RED：首次全量门禁在 Spotless 阶段失败（新增文件未格式化）；格式化后 `verify` 编译通过，`ColumnBinderTest` 12 例中 2 例失败：`unknown` 为解析器保留字、自连接用例使用了不存在的 `orders.name`。修正测试输入后全绿。实现先于测试运行，本切片未形成严格 RED。

验证命令与结果：

```text
.\mvnw.cmd -B -ntp -pl ptmcp-common,ptmcp-guard -am spotless:apply
.\mvnw.cmd -B -ntp -pl ptmcp-common,ptmcp-guard -am verify
```

结果：common 210 tests、guard 183 tests，0 failures / 0 errors / 0 skipped；`BUILD SUCCESS`。新增 `ColumnBinderTest` 12 例，断言具体 range 别名、列名、列序号与物理来源：
- `s.*` 按快照列序展开并绑定到 `s`；自连接 `a`/`b` 别名不混淆；ON 子句同样绑定。
- `erp.sales.orders.id` 解析到物理资源；相关子查询外层列绑定到 parent scope。
- 未限定同名列歧义 `RESOURCE_AMBIGUOUS`；未知 `t.*`/未知关系/缺失列 `INVALID_ARGUMENT`。
- 重复输出列名按 index 保留；`t.*` 只展开命名 range；CTE/派生表输出保留底层物理来源且 resource 为空。
- 多 range `*` 输出序号连续（回归断言在 `preservesDuplicateOutputNamesByIndex` 与星号展开用例中覆盖）。
