## 目标与边界

来源/父任务：T19 父任务；接续 [T19-a](T19-a.md) 的 Tier1 fail-closed 边界。
契约：[认证设计](../../docs/backend/authentication.md) §3、[API 规格](../../docs/backend/api-spec.md)
平台证明、[部署](../../docs/ops/deploy.md) 受信代理边界。

目标：Tier1 平台不再对所有请求统一返回 `PLATFORM_PROOF_REQUIRED`，而是从主库读取平台加密
证明策略，按平台注册的 proof 模式验证每请求证明：

- MTLS：直连 TLS 的客户端证书 SHA-256 指纹，或受信代理在 `proxyCidrs` 内转发的指纹 Header；
- PROXY_SECRET：受信代理在 `proxyCidrs` 内转发的 base64 secret，恒时比较；
- 平台 tier/proofMode 仍来自已认证令牌绑定的 platform，不由请求 Header 决定。

不做项：不实现平台 proof 配置管理写入（平台 CRUD 仍为后续片）；不做证书链/有效期/吊销的
网关内验证（由 TLS 入口或代理承担）；不做 JWT cnf 绑定、secret 轮换版本表、Nginx 实机配置；
不放宽 Tier1 任何失败路径。

不变量：Tier1 proof 在任何工具执行前完成；缺少证明 403 `PLATFORM_PROOF_REQUIRED`；错误/未
受信来源 403 `PLATFORM_MISMATCH`；策略缺失/不可解密 503 `SECURITY_STATE_UNAVAILABLE`；
`X-PTMCP-*` 证明 Header 只从配置的代理 CIDR 接受；证明值不写日志、不进入审计 payload。

## 实施与验证

- 将 `PlatformProof`、`CidrRange`、`MtlsProofVerifier`、`ProxySecretProofVerifier` 从 authz
  移到 common `local.ptmcp.common.platform`，使 gateway 与 authz 共享同一证明语义；
  `CidrRange.unwrap` 公开供 CIMD 策略复用；authz 测试随实现迁移。
- `AuthorizationReader.loadPlatformProofConfig` 读取 `proof_mode/proof_config_cipher/proof_key_id`，
  只返回密文。
- `Tier1ProofVerifier`（gateway）：
  - 用部署 `credential-key` 解密密文 JSON；
  - MTLS JSON `{mode,fingerprints[],proxyCidrs[]}`；直连读取 Servlet `X509Certificate`
    属性，代理转发仅在来源 CIDR 内读取 `X-PTMCP-Client-Cert-Fingerprint`（hex SHA-256）；
  - PROXY_SECRET JSON `{mode,secret(base64),proxyCidrs[]}`；仅在来源 CIDR 内读取
    `X-PTMCP-Proxy-Secret`（base64）；
  - 配置上限（20 指纹/20 CIDR/256 字节 secret）、格式错误/模式不一致 fail-closed。
- `PatJwtAuthentication` 在令牌与 `X-Platform-ID` 一致性之后调用证明验证；
  `McpGatewayConfiguration` 装配 verifier。
- 测试：`McpTier1ProofTest` 2 例（MTLS 缺失/正确/错误/不受信来源；PROXY_SECRET 缺失/错误/正确），
  使用真实 MySQL 元库、加密 platform proof 配置与真实 HTTP `/mcp` tools/list。

验证命令：

```text
mvnw.cmd -B -ntp -pl ptmcp-authz -am verify
mvnw.cmd -B -ntp -pl ptmcp-gateway -am verify
```

未验证/边界：

- 直连 mTLS 的证书链、有效期、用途、吊销与 `X509Certificate` Servlet 属性回环未做真实 TLS
  容器联调；当前测试覆盖代理转发指纹路径。
- 受信代理（Nginx/负载均衡）来源 CIDR、外部同名 Header 剥离、secret 轮换与多副本配置同步
  未做部署联调；只在嵌入式 Tomcat 的 `127.0.0.1` 上验证。
- 平台 proof 配置写入/管理面未实现；本片通过测试直接写入加密行，生产需平台 CRUD 或运维
  受控写入路径。
- JWT `cnf` 绑定未实现；独立安全评审缺失，本片为自审候选。

评审类型：自审（解密/解析、来源 CIDR、Header 信任边界、失败码、证明值不落日志）。
