## 目标与边界

来源/父任务：T19 父任务；接续 [T10-a](T10-a.md)/[T12-a](T12-a.md) 的预算与安全状态边界，
落实 [数据源设计](../../docs/backend/datasource.md) §9 并发上限、[部署](../../docs/ops/deploy.md)
用户3/数据源8/副本16与队列32。

目标：`execute_readonly_sql` 在借业务连接前获取用户/数据源/网关三层执行许可，容量满时最多
等待一个队列窗口，超时返回 `GATEWAY_BUSY`；等待时间写入审计 `queue_ms`；获得许可后才激活池、
复核安全状态并执行；任何失败都释放许可。

不做项：不实现 Redis/多副本共享计数（当前 `InMemoryQuotaLimiter` 为单进程）；不改变
`USER_MAX=3`、`DATASOURCE_MAX=8`、`GATEWAY_MAX=16`、`QUEUED_MAX=32` 或 3 秒窗口；不做压测/
SLO；不把等待当作已执行或已授权。

不变量：许可按 user→datasource→gateway 顺序原子获取，部分获取失败全部回滚；队列许可只允许
一次执行，失败/超时释放；超时后不借业务连接；执行前仍由 `ApprovedQueryAdapter` 的 checkout
guard 复核安全状态；许可释放覆盖成功、异常和编码前路径；多副本部署仍按单进程语义记录。

## 实施与验证

- `McpToolService` 注入 `QuotaLimiter`，在 guard 通过后、池激活/执行前调用
  `awaitExecution`：
  - 每次尝试获取队列许可，再尝试 user/datasource/gateway 许可；
  - 容量拒绝时释放队列许可并最多重试 3 秒，超时 `GATEWAY_BUSY`；
  - 成功后立即进入池激活/执行，`finally` 释放执行许可；`queue_ms` 在超时和成功路径都记录。
- `McpGatewayConfiguration` 装配 `InMemoryQuotaLimiter`；未改变既有 `QuotaLimiter` 契约。
- 现有 `SecurityStateTest` 已覆盖 3/8/16/32 原子性、部分失败回滚、队列过期和拒绝释放；
  本片补真实 HTTP 接线测试。

验证命令：

```text
mvnw.cmd -B -ntp -pl ptmcp-gateway -am verify
```

未验证/边界：

- `InMemoryQuotaLimiter` 仅单进程；多副本 gateway 的全局 16/队列 32 需要 Redis/共享租约，
  当前多副本会按副本各自计数，不能宣称集群级预算。
- 集成测试只覆盖用户 3 上限与超时路径；数据源 8、网关 16、队列 32 由既有单元测试覆盖，
  未做真实并发压测/延迟注入。
- 队列等待期间未记录中间状态；审计只记录最终 `queue_ms`。
- 独立安全评审缺失，本片为自审候选。

评审类型：自审（许可顺序/回滚、超时不借连接、释放路径、审计 queue_ms、单进程边界）。
