## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) A1，父任务 T05；[SQL guard 契约](../../docs/backend/sql-guard.md) §1/§8。

目标：对不可信 SQL 建立可执行、可证明的解析隔离与 AST 预算：64KiB UTF-8 输入、AST 深度 64、物理关系引用 64。超时或线程无法确认终止时必须隔离该 worker 且拒绝继续使用，返回 `SQL_BUDGET_EXCEEDED`；解析失败返回 `SQL_SYNTAX_INVALID` 且不回显 SQL。

不做项：不实现词法/语句形状/函数白名单（T05-a/b 已完成），不实现列绑定/改写，不提供执行入口；`Future.cancel` 不作为线程已停止的证明。

不变量：guard 仍只依赖 common + JSQLParser；错误只含登记码；解析池固定容量、有界队列、命名守护线程、可关闭；连续超时达到隔离上限后 fail-closed。

## 实施与验证

新增 `guard/budget`：
- `AstMetrics`：遍历 JSQLParser 公共 AST 节点树计算结构深度；重复包装节点不重复计层；子查询、CTE、UNION、CASE、函数参数均自然计入。无公共 AST 的手工构造节点 fail-closed。
- `RelationBudget`：按物理引用列表计数（保留重复），64 通过、65 拒绝；只统计，不替调用方处理 unresolved。
- `BoundedParser`：UTF-8 64KiB 边界、固定线程池 + ArrayBlockingQueue、超时轮换并隔离整个 worker generation、隔离代数上限、关闭后拒绝新任务；所有解析异常映射为 `SQL_SYNTAX_INVALID`。

RED：首次执行因 Spotless 布局不通过；`spotless:apply` 后再次执行因 `BoundedParser`/`AstMetrics`/`RelationBudget` 不存在而编译失败。真实失败后实现。

验证命令与结果：

```text
.\mvnw.cmd -B -ntp -pl ptmcp-common,ptmcp-guard -am spotless:apply
.\mvnw.cmd -B -ntp -pl ptmcp-common,ptmcp-guard -am verify
```

结果：common 210 tests、guard 171 tests，0 failures / 0 errors / 0 skipped；`BUILD SUCCESS`。新增用例：
- 深度 64 通过、65 拒绝（精确边界），扁平 SELECT 深度 3，子查询/CTE/函数参数使深度增长。
- 引用 64 通过、65 拒绝；同一物理引用重复 65 次同样拒绝。
- UTF-8 65536 字节通过、65537 拒绝。
- 超时返回 `SQL_BUDGET_EXCEEDED`，随后请求由新 worker 名称服务（证明隔离轮换）。
- 解析线程异常仅映射 `SQL_SYNTAX_INVALID`，异常消息不含注入文本。
- 关闭后拒绝新任务。
