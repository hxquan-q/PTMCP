## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) A5，父任务 T03；[元库设计](../../docs/backend/db-design.md) §2/§3/§4/§7。

目标：在 V1 安全基座上追加 V2 版本化迁移，按设计落 12 张业务表，并为若依登录名/组织/角色补 3 张**新建**最小等价表（目标库不含若依基础表，本片不复用上游 DDL）。空库一次升级 V1→V2 成功、重复 migrate 为 0，约束与孤儿策略在真实 MySQL 8.4 上可证。

不做项：不写业务仓储/服务（组织写事务、快照发布属后续切片）；不建 V3（Token/审计/幂等/租约）；不连接既有 `ptmcp_dev`；不改 POM、不改 `V1__security_foundation.sql`、不改 `SecurityChangeTransaction`/`SecurityEvent`。

不变量：显式主键；UTC `DATETIME(6)` 的 `create_time`/`update_time`；无 `ON UPDATE`；布尔 `TINYINT(1)`+CHECK；状态 `VARCHAR`+CHECK；有符号 `BIGINT`；snake_case；`uk_`/`idx_`/`fk_`/`chk_` 命名；InnoDB + `utf8mb4_0900_bin`；ACL 半开时间窗；授权不因删除/重建复用 `object_id` 而串权。

## 实施与验证

新增 `V2__organization_platform_resource_acl.sql`，15 张表：

```text
platform_registry, datasource, resource_namespace, schema_snapshot,
resource_object, snapshot_object, resource_column, business_dictionary,
platform_scope, acl_grant, admin_delegation,
sys_dept, sys_role, sys_user_role, sys_user_login_name
```

- 12 张业务表逐列对齐 db-design；`sys_dept`/`sys_role`/`sys_user_role`/`sys_user_login_name` 是仅含 PTMCP 所需列的新建等价表（文件头已注明），`sys_user` 不存在，故登录名绑定与用户角色 `user_id` 不建 FK，由身份适配层负责。
- 8 个唯一键（含 `uk_resource_namespace_identity`、`uk_resource_object_identity`、`uk_platform_scope_target`、`uk_resource_column_name`）与 7 个普通索引；57 个 CHECK；10 个显式 FK。
- 多态目标（`acl_grant`/`admin_delegation`/`platform_scope`）按设计不建 FK，由写入事务校验；其余父子关系全部显式 FK，孤儿行由 1452 拒绝。
- `chk_sys_dept_self_parent` 被真实 MySQL 以 Error 3818 拒绝（CHECK 不能引用 AUTO_INCREMENT 列），已移除；部门树自环/环由后续组织写事务保证，V2 只约束状态与父列类型。

测试新增 `MetadataSchemaMigrationTest`（真实 MySQL 8.4 容器，沿用 V1 fixture 配置）：

- 空库断言 0 表 → `migrate()` 恰好执行 2 个版本 → 再迁 0 → 当前版本 `2`；18 张域表 + V1 epoch 种子 + 2 条成功历史。
- 每表 InnoDB/`utf8mb4`、显式 PK、`DATETIME(6) NOT NULL` 时间列且无 `ON UPDATE`、snake_case、有符号 `BIGINT`、6 个布尔列均为 `tinyint(1)`。
- 契约索引/唯一键存在且列序正确；CHECK 共 57（排除 V1 与 flyway 历史）；FK 名称集合恰为设计的 10 个。
- 逐表非法行拒绝：平台 tier/状态/目录/证明组合、数据源 engine/port/pool/TLS、命名空间 generation 与重复、对象 generation/kind/重复、快照到期与计数、快照对象版本与重复、列序号/可空/重名、Scope 动作与重复目标。
- ACL 空窗/非法 effect/主体类型/动作、委托空文档与等窗、部门状态、角色重复/状态、用户角色重复、登录名大写/空/重复均拒绝。
- 6 组孤儿插入返回 1452；15 表整组 DML 后 rollback，逐表计数归零。
- 同 generation 删除重建获得新的 `object_id`（不复用）。

RED：V2 文件尚未创建时执行 persistence `verify`，新测试在 Flyway `target("2")` 处失败：`No migration with a target version 2 could be found`；既有 V1 7 例与安全事务 14 例保持通过。

GREEN：补齐迁移与测试数据后，真实容器 6/6 通过；期间修复两处真实失败——MySQL 3818 拒绝自引用 CHECK（移除并记录由写事务保证）、列插入少传 `comment` 参数（`No value specified for parameter 17`）。

兼容处理：`SecuritySchemaMigrationTest` 仅追加 `.target("1")`，把既有 7 条断言固定在其发布单元上，未修改任何断言；V2 head 由新测试独立覆盖，避免后续 V3 变更污染 V1/V2 证据。

```text

.\mvnw.cmd -B -ntp -pl ptmcp-persistence -am verify
```

结果：common 210 tests、persistence 27 tests（V1 7 + 安全事务 14 + V2 6），0 failures / 0 errors / 0 skipped；`BUILD SUCCESS`。
