## 目标与边界

来源/父任务：T16 父任务；[API 规格](../../docs/backend/api-spec.md) §5（/delegations、
DelegationWrite）、[数据库设计](../../docs/backend/db-design.md) §6（admin_delegation）、
[安全架构](../../docs/architecture/security.md)（委派=部门根子树∩资源范围∩动作∩有效期）、
T16-a 工作项（SelfEscalationGuard/AclDirectory/测试通道）。

实现委派管理员：

1. **`DelegationStore`**（persistence/org 新增）：admin_delegation 的创建/按用户列表/撤销
   （乐观锁+幂等重放）/findValid 执行端查询（ACTIVE+窗口+resource_generation 仍当前）；
   创建同事务写 admin_operation_log（DELEGATION_CREATE/REVOKE）；创建时 userId==operator
   → SELF_PRIVILEGE_ESCALATION；目标用户（sys_user_login_name）/部门根（sys_dept）/资源
   （DATASOURCE/NAMESPACE/OBJECT，generation 校验同 AclGrantStore）存在性校验；
   allowedActions JSON 数组（规范化去重、动作名 `[a-z][a-z0-9:._-]{0,63}`、≤32 项）。
2. **`DelegationAdminController`**（admin/api 新增）：GET /api/v1/admin/delegations?userId=
   （delegation:list，平台管理员）、POST（delegation:create，平台管理员，自委派
   403 SELF_PRIVILEGE_ESCALATION）、DELETE /{id}（If-Match 乐观锁；幂等重放同版本返回
   REVOKED，旧版本 409 VERSION_CONFLICT，缺失 404）。
3. **委派强制**（ManagementScope.requireGrantOperator）：平台管理员直通；其他调用者必须有
   有效委派覆盖「动作 ∩ 资源（type+id+generation 仍当前）」且目标主体部门位于委派部门根
   子树内（沿 parent 链上行，带环界）；ROLE/未知主体跨部门，保持平台管理员专属；任何不满足
   统一 MANAGEMENT_SCOPE_DENIED，不泄露失败维度。接线到 AclGrantAdminController 的
   create/update/revoke（revoke 用既有授权的坐标做门，幂等重放语义保持 T16-a 不变）。

不做：delegation:list 分页游标（当前按用户全量≤200，游标组件待统一替换）；授权矩阵与
预览（T16-c）；审计管理 API（T16-d）；delegation 撤销的 epoch 安全事件（安全快照不含
委派维度，api-spec 的 epoch 事件待 T12-b 撤销广播切片统一）；Idempotency-Key 头部接线
（Store 层协议已在 T16-a 验证）。

## 实施与验证

- persistence：`org/DelegationStore.java` 新增；user 存在性走 `sys_user_login_name`
  （本部署的用户身份表，宿主 sys_user 表不属于元库——修正了首版误查 sys_user 的问题）。
- admin：`DelegationAdminController` 新增；`ManagementScope` +requireGrantOperator/
  subjectDepartment/withinSubtree；`AclGrantAdminController` 构造注入 DelegationStore+OrgStore
  并在 create/update/revoke 接门；`AdminStoresConfiguration` +DelegationStore Bean。
- `DelegationApiTest`（新，MockMvc + 真实 MySQL 8.4 容器，8 例）：
  平台管理员创建/列表/撤销 + 幂等重放（200 REVOKED）；自委派 403 SELF_PRIVILEGE_ESCALATION
  且零落行；非平台管理员创建/撤销 403（越级）；If-Match 缺失 400 PRECONDITION_REQUIRED、
  旧版本 409 VERSION_CONFLICT；委派管理员范围内授予 201 + 主体出子树 403 + 资源出范围 403
  + 动作不在 allowedActions 403 + 过期委派 403 + 撤销后 403（过期/撤销均以
  delegatedAdminGrantsOnlyInsideScopeAndWindow 与 expiredAndRevoked... 覆盖）。
- `AdminApiTest` 5/5 保持绿（ACL 幂等撤销语义回归覆盖）。

  既有环境噪声，重跑通过；AdminApiTest 5 + DelegationApiTest 7 + 其余全部绿）。
- `python scripts/check.py` PASS；`git diff --check` 干净。

## 偏差

- 委派撤销的 "epoch 事件"：admin_delegation 不在安全快照维度内，本切片以
  admin_operation_log 审计替代，epoch 广播待 T12-b 统一（api-spec 行已对照记录）。
- ROLE 主体与 /acl/grants list/preview 仍平台管理员专属：跨部门角色主体与全局列表不在
  单委派表达范围内（安全架构按维度求交的前提）。
- DelegationStore.requireUserExists 查 sys_user_login_name（元库用户身份表）；宿主
  sys_user 表不属于元库。
