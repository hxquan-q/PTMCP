## 目标与边界

来源/父任务或用户请求：[parallel-prompts-20261024](../parallel-prompts-20261024.md) B2，父任务 T09；[审计设计](../../docs/backend/audit.md) §1/§2、[总体方案](../../docs/总体方案.md) §9、[ADR-0007](../../docs/architecture/adr/0007-审计持久准入与非分区存储.md)、[数据库设计](../../docs/backend/db-design.md) §2/§5。

目标：在 `ptmcp-persistence` 落最小 START 与唯一 terminal 的持久模型和仓储；START 原子占用请求身份，terminal 幂等不回退，terminal 可先于 START 到达并携带完整身份，提供基于执行租约过期的 UNKNOWN 恢复方法。

不做项：不实现加密 WAL（C2）；不接 guard/gateway/HTTP/MCP 入口（C1 之后）；不做 outbox 消费者与 P1 冲突告警通道；不实现 SQL 脱敏器（调用方只传已脱敏 SQL）；不做进程 kill/重启回放与数据库主从切换实验；不改 `SecurityChangeTransaction`、V1–V3 迁移和既有测试。

不变量：START 不接收 SQL 明文，只接收 32 字节哈希与原始长度；同一 `request_id` 的 START payload 不同即 `IDEMPOTENCY_KEY_REUSED`；terminal 不覆盖已持久结局；terminal 不能是 `RUNNING`；`audit_log.request_id` 唯一；所有生产 SQL 显式列、参数化；异常不携带 SQL、连接串或驱动文本。

## 实施与验证

```text
ptmcp-parent/ptmcp-persistence/src/main/java/local/ptmcp/persistence/audit/
  AuditStart.java         UUID、可选 user/platform、工具白名单、32B 哈希、长度、UTC 起始时间
  AuditTerminal.java      结果/裁决/错误码/耗时/行数/截断/脱敏 SQL/指纹/密文占位/完整身份
  AuditRepository.java     insertStart/submitTerminal/markUnknownIfStale + TerminalState
  AuditPayloads.java      版本化 canonical JSON、SHA-256、JSON 转义与 UTF-8 安全
  AuditTransaction.java   专用元库写事务；UTC/RC/只读主库校验/超时/异常映射
```

行为：

- `insertStart` 在单事务内先以 `UNIQUE(request_id,event_kind)` 写 `audit_outbox` START（seq 0），再 upsert `audit_log`（result=RUNNING、verdict=UNKNOWN，初始不写 SQL）。重复相同 payload 幂等；不同 payload 抛 `IDEMPOTENCY_KEY_REUSED` 且回滚。
- `submitTerminal` 在单事务内写 TERMINAL outbox（seq 1）并物化 `audit_log`。提交成功后才返回；重复请求返回既有状态；不同 payload 标记 `conflict=true` 但不覆盖。terminal 先到时用自身身份插入；晚到 START 只用 `COALESCE` 补空字段，绝不回退 result/verdict。
- `markUnknownIfStale(staleBefore, limit)` 只选择 `result='RUNNING'`、`started_at` 早于阈值且不存在 `QUEUED/RUNNING/CANCELLING` 且 `lease_until > UTC_TIMESTAMP(6)` 的记录，经同一 terminal 路径写 `UNKNOWN/UNKNOWN/EXECUTION_OUTCOME_UNKNOWN`；仅用于恢复，禁止对在途查询调用。
- 事务前置：拒绝已开启事务的连接；确认主库非 read_only；会话固定 UTC；隔离级别 READ COMMITTED；语句超时 5s。提交结果不明时返回 `OPERATION_UNKNOWN`，提交前失败返回 `DEPENDENCY_UNAVAILABLE`，不重试、不回显基础设施文本。
- outbox payload 不含原始 SQL/结果/凭证；masked SQL 作为已脱敏字段随 terminal 事件写入，转义后仍是合法 UTF-8（孤立代理项替换为 U+FFFD）。

偏差：提示词的 terminal result 域列出 RUNNING，但一次性 TERMINAL 事件若写 RUNNING 会永久占用唯一终结位；本片在 `AuditTerminal` 构造拒绝 RUNNING（结果枚举仍保留该值用于读取 `audit_log`），失败关闭。START 的 verdict 记为 UNKNOWN，表示策略裁决尚未完成；terminal 再写实际裁决，崩溃恢复则保持 UNKNOWN。

## 测试与证据

`AuditRepositoryTest` 9 例，真实 MySQL 8.4 固定 digest 容器：

1. START 新连接可见：outbox payload_hash 等于 payload 的 SHA-256，payload 不含 SQL 文本；`audit_log` 为 RUNNING/UNKNOWN、raw_length 正确、completed_at 为空。
2. 重复 START 幂等；更改 rawLength 后 `IDEMPOTENCY_KEY_REUSED`，两表仍各 1 行且旧值不变。
3. terminal SUCCESS 持久化；随后提交 ERROR 返回既有 SUCCESS 且 `conflict=true`；重放原 SUCCESS `conflict=false`；outbox 始终只有 1 条 TERMINAL、`audit_log` 1 行、terminal_hash 不变。
4. terminal 先到（user/platform 为空）创建记录；晚到 START 只补 user/platform/raw_length，保留 terminal 的 started_at、SUCCESS/ALLOW 与 masked SQL。
5. masked SQL 原样写入，合成敏感串在 `audit_log.sql_masked` 与 outbox payload 中均不存在。
6. 在 outbox START 已插入后注入 `audit_log` 写失败：调用方得到 `DEPENDENCY_UNAVAILABLE`（消息仅为码名、无 cause/suppressed），两表均无半条记录；获取连接失败同样映射。
7. 过期恢复：无租约与已过期 CANCELLING 租约的 START 恢复为 UNKNOWN；RUNNING 且租约未过期的保持 RUNNING；已 SUCCESS 的不变；第二次调用恢复 0 条。
8. 非法输入（工具名、哈希长度、长度/哈希配对、负耗时、错误码格式、密文/keyId 配对、RUNNING terminal、null、limit 边界）全部 `INVALID_ARGUMENT` 且 0 次获取连接。
9. 两个连接并发提交 SUCCESS 与 ERROR：只存在 1 条 TERMINAL outbox，两天返回同一持久结局，恰有一方 `alreadyExisted=false`。

RED：首轮 4 例 terminal 用例失败为 `DEPENDENCY_UNAVAILABLE`。原因是测试把 `startedAt` 写成未来时间，触发真实 `chk_audit_log_completed`（`completed_at >= started_at`）并整体回滚；不是实现缺陷。修正为相对当前时刻的过去时间后通过，未改阈值或断言。
