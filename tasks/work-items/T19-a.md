## 实施与验证

当前基线：gateway 只有启动类/健康检查，无 MCP/auth/执行接线；下游组件已有单独测试。
先增加真实 HTTP + 独立元库/业务库回归并观察失败，再实现生产接线。
验证需证明：PAT/JWT 允许成功；签名/issuer/audience/撤销/平台头冲突拒绝；
用户 Deny、平台封顶、未知对象、写 SQL、多语句拒绝均零业务 checkout；
START 不可写零 checkout；terminal 写失败进入 WAL，二者失败不得成功；
结果行/单元格/JSON 字节边界与 Unicode；返回前再核验状态，旧快照/版本不执行。
通过定向测试后运行根检查与实际全量构建，独立安全评审缺失时明确标为候选。

2026-10-26 生产接线落地（单 Agent 串行）：

- common 新增受限接口 `ApprovedSqlPlan`（finalSql/sqlHash/effectiveLimit/审批窗口），guard
  `ApprovedQuery` 实现它；datasource 不依赖 guard 即可消费已批准计划。
- datasource 新增 `ApprovedQueryAdapter`：包内唯一调用 `ReadOnlyRequest.of` 的适配器，
  借池前复核哈希完整性、审批窗口与 CheckoutGuard 回调（网关注入权威安全状态复核）。
- datasource 新增 `PinnedTlsMysqlPoolFactory`/`PinnedDriverDataSource`（connection 包）：
  每次物理连接时按运维 CIDR 重新解析并固定 IP（防 DNS rebinding），TLS VERIFY_IDENTITY
  + 部署 truststore，URL 参数固定不可注入弱化项；连接工厂解决 Hikari 后台线程与
  ThreadLocal 固定的配合。
- persistence 新增 `PublishedSnapshotReader`（活动 PUBLISHED 快照一次性读取，缺失/过期
  返回不可用，数据源行缺失抛 RESOURCE_NOT_FOUND）、`AuthorizationReader`（主体范围/
  ACL 全行/平台 scope/平台注册信息读取）；`AuditRepository` 新增 `confirmStart`。
- gateway 新增 `McpGatewayConfiguration`（enabled 条件装配，元库池惰性初始化）、
  `PatJwtAuthentication`（PAT 哈希定位+状态/有效期/平台/用户校验；JWT 远程 JWKS+issuer
  验证、family/客户端/版本绑定校验；X-Platform-ID 冲突 403；Tier1 平台无 proof 验证器
  时 fail-closed 403）、`IdentityStore`、`ToolPermissionService`（数据源→命名空间→对象
  资源树，合成 ID 消除三表自增 ID 数值冲突；平台 scope 封顶∩用户展开授权，代际匹配，
  DENY 优先）、`McpAuditWriter`（START 必须主库持久；TERMINAL 主库失败回退加密 fsync
  WAL，两者皆失败 503）、`ToolResultEncoder`（类型映射、BIGINT/DECIMAL 固定字符串、
  4KiB 单格 UTF-8 码点边界截断）、`McpToolService`（JSON-RPC initialize/ping/tools/list/
  tools/call，三工具全实现，START→guard→复核→执行→terminal→响应顺序，1MiB 响应预算
  含双份内容整行舍弃）、`McpToolController`（POST /mcp，2MiB 请求体上限，通知 202，
  AUDIT_UNAVAILABLE 503）。
- 测试：`McpQueryFlowTest` 扩展为验收矩阵（允许查询+审计 SUCCESS/ALLOW、Unicode 回环、
  Deny/写 SQL/未知表/未知库/多语句拒绝且业务连接计数零增量、PAT 未知/撤销/过期、
  X-Platform-ID 冲突、JWT 允许+错误签名/issuer/audience/撤销族/版本失配、单格限幅、
  响应预算整行舍弃、行上限、tools/list、目录 DISCOVER authorized 标记、get_table_schema
  批量拒绝）；新增 `McpAuditResilienceTest`（可写主库全链路成功后，以 REPEATABLE READ
  行锁持有 audit_outbox 模拟 START 不可写→503 AUDIT_UNAVAILABLE+零业务连接+审计行数不变）、
  `McpAuditWriterTest`（TERMINAL 主库失败→WAL fsync 成功；双失败→拒绝）与
  `ToolPermissionDenyTest`（OBJECT 级 DENY 判定回归）。

环境备注（2026-10-26 全天实测，影响验证可重复性）：

- Clash Verge（verge-mihomo TUN）使 Windows loopback TCP 间歇性损坏并随时间恶化：连接重置/SYN 挂死/响应丢失，后期 Windows→WSL 端口转发与 Windows→Windows JVM 互连均受影响（连 /actuator/health 健康检查都超时）；`wsl --terminate` 重启无效。
- 解决容器连接：`TESTCONTAINERS_HOST_OVERRIDE=<WSL虚拟机IP>` 绕开 127.0.0.1 端口转发直连容器（persistence 85 例一次全绿）。JVM→Tomcat 的本机 HTTP 无等价绕过，靠好窗口+重试。
- 2026-10-26 四线整理补强（仅测试夹具）：`TlsMysqlFixture` 的临时证书 SAN 与
  `ptmcp.gateway.allowed-cidrs` 按 `TESTCONTAINERS_HOST_OVERRIDE` 动态加入该数值 IP，
  使 `VERIFY_IDENTITY` 仍校验主机名、目的地策略仍只放行测试容器；生产信任材料与策略不变。
  未加此步时容器可启动，但 JDBC 因 SAN 不匹配或 CIDR 拒绝返回 `INVALID_ARGUMENT`，属环境
  差异而非产品回归。
- 因环境而失败的运行与代码无关的证据：同一套件在不同窗口多次全绿；失败均为 ConnectException/HttpTimeout/上传流卡死，无断言不符。
- 服务端落库证据（audit_log result/verdict）与响应断言并用；测试客户端 30s 超时防挂死。
- 建议跑集成测试时暂停代理/TUN 以获得稳定复现。
