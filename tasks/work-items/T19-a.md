## 目标与边界

来源/父任务：T19 父任务；[MCP 工具契约](../../docs/backend/mcp-tools.json)、
[授权设计](../../docs/backend/authorization.md)、T14-a（Tier1 证明）。

实现 gateway 模块的 MCP Streamable HTTP STATELESS 骨架：
- `POST /mcp`：JSON-RPC 协议处理（initialize / tools/list / tools/call）
- `GET /.well-known/oauth-protected-resource`：RFC 9728 发现端点
- `McpAuthFilter`：每请求独立 Bearer 认证，无 session/cookie/Mcp-Session-Id
- `McpToolRegistry`：从 classpath 加载 mcp-tools.json 注册三个工具

不做：实际 SQL 执行（T19-b）；Bearer 令牌真实验证（T19-b 接 authz 模块）；
真实客户端兼容（NOT_RUN）；CSRF（T17-api-b 会话切片）。

## 实施与验证

### gateway 模块新增

```text
mcp/McpToolDefinition     工具定义 + required/args 校验
mcp/McpToolRegistry       classpath 加载 mcp-tools.json，三工具注册
mcp/McpAuthFilter         STATELESS 每请求认证，401+WWW-Authenticate
mcp/McpProtocolController JSON-RPC 分发（initialize/tools/list/tools/call）
mcp/ProtectedResourceMetadataController  RFC 9728 发现
mcp/McpGatewayConfiguration  装配（ConditionalOnProperty gateway.mcp.enabled）
resources/mcp-tools.json  从 docs/ 复制到 classpath
```

gateway pom 新增 `jackson-databind`（BOM 管理）。

### 测试（纯 JVM，无 Docker 依赖）

- `McpToolRegistryTest` 2 例：加载三工具 + required 参数校验
- `McpProtocolTest` 4 例：tools/list 三工具、initialize 协议版本、
  unknown tool -32602、unknown method -32601

## 偏差

- 认证过滤器使用 stub token validator（仅接受 "valid-test-token"），真实
  Bearer/PAT 验证归 T19-b 接 authz 模块。
- 工具执行返回 not-implemented 占位——实际 SQL 执行链归 T19-b。
- protected-resource metadata 的 issuer 从配置读取，默认指向本地 authz。
