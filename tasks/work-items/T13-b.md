## 目标与边界

来源/父任务：T13 父任务；接续 [T13-a](T13-a.md) 的授权码流程。契约：
[认证设计](../../docs/backend/authentication.md) §5/§6、[ADR-0006](../../docs/architecture/adr/0006-公开客户端刷新令牌轮换.md)、
[数据库设计](../../docs/backend/db-design.md) refresh family/token 段。

目标：已登记 PUBLIC、`none`、S256 且授予 `refresh_token` 的客户端能完成完整刷新链：

- 授权码兑换签发 256-bit 不透明 refresh token，数据库只保存 SHA-256；
- 首次授权创建 family；每次刷新原子消费旧 token、生成新 generation，idle=7天且不超过
  family 绝对 30 天；
- 旧 token 重放使整族 REVOKED，authorization 与所有 token 墓碑保留；
- 刷新后的 JWT `sid` 仍指向同一 family，auth_version 与用户/客户端/平台绑定不变；
- PUBLIC 客户端可通过标准 `/oauth2/revoke` 撤销自己的 refresh token，未知 token 或属于
  其他 client 的 token 统一 200 且不产生跨 client 撤销。

不做项：access token 按 sid 撤销（当前服务不存 access token hash/jti；JWT 撤销仍走
`/me/authorizations` 族撤销）、多副本并发刷新/响应丢失注入、真实客户端矩阵、JWT `cnf` 绑定。
confidential 客户端若登记 refresh grant 也复用同一轮换链，但本片只对 PUBLIC 做了端到端验证。

不变量：refresh 明文不落库/日志；查询与消费均按 hash；旧 token 只能消费一次；重放整族撤销；
刷新不得扩大 scope，issuer/audience/客户端/平台/auth_version 绑定不变；轮换失败事务回滚，
不返回可用响应；失败/未知 token 统一 invalid_grant。

## 实施与验证

- `OAuthProperties`：refresh token 7 天、family 绝对 30 天，刷新寿命不得大于绝对寿命。
- `PtmcpRefreshTokenGenerator`：仅当 registered client 同时登记 authorization_code+refresh_token
  时生成 32 字节随机不透明 token；加入 Delegating token generator。
- `PtmcpRegisteredClientRepository`：只保留 authorization_code/refresh_token 两种 grant；
  TokenSettings 使用 `refreshTokenTimeToLive`，`reuseRefreshTokens=false`。
- `PublicRefreshClientAuthenticationConverter/Provider`：仅识别 token 端点
  `grant_type=refresh_token` + 单 client_id、无 client_secret 的 PUBLIC 请求，不要求 code_verifier；
  默认 PKCE provider 继续负责授权码兑换。
- `PublicRevocationClientAuthenticationConverter/Provider`：仅识别 `/oauth2/revoke` 的
  public/无 secret 请求；`PtmcpTokenRevocationAuthenticationProvider` 校验 token 所属 client，
  未知/跨 client 统一成功 no-op，已知 refresh 走 save 撤销整族。`/oauth2/revoke` 从关闭列表
  移入 AS 端点，discovery 恢复并声明 `none`。
- `PtmcpOAuth2AuthorizationService`：
  - 授权码兑换在 authorization 行写入 family_id，并在 authorization 行存在后插入 family；
  - `save` 首次插入 generation=1，刷新时 `UPDATE ... WHERE status='ACTIVE'` 原子消费旧 token，
    插入新 generation，更新 family idle/last_rotated；
  - `findByToken(REFRESH_TOKEN)` 按 hash 查询 token/family/authorization，校验 status/到期/
    auth_version；CONSUMED 或族不活跃时撤销整族并返回 null；
  - 重建授权时把本次提交的 refresh hash 作为内部属性传给 save；save 只消费该 hash 对应的
    ACTIVE 行，因此并发复用同一旧 token 时只有一个事务能消费，后到者撤销整族；
  - `remove` 对已有 family 的授权改为族撤销，避免 family 外键阻止删除；
  - `revokeFamily` 同事务更新 family、token、authorization 为 REVOKED。

验证命令：

```text
mvnw.cmd -B -ntp -pl ptmcp-authz -am verify
```

## 结果与证据

2026-10-26 实际运行（真实 MySQL 8.4 Testcontainers）：

| 检查 | 结果 |
| --- | --- |
| `ptmcp-authz -am verify` | PASS：common 224 / persistence 85 / authz 32，0 失败/错误/跳过 |
| `OAuthAuthorizationCodeFlowTest` | 13/13 PASS；刷新用例：授权码兑换得到 refresh_token，family ACTIVE、generation=1 ACTIVE；刷新后旧 token CONSUMED、新 generation=2 ACTIVE、JWT sid 不变；旧 token 重放返回 400 invalid_grant，family 与全部 token 均 REVOKED。撤销用例：其他 client 撤销同 token 返回 200 且族仍 ACTIVE；本 client 撤销后族/全部 token REVOKED，随后刷新 invalid_grant |
| 既有授权码/PKCE/同意/关闭端点 | 11 例回归 PASS；未登记 refresh 的 PUBLIC 客户端仍不返回 refresh_token；discovery 声明 authorization_code+refresh_token 与 revocation none |

未验证/边界：

- 标准 `/oauth2/revoke` 已开启并覆盖 refresh token；access token 按 sid 撤销仍未实现
  （服务不保存 access token hash/jti），该路径当前 200 no-op，不能用它替代族撤销。
- 未做并发同一旧 token 双请求、响应丢失/重试、双副本事务竞争；单线程测试只验证顺序重放。
- 未做真实客户端矩阵、独立安全评审与刷新 token 明文泄漏之外的日志审计。
- family/token 墓碑保留策略、180 天清理和备份恢复未演练。

评审类型：自审（hash/事务/代际/重放、客户端认证边界、失败码、墓碑保留）；无独立安全评审。
