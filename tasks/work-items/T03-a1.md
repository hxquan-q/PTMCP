实现仅四个源码/记录文件和父 POM 一行 modules：新增 persistence POM、`src/main/resources/db/ptmcp-migration/V1__security_foundation.sql`、`src/test/java/local/ptmcp/persistence/SecuritySchemaMigrationTest.java`、本文。迁移资源不在 Boot 默认 `db/migration`，没有 Java 自动配置/启动钩子，三应用无 persistence 依赖变更。调用方未来须显式选择专属 location 并保持 cleanDisabled=true/baselineOnMigrate=false；本切片测试已显式固定并实测拒绝 clean/未知非空库自动 baseline。

实际验证（Windows PowerShell，每次先 dot-source 本 worktree `scripts/Enter-Dev.ps1`；Maven 在 ptmcp-parent 调 Wrapper）：

- `docker version --format '{{.Server.Version}}'` 返回 29.1.3；真实 Testcontainers 通过双向 TLS 建立一次性容器，未连接已存在的 ptmcp_dev。固定镜像 `mysql@sha256:76f0358884cb92d9a086d24e5671c38048d3fef40f2588703d73eb55392d6b69`。
- RED：无 V1 时 `./mvnw.cmd -pl ptmcp-persistence -am test` 退出 1；在实库 `migrateEmptyDatabaseExactlyOnce` 报 expected 1 / actual 0，证明空资源不满足验收；不是 Docker 不可用或编译失败。
- GREEN/最终：`./mvnw.cmd -pl ptmcp-persistence -am spotless:apply` 退出 0；`./mvnw.cmd -pl ptmcp-persistence -am verify` 退出 0。persistence 7 项测试，失败/错误/跳过均 0；common 80 项全通过。最终实库测试耗时 21.48s，reactor 37.261s。
