## 目标与边界

来源/父任务或用户请求：用户要求将现有最初框架页推进成可用、可联调、可验收的 PTMCP 业务前端。

目标：在保留 Vue 3 + TypeScript + Element Plus 工程边界的前提下，落地会话/权限基础层、管理数据源/元数据/组织页面和个人门户，使用真实 REST 接口，提供明确的加载、空、错误、权限和缺少接口状态。

不做项：聊天、在线 SQL 控制台、虚假指标大屏、审批中心、把尚未存在的后端端点 mock 成成功。凭证、密码、PAT 和解密 SQL 不进入浏览器持久存储。

## 实施与验证

依赖、读写路径、独占契约：基础层、数据源/元数据、组织/个人页面分别在独立 worktree 并行实施；root 负责集成路由、登录、工作台首页、缺口页面、最终检查和浏览器验收。后端源码只读，页面通过 Vite `/backend/*` 代理访问服务。

关联：FR-01～08、FR-10～13、FR-16～19；TC-UI-001～006、TC-ACL-003/004/009/011、TC-API-003～006/009。以下证据只覆盖本轮明确列出的前端行为，不表示这些端到端用例全部通过。

不变量：会话与权限只在内存；身份变化使旧请求和 CSRF 引导失效；密码/PAT 不持久化；写请求不自动重放；ID/版本保持字符串；资源 generation 不得猜测；409/412 保留草稿并显式采用新版本；权限预览不作为执行授权；缺少端点的操作禁用。后端鉴权和业务数据执行路径不由前端修改。

回滚/收窄：按本轮前端切片回退对应页面或导航，不改数据库 Schema、不降低服务端鉴权；未提供命名空间实时 generation、管理范围或敏感审计接口时保持禁止提交。

当前切片：用户明确要求先完成所有页面前端；已单 Agent 串行补齐委派、平台/客户端、Scope、审计及组织缺失表单与交互。开发专用 frontend-preview 模式以标注合成数据的内存适配器验证完整前端，不连接业务后端、不冒充真实API验收；正常模式仍禁用缺端点操作。前端候选已进入验收，18组范围由30个预览入口覆盖（AS为独立前端预览）。复用现有设计、契约及工作项，保留开工前修改。真实后端、安全验收、AS集成、生产部署及人工接受分别待后续完成。
