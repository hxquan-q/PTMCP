状态：用户于2026-10-23授权完整后端实施、前端接口交付及逐片提交推送；业务验收仍待实现和证据。Agent 执行方式见[任务入口](README.md)与[开发流程](../docs/standards/agent-workflow.md)。

## 目标与约束

按[项目总体方案](../docs/总体方案.md)与[实施路线](../docs/architecture/roadmap.md)建立可验证的薄网关。M0先验证高风险假设，之后再锁定9～10周目标排期。任务状态集中记录在[todo](todo.md)，本文件不复制另一份可勾选任务列表。

## 依赖与纵切

合同/ID/错误语义 → 元库迁移与安全版本 → PAT+单平台 → 词法/绑定/ACL/final_sql → 审计START → MySQL执行 → PG执行与宽行/取消 → 完整OAuth → 管理/门户 → 故障/上线。

OAuth原型与guard可以在契约固定后并行；前端可用契约mock并行，但系统验收必须真实联调。数据库迁移、共享错误码和权限语义由统一契约控制，不允许不同工作流各自重定义。

## 任务切片约定

每个待办有明确验收、验证、依赖和预计文件范围；超过约5个独立文件或一次工作周期时，先检查能否按独立验收/回滚边界拆分；文件数是切片提示，不为凑数拆出无法验证的半成品。涉及安全行为必须包含反例，不能只验证正常SQL。

根目录 Maven/UI 工程已存在，实际命令见[代码规范](../docs/standards/code-style.md)与[环境指南](../docs/ops/development-environment.md)。2026-10-23实施前已在规定Windows环境执行 python scripts/check.py --all，退出0，覆盖26项检查器回归及Maven/pnpm框架构建；尚无业务测试，不能将其记为业务PASS。构建结果、客户端版本、SQL结果等价和恢复演练都纳入[证据登记](../docs/evidence/m0-gate-register.md)。

## 验收检查点

M0检查点：依赖隔离、R1六例各自正确、四反例拒绝无业务连接、对象与列绑定等价、可靠审计、public NONE刷新全链与宽行初测。

M1检查点：双方言真实数据库、缓存消息丢失与到期、≤5秒撤权、取消无误杀、私有夹具资产就绪。

发布检查点：前后端闭环、四客户端支持矩阵、性能与内存环境证据、备份恢复与回滚、密钥/许可证/私有资产边界。未通过的能力保持关闭或明确降级，不修改验收口径凑通过。

## 风险与决策更新

公开客户端安全扩展、数据库端输出限幅、作用域绑定、DDL变更竞态和跨副本配额为重点风险。方案变化先更新相应ADR、PRD/API/TC，再实施。生产容量、外部地址与真实客户端版本属于部署/联调交付，不在设计文档中假填。
