## 总体判断

当前 UI 的企业后台方向正确，但还没到只需最后润色的阶段。主要短板是操作完整性、信息优先级和跨页一致性。SAP 白／灰／蓝的克制风格适合 PTMCP，不建议推翻重做。产品辨识度来自功能权限与数据授权分离、权限交集、未知执行结局等真实业务语义，而不是增加装饰。

本轮评审覆盖角色、数据源、权限矩阵、审计、个人接入、个人字典六个主要页面的 1440、1280、390px 渲染，补看用户页与匿名登录页，并实际操作授权树、规则弹窗和审计返回路径。后台交互使用合成预览，不代表真实业务验收。

## 优先问题

### 1. [P1] 授权资源树能聚焦，却不能用键盘完成选择

选择授权主体和数据源后，树节点可以获得焦点，方向键也能移动焦点；但按 Enter／Space 不会设置当前资源，新增规则一直禁用。鼠标点击同一节点则立即生效。

影响：这是授权主流程的必选步骤，不是缺少一个快捷键。仅键盘用户会在这里卡住。

建议：让键盘激活与鼠标点击共用同一选择逻辑，消除内层文本的无效重复焦点；同时验证数据源、命名空间、对象三类节点。

位置：`ptmcp-ui/src/views/admin/access/PermissionsView.vue:126`、`ptmcp-ui/src/views/admin/access/PermissionsView.vue:139`。

建议命令：`$impeccable harden`。

### 2. [P2] 审计页把筛选条件放在前面，却把审计结论藏到右边

默认展开九个查询字段，并列清空、校验筛选、查询审计。桌面首屏大部分空间用于表单；列表首先展示时间、员工 ID、平台 ID 等字段，结果、判定、错误码和速览入口需要横向滚动才能看到。

尚未选中记录时，右侧速览仍占约 340px。1440px 下表格可视宽度约 796px，内容宽度约 1880px。

影响：管理员想先找失败或拒绝记录，却必须先越过完整检索表单，再横滚寻找结论。字段完整，但排障顺序反了。

建议：默认保留常用筛选，其余放入高级筛选；查询时直接校验，取消重复的校验筛选动作。把结果、判定和排查入口放进默认可见区；名称优先，ID 作为次级信息。速览按需展开，避免空面板长期挤压列表；保留时间范围与安全限制。

位置：`ptmcp-ui/src/views/admin/audit/AuditView.vue:174`、`ptmcp-ui/src/views/admin/audit/AuditView.vue:200`、`ptmcp-ui/src/views/admin/audit/AuditView.vue:229`。

建议命令：`$impeccable layout`、`$impeccable distill`。

### 3. [P2] 查看完整审计详情后返回，会丢失排查上下文

实际操作工具填入 `query`、查询、速览、完整详情、返回审计后，工具条件清空，时间范围重新初始化，原选中记录也消失。列表内切换上一条／下一条、关闭速览则能保留筛选，断点集中在跨页返回。

影响：查看更多证据反而中断连续排查，用户需要记住并重建条件。

建议：返回时恢复筛选、时间范围、分页／游标和选中记录，必要时恢复滚动位置。只恢复查询上下文，不恢复解密明文，保留离开即清除敏感内容的边界。

位置：`ptmcp-ui/src/views/admin/audit/AuditView.vue:32`、`ptmcp-ui/src/views/admin/audit/AuditDetailView.vue:86`。

建议命令：`$impeccable harden`。

### 4. [P2] 未开始、加载中、空结果和读取失败，状态表达相互混淆

字典尚未选择数据源、权限矩阵尚未选择主体时，都使用蓝色勾和暂无记录。数据源慢加载时仍能看到暂无记录；本轮空数据切换为读取失败后，上方出现错误，下方却继续展示暂无符合条件的数据源和新建数据源。

影响：用户难以判断是尚未开始、确实没有数据，还是根本没读成功。权限产品不能让读取失败看起来像资源不存在。

建议：分清未开始、加载、真实空结果、失败四种状态。未开始直接提示缺少的选择；失败突出恢复入口，不再同时给出确定的空结果结论；不要用成功勾表达尚未完成的前置步骤。

位置：`ptmcp-ui/src/components/common/PageState.vue:44`、`ptmcp-ui/src/views/admin/data/DatasourcesView.vue:268`。

建议命令：`$impeccable clarify`、`$impeccable harden`。

### 5. [P2] 角色页与用户页仍像两套表格系统

角色页是白底、较重表头与分隔线、编辑加更多；用户页仍是外层卡片、灰色表头、斑马纹，以及一行多个操作。角色页在较窄桌面下需横滚才能到操作列，用户页则固定在右侧。

角色功能码也存在信息取舍问题：不同权限被截成相同的 `ptmcp:datasource:…`，真正有区分度的动作后缀不见了。虽然更多功能码能查看完整内容，但列表的快速识别价值被削弱。

影响：同一组织管理区域里，用户需要重新学习阅读节奏和操作位置；最新角色页的精修尚未形成全站一致性。

建议：统一表头字阶、行密度、筛选带和行操作规则，复用现有样式而不是继续逐页叠加特例；权限码优先露出差异部分，并保留完整内容的键盘可达入口。

位置：`ptmcp-ui/src/views/admin/org/RolesView.vue:195`、`ptmcp-ui/src/views/admin/org/RolesView.vue:217`、`ptmcp-ui/src/views/admin/org/UsersView.vue:331`。

建议命令：`$impeccable polish`。

本轮没有发现 P0；共 1 项 P1、4 项 P2。后四项均有绕行方式，不应夸大为整个系统不可用。

## 值得保留

- 全局框架可信、克制。视角切换、分组导航、当前位置与主操作容易识别；不需要再靠更多卡片或装饰强化企业感。
- 安全语义有产品表达。功能权限与数据授权分离、未知执行结局、原文独立查看等边界，不只是藏在文档里。
- 部分退出行为做得扎实。新增规则按 Escape 或取消，都能关闭弹窗并把焦点返回新增规则；速览内部切换不清空筛选。窄屏没有发现整页横向撑破。

## 认知负荷与情绪旅程

高负荷主要集中在审计，而不是所有页面。明显短板是默认分块过大、结果优先级偏低、跨页依赖记忆、渐进披露不足。九个筛选字段是需要收敛的决策点；接入页五种客户端是合理业务选项，不应为了机械满足选项少而删减。

用户进入时，稳定的企业框架建立信任；开始任务时，成功勾加暂无记录造成犹豫；高风险授权弹窗通过明确主体、资源和原因提供安心感；连续排障在关键列离屏、详情返回丢条件处跌入低谷。最大的提升不是让界面更热闹，而是让用户始终知道现在是什么状态、下一步做什么、返回后还能不能接着做。

## 用户补充方向后的布局排版复核

用户明确要求重点看布局排版，指出当前界面不美观且操作性差。下面将评审重心从功能检查收敛到布局、视觉节奏与操作组织。以下是建议，不是已经实施或被用户接受的设计。

### 1. 页面节奏不统一，视觉上忽松忽紧

角色页很快进入表格；用户页多套了一层带内边距的卡片；审计页先铺满一大块筛选表单。切换页面时，标题、筛选和数据的起始位置不断变化。角色页的深色横线、偏黑表头，与用户页的蓝灰表头、斑马纹不属于同一套排版。

应统一页面骨架：标题和一句说明组成紧凑页头，主操作固定位置；筛选工具栏紧贴数据区，不额外套装饰卡片；表头字阶、行高、分隔线、操作列位置全站一致。底部因记录少而留白是正常的，不靠增加卡片填满；应压缩的是数据前面的无效占位。

### 2. 权限矩阵的三栏比例失衡

当前主体栏约 180px，名字被迫折行；资源栏约 220px，只放选择框时显得空；右侧用大面积空状态把有效权限预览推到下面。左边挤、中央空、右边长，没有顺着授权步骤组织。

建议：主体选择提升为上下文条；下方资源树约 260px，右侧工作区占剩余宽度。规则与有效权限在同一工作区切换，不继续向下堆卡片。摘要条持续显示主体与资源，让用户看清给谁、对什么资源、授什么权限。

```text
权限矩阵                                      [新增规则]

授权主体：[用户 / 角色 / 部门] [搜索并选择主体]
当前上下文：合成分析员 / 合成订单库

资源树：约 260px     | 工作区：占剩余宽度
数据源选择          | 授权规则 / 有效权限
命名空间、对象      | 当前资源、状态、操作和规则列表
```

### 3. 审计页改为结果工作台

最醒目的不应是筛选区域。常用条件组成紧凑工具栏，高级条件折叠并保留已选摘要；结果与判定进入默认可见列。点击记录后再展开侧边速览，未选择时列表使用完整宽度。

```text
全局审计
[时间范围] [平台] [结果] [高级筛选]              [查询]
时间    调用者 / 平台    工具    结果 / 判定    操作
```

### 4. 表格列宽按信息价值分配

角色表中 Key 被截断，功能码被截成相同前缀；成员数、管理部门等短值仍各占整列。用户表多个动作横向铺开，抢走内容宽度。应让名称与必要标识组成主信息，数量字段紧凑显示，功能码展示有区分度的部分；常用编辑保留，低频操作进入更多，操作列固定行末，不把字段等权排开。

### 5. 字阶和强调方式统一

目前有的地方靠黑色粗体，有的靠蓝色、边框或浅灰底，主次显得零散。建议沿用现有 SAP 字体和配色，统一尺度：页面标题 24–28px、区域标题 16px、正文及表格 14px、辅助信息 12px。减少深色横线、重复边框和大面积说明块，让数据和操作成为视觉中心。

建议整改顺序：先用角色／用户页定好一套列表排版，再重排权限矩阵和审计工作台。先建立统一规则，再解决复杂页面的操作结构，而不是只把单页修漂亮。
