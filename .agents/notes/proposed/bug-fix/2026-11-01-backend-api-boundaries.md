# Agent Note: ACL 变更与客户端凭证的真实边界

Status: proposed

## Problem

当前管理入口的逐请求鉴权不能证明分派后的 ACL 更新原子，也不能只凭当前时间证明未来授权不自增权。
客户端创建的完整响应被通用幂等缓存明文保留；管理写入器与 AS 手工 CSV 夹具又掩盖了真实落盘格式不一致。
这些问题由本会话九个失败反例复现，范围与证据归属
[修复工作项](../../../../tasks/work-items/DEV-20261101-backend-api-fixes.md)。

历史检索：[网关能力笔记](../architecture/2026-10-28-gateway-capability-hardening.md)部分重叠，
其入口动作码、UNKNOWN 与事务事实仍适用，不替代或改写；T13-a 的 CSV 是既有兼容格式，
本次数组读写需要保留它的兼容读取。ADR0003/0007/0011 的身份、安全事务与审计边界不变。

## Proposal

ACL create/update/revoke 在持有全局安全锁的同连接上核对实际写集及本人权限；
替换保持 ID/创建人并递增版本，写入、操作记录和 epoch/event 同事务，失败完整回滚，提交不明不重放。
本人增权比较覆盖当前时刻及前后规则的未来生效/到期边界，关系展开只做一次，不逐时间点重复展开整树。
列表必须由同一委派同时覆盖主体部门与授权资源，不交叉拼接两个委派。

客户端创建区分首次可见响应与持久回放投影，投影不包含 secret。
旧客户端回放也必须先投影清除，不把旧缓存按原字节下发；迁移清理既有响应，未知结局仍占键。
scopes/redirect_uris 新写使用 JSON 数组，兼容读支持 CSV 及既有管理端表示，URI 保持逐字匹配。
private_key_jwt 未完成密钥验证/SSRF 接线前明确拒绝登记，不为“修复”引入宽松外抓或伪造 secret。
客户端分页使用唯一键，不把配置 version 当排序身份。

## Alternatives considered

- 只在 DELETE 前调用当前时间的检查改动最少，但仍遗漏未来边界及校验/提交竞争，因此不采用。
- 继续通用幂等响应加密能保留便捷回放，但仍违背只展示一次，也扩大密钥和历史恢复面，因此只保留安全元数据。
- 将所有客户端列表改回 CSV 最接近早期 AS，但合法 URI 中的逗号与分隔符存在歧义；数组能明确边界，旧格式只用于兼容读取。
- 本次完整实现 private_key_jwt 可保留所有可选方法，但缺少已批准的 JWKS 出站和客户端矩阵，故选择收窄登记而不是冒充支持。

## Acceptance criteria

九项评审反例收敛；ACL 失败/并发/未来边界与 secret 首次/回放/旧缓存清理有真实 MySQL 证据；
旧 CSV、旧管理格式与新数组都能读取，URI 字面量不被拆成新增回调；
客户端分页覆盖同版本行、过滤变化和边界页；网关启动与证明 round-trip 同时通过。
实际源码组合通过适用门禁与只读独立安全复审，不引用修复前绿灯。

## Risks

数组写入后旧 AS 不能直接回滚；先上线兼容读端，历史数据转换与生产凭证轮换需另具操作授权。
历史备份中的明文不能由一次应用升级追回。
本次不承诺所有管理路径的会话撤销/最后管理员/间接成员增权已闭环，不以这九项修复外推整体生产验收。
