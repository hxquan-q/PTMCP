# Agent Note: 工作台表格滚动、审计往返记忆与空闲态收敛

Status: implemented

## Problem

角色、用户、审计三张工作台表格在 1280/390 宽度下必须横向拖动才能到达操作列；外层再套一层 `overflow-x` 容器后，Element Plus 的 `fixed="right"` 列相对于表格自身右边缘定位，操作列反而被推到视口外。审计页首屏把全部筛选平铺，速览栏未选中记录时仍占右栏，窄屏下表格只剩几百像素可见宽度；且筛选、游标与选中记录在进入详情后丢失，用户排障需要重新填一遍。权限树与字典页在“尚未选择前置项”时显示成空结果，错误态与空态还会同时出现，让“没有数据”和“没查”读起来一样。

同时，键盘激活路径分裂：树节点内层 `span` 自带 `tabindex=0`，外层节点另有一层焦点，Enter/Space 只在部分节点生效。

## Decision

数据表由 Element Plus 自己持有横向滚动条，页面不再外包滚动容器；需要常驻可达的操作列声明 `fixed="right"`，并用 `scrollbar-tabindex="0"` 让键盘用户能聚焦滚动区域。角色、用户、审计三表遵守同一规则，数据源与元数据表沿用既有 `fixed="right"`。

审计筛选分两级：默认只渲染时间、工具、结果、判定五类常用条件，员工 ID、平台、数据源、错误码进入“高级筛选”，按钮显示已设条件数。速览栏只在选中记录时存在，未选中时列表占满宽度。

审计筛选/时间/已加载行/游标/选中记录/滚动位置只允许在“列表 → 完整详情 → 返回列表”往返中恢复。离开到其他路由时立即丢弃快照，不跨无关导航泄漏上一次查询；快照只含脱敏摘要与 ID，不保存 SQL 明文。

权限树只保留一层焦点，Enter/Space 统一经 `selectResource` 激活；节点类型约束（命名空间不满足 generation 时不启用“新增规则”）仍由既有选择逻辑决定，键盘不绕过它。

状态渲染遵循 idle / loading / empty / error 互斥：未完成前置选择时显示 idle（“尚未开始”），加载中只出骨架，错误只出错误态与重试，真实空结果才出 empty。实现方式是在各视图给 `PageState` 显式 `kind`，并用 `!loadError` 之类的条件阻止错误态同时渲染空表结论。

## Alternatives considered

保留外层滚动容器并用 CSS 覆盖粘性列位置：这样能少改模板，但会让列固定锚点继续相对整张表而非可视区，窄屏下操作列依旧不可达，属于用样式掩盖结构错误。

不做外层容器、改为逐列压缩到 390px 内：能在窄屏免滚动，但会牺牲功能码、请求 ID 等排障必要字段的可读性；这些字段是工作台的主要信息，不该为首屏整齐而截断。

审计筛选一次性全量平铺（维持原状）：实现成本最低，但首屏把 9 个条件同等对待，常用路径被稀释，窄屏还要多滚一屏才能看到列表。

审计筛选永久记忆（浏览器级持久化）：排障往返更省事，但会让“新开会话却看到旧筛选”变成隐式状态，且需额外考虑存储与清理边界；当前只需覆盖详情往返，内存快照即可。

把 idle 复述为 empty：只需一处改动，但会让用户把“还没选”误读成“查过且没有”，直接影响权限矩阵与字典页的判断。

## Consequences

三张工作台表格在 1440/1280/390 下操作列常驻可见，横向滚动只影响中间列；键盘用户可聚焦表格滚动区域并用方向键浏览。代价是页面不再能通过外层容器统一控制表格溢出，新增表格须自己声明 `fixed="right"` 与 `scrollbar-tabindex`，否则会退回旧问题。

审计首屏高度下降，窄屏速览改为列表下方整宽区块；代价是宽屏下速览位置随选中状态变化，列表宽度会跳变，需要靠固定栅格避免抖动。

审计往返恢复只对详情路由生效，用户从侧栏重新进入审计时看到的是干净默认筛选；这让“续接”和“重开”语义明确，代价是不能跨页面保留查询。

状态互斥减少了“空表 + 错误”的重复信息，代价是每个视图都要显式指定 `kind`，新增页面若沿用默认值仍会落到 error 语义。
