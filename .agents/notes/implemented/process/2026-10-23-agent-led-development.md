# Agent Note: 用任务合同和决策记忆支撑 Agent 主导研发

Status: implemented

## Problem

PTMCP 已有设计、安全约束和待办，但缺少开发 Agent 的发现入口、跨会话执行合同和决策记忆治理。会话里的计划与完成总结无法替代仓库事实；直接移植成熟项目的流程又会引入多份状态与过量台账。

## Decision

仓库保留 docs、9 份 ADR 和 T01～T20。根 AGENTS 按任务路由到开发流程、决策笔记和领域契约。非平凡实施使用独立工作项，小改复用记录。本地与 CI 共用标准库检查入口，现有产品设计保持待实现。该笔记的 implemented 仅指开发规范和本地工具已经落地。

笔记结构检查按生命周期校验必需章节顺序并拒绝重复二级标题，允许穿插自由章节和代码块示例；这只能防止结构歧义，不能证明决定理由真实或评审充分。

## Alternatives considered

- **完整移植 open-forge 管理栈**：具备详细的调度、协作和发布合同；当前仓库还没有应用工程，完整移植会重复已有 tasks/docs，并依赖本项目不存在的控制器和运行环境。
- **直接安装外部笔记 Skill**：拥有成熟模板与看板；本轮只需方法参考，外部安装和命令会扩大依赖与规则面，也不能解决现有 ADR、设计状态和任务交接的衔接。
- **只扩充根规则**：改动集中、容易发现；执行细节全部常驻会增加上下文负担，且缺少可执行的反馈。
- **仅检查必需章节存在**：兼容更宽松的写法，但允许重复标题或章节乱序混淆决定、备选与后果；采用允许自由章节的有序骨架，而不限制正文的具体写法。

## Consequences

收益：新会话有明确入口和恢复合同，决策因果与短期进度分开；本地检查覆盖状态矛盾、笔记骨架、归档冻结和 ADR 演进。

代价：工作项与非显然决定需要维护；结构门禁不能证明 Agent 遵循流程、业务安全或证据充分。规则按需披露；后续工程/并发规模变化时需要补真实构建、集成与运行评审。
