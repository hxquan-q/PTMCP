# Agent Note: 用任务合同和决策记忆支撑 Agent 主导研发

Status: implemented

## Problem

PTMCP 已有设计、安全约束和待办，但缺少开发 Agent 的发现入口、跨会话执行合同和决策记忆治理。会话里的计划与完成总结无法替代仓库事实；直接移植成熟项目的流程又会引入多份状态与过量台账。

## Decision

仓库保留 docs、已有 ADR 和 T01～T20。根 AGENTS 按任务路由到开发流程、决策笔记和领域契约。非平凡实施使用独立工作项，小改复用记录。本地与 CI 共用标准库检查入口；产品设计、实现与验证仍分别取证。该笔记的 implemented 仅指开发规范和本地工具已经落地。

[研发闭环](../../../../docs/standards/harness-development.md)按上游实际实践补充变更范围、风险验证、评审和迁移交接；只读范围报告区分提交、暂存、未暂存和未跟踪文件，不推断归属或基线。[资产治理](../../../../docs/standards/agent-assets.md)界定根入口、视觉设计、笔记、技能与宿主配置的职责；忽略的本机技能不成为团队必备依赖，结构门禁仅检查被 Git 跟踪的技能元数据。

根入口只承载全仓边界、最小改动纪律和路由；[后端](../../../../ptmcp-parent/AGENTS.md)与[前端](../../../../ptmcp-ui-react/AGENTS.md)的差异就近放置，模块规则沿各父入口下钻，仅保留所属子树差异。CLAUDE 用 `@AGENTS.md` 共用根规范，目录规则按目标路径读取，不批量导入。防御依据真实输入、失败模式或合同，避免对已保证的内部条件重复校验；安全、数据完整性和资源清理处理继续保留。经验规则由重复偏差驱动，既有安全合同不等待再次失败才执行。

笔记结构检查按生命周期校验非空标题、Problem 首节和必需章节顺序并拒绝重复二级标题，允许后续穿插自由章节及代码块示例；新增笔记前检索并分类相关活跃记录，提交前语义自审问题、真实备选、后果与验证。结构检查只能防止形式歧义，不能证明决定理由真实或评审充分。对外接口变更在工作项中使用[接口合同模板](../../../../docs/standards/api-change-template.md)并同步权威契约；文档门禁只检查模板存在和链接，不能证明开发者实际遵循或协议实现正确。

## Alternatives considered

- **完整移植 open-forge 管理栈**：具备详细的调度、协作和发布合同；当前仓库还没有应用工程，完整移植会重复已有 tasks/docs，并依赖本项目不存在的控制器和运行环境。
- **直接安装外部笔记 Skill**：拥有成熟模板与看板；本轮只需方法参考，外部安装和命令会扩大依赖与规则面，也不能解决现有 ADR、设计状态和任务交接的衔接。
- **只扩充根规则**：改动集中、容易发现；执行细节全部常驻会增加上下文负担，且缺少可执行的反馈。
- **一次性为所有目录创建规则文件**：路径归属清楚，但没有实际差异的文件只会复制父规则。仅为已确认的模块契约或特殊运行边界建立局部入口，其余继承父规则；目录数量不作为交付指标。
- **内部调用一律互信、严格禁止新文件**：字面约束容易执行，但会漏掉实际信任边界或迫使不同职责塞进旧文件；采用以契约和当前职责为依据的最小改动。
- **仅检查必需章节存在**：兼容更宽松的写法，但允许重复标题或章节乱序混淆决定、备选与后果；采用允许自由章节的有序骨架，而不限制正文的具体写法。

## Consequences

收益：新会话有明确入口和恢复合同，决策因果与短期进度分开；本地检查覆盖状态矛盾、笔记骨架、归档冻结和 ADR 演进。

代价：工作项与非显然决定需要维护；结构门禁不能证明 Agent 遵循流程、业务安全或证据充分。规则按需披露；后续工程/并发规模变化时需要补真实构建、集成与运行评审。

目录拆分要求跨目录任务分别读取各自入口；不能把拆分等同于所有宿主自动加载成功。若局部规则出现稳定且不同的验证或安全约束，再下拆到相应模块，不以文件数作为完成指标。
