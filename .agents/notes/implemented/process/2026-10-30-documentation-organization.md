# Agent Note: 保持现行文档入口与历史证据分层

Status: implemented

## Problem

项目已有产品、架构、后端契约、测试、运维与任务记录，但随着实现推进和前端工程变更，部分入口仍描述旧目录、旧框架或“业务尚未实现”。历史测试与当前状态混在同一导航中，读者难以判断哪些是目标合同、哪些是实现事实、哪些只是特定日期的验证；机械链接通过也不能发现这种语义漂移。

## Decision

沿用既有文档和职责，在根入口及文档导航按研发阶段和读者任务组织入口；对现行指南的工程路径与命令按源码核对，对历史报告和旧版页面覆盖明确日期与适用范围。实现与验证状态仍由工程、工作项和证据持有，索引只提供链接和解释，不另建维护当前进度的副本。发现的检查器/构建脚本漂移原样报告，不把修正文档当作修复工具或完成产品验收。

## Alternatives considered

- **把旧报告和覆盖矩阵直接改写成当前结果**：阅读时更集中，但会抹掉旧测试的对象、时间和前端版本，且无法凭现有资料补出新的真实运行证据。
- **新建一份完整的当前状态总表，取代现有工作项和报告入口**：可一次浏览全貌，但会形成第二套动态事实源，开发中的变化很快使它与工作项、源码不一致。

## Consequences

收益：根入口与文档导航能按研发阶段发现产品、设计、源码、开发、测试和运维材料；旧 Vue 和历史测试证据保留原范围，不再冒充当前 React 结论。设计约束、工作项、源码和验证记录继续各司其职。

代价：索引和工程事实仍需随变更同步，盘点不能证明所有领域文档与源码完全一致；工作树有其他在制修改，局部核查不代表整个构件已验证。整理过程中发现检查器、CI 和启动脚本的旧路径，其他会话正在迁移；脚本接线、云端运行和 Linux 一键启动须由相应工作项及实际结果验证，本整理不冒称通过。
