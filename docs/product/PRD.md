# PTMCP 产品需求文档

版本：1.0-design · 日期：2026-10-23 · 状态：待实现、待验收。

本文规定一期业务需求和验收口径。[总体方案](../总体方案.md)是跨文档权威基线；输入为[用户 review](../reviews/review.md)、[原始需求](../REQ.md)及参考源码。本文描述目标行为，不代表参考项目已经具备 PTMCP 能力。接口以[后端契约](../backend/api-spec.md)为准。

## 1. 问题、目标与产品边界

企业需要让员工在外部 Agent 中问数，同时控制用户、平台和业务表的访问范围，并能追溯每次工具调用。PTMCP 提供身份、平台 Scope、目录与结构过滤、只读 SQL 守门、受控执行和审计；外部 Agent 自行生成 SQL 和解释结果。

一期业务目标：

| 目标 | 度量及验收方式 |
| --- | --- |
| 正确隔离数据 | 一期威胁模型与内部回归集下，表权限绕过为 0；静态拒绝场景业务执行器调用次数为 0 |
| 降低接入成本 | 首次使用管理员在 10 分钟内完成建部门、建源、同步、平台 Scope、表授权和验证；计时前提供可用只读账号与网络 |
| 让员工判断能问什么 | 目录按平台模式展示；无 READ 的表不返回字段、键或字段注释；明确显示目录可见与数据可查的区别 |
| 及时撤销 | 已提交撤销对新查询最大 5 秒生效；排队出队及 JDBC 提交前复核；在途尽力取消 |
| 留下可追踪记录 | 每次已认证 Tool 调用具有 requestId 和审计记录；执行准入与结束事件先持久确认；不可持久化时阻断新 SQL |
| 控制网关开销 | 2C4G、50 客户端并发、SQL ≤4KiB、权限热缓存条件下，非数据库内部处理 P95 <50ms；队列等待单列 |

不将“成功解析 SQL”视为安全证明，也不承诺任意 SQL 兼容。生产可用性、客户端兼容性、容量和内存上限必须有实测证据。

## 2. 用户、角色与权限分工

角色是管理职责模板；实际接口操作权限由服务端菜单/操作授权检查。数据 READ/META 另行计算，拥有控制台菜单不等于能读取业务表。

| 角色 | 职责与可见内容 | 默认不具备 |
| --- | --- | --- |
| 平台管理员 | 数据源、Schema、业务字典、组织账号、平台及接入策略的管理；按操作码授予功能 | 自动读取所有业务数据、自动解密原 SQL |
| 组织授权管理员 | 在其可管理的组织及资源边界内维护授权、预览有效权限 | 跨管理范围授权、修改平台信任等级或连接密钥 |
| 安全审计员 | 按获授审计范围查看全局脱敏审计、拒绝分类与事件详情 | 业务表读取；原 SQL 解密需单独权限 |
| 普通员工 | 本人数据字典、接入配置、PAT、OAuth 授权及查询历史 | 选择其他 userId、查看其他人记录、修改自身平台 Scope |

用户可同时具有多个管理角色，查询仍遵守相同平台与数据权限交集。组织管理员不能以为其他用户创建凭证的方式代替实际用户验证权限；预览只返回判定解释，不执行业务 SQL。

## 3. 一期范围与二期边界

一期纳入：内置账密、部门/角色/个人授权、MySQL 8 系列与 PostgreSQL 的已验证版本、库表级权限、DISCOVER/HIDE 目录模式、三个 MCP Tool、OAuth 授权码 + S256、受控刷新、PAT、双视角控制台、可靠审计和运行告警。

候选业务数据库为 MySQL 8.4、PostgreSQL 18，元数据库固定 MySQL 8.4；完整补丁与驱动组合在 M0 锁定。只开放双引擎回归通过的类型。MCP 使用 HTTPS Streamable HTTP `/mcp`，不提供旧 SSE 地址。

二期：Oracle/SQL Server、ERP 组织同步、行级过滤、列级权限与字段脱敏、企业 SSO、Token Exchange。页面不放可用性未知的二期操作按钮；模型预留不代表已实现控制能力。

## 4. 业务对象与状态

| 对象 | 业务定义及状态规则 |
| --- | --- |
| 数据源 | 一个被管理的只读连接入口；启用、停用；连通状态与业务启停状态分开展示 |
| 资源对象 | `(datasourceId,catalog,schema,objectName)` 对应的已同步物理关系；显示名不能替代资源 ID；ID 以字符串传输 |
| Schema 快照 | 同步生成的版本化结构；可用、过期、变更待确认；删除/重建对象不继承旧对象授权 |
| 授权记录 | 主体、资源、META/READ、ALLOW/DENY、继承选项、`[validFrom,validTo)`；尚未生效、有效、已到期为时点计算结果 |
| 平台 | Tier 1 受信后端、Tier 2 受管公开客户端、Tier 3 个人终端；启停、目录模式和 Scope 分别配置 |
| OAuth 授权族 | 活跃、撤销、到期；可轮换刷新；旧 Refresh Token 再用撤销整族及关联 JWT |
| PAT | 活跃、撤销、到期；默认 30 天、最长 90 天；仅创建响应展示完整值 |
| 审计调用 | 独立保存 result、error、verdict；崩溃遗留开始记录为 UNKNOWN，不冒充成功 |

业务日期以用户时区展示，服务端时间以 UTC 与带时区 ISO 8601 传输。授权生效的判断基于服务端时钟，前端倒计时只用于提示。

## 5. 功能需求与用户故事

### FR-01 会话与账号状态

作为员工，我要使用分配的账号登录控制台，并能改密与退出。登录失败 5 次锁 10 分钟，同时按账号/IP 限速。会话最长 8 小时。控制台使用 HttpOnly/Secure/SameSite=Lax Cookie；所有写请求验证 CSRF。用户停用/删除拒绝登录与新调用；改密提升认证版本并撤销会话与凭证，但不将正常用户改为停用。

验收 AC-01：Cookie 无法由页面脚本读取；CSRF 缺失或错误不能写入；改密后旧 Cookie、JWT、PAT 不能继续获得新查询准入。用户名不存在与密码错误给出一致的安全提示。创建、改密与重置的新密码统一为12～64字符且UTF-8≤72字节，BCrypt不能静默截断。

### FR-02 组织、用户和角色

作为管理员，我要维护部门树、员工归属和角色成员。组织管理员只能管理其服务端授权边界内的主体；部门树禁止循环。平台管理员通过 admin_delegation 显式委派管理员、部门根子树、资源范围、动作和有效期；组织授权管理员必须同时具备功能码和有效委派，不能自我扩权，不能修改跨范围共享角色。停用角色、迁移部门、树调整、角色成员变化都更新安全版本并产生事件。重置密码不在日志中保存明文，不从列表再次取回初始密码。

验收 AC-02：角色或部门变更影响继承授权；直接调用越界接口仍拒绝；停用与删除前显示影响范围；被撤销权限不能被前端旧树恢复；委派到期、超资源范围、超动作/期限和自我扩权分别有拒绝用例。

### FR-03 数据源与连接管理

作为平台管理员，我要配置类型、地址、端口、库、只读账号和连接池预算，测试连通性并启停。密码只写不读，编辑时留空表示不更改。后端限制连接目标与驱动参数；控制台不能提交任意 JDBC URL、驱动类或任意 SQL 测试语句。数据源 ID 明确显示，避免同名库混淆。

验收 AC-03：未验证的数据库类型不可启用；密码不出现在响应/日志/剪贴板配置；全副本连接预算超过已核准容量时不能静默保存。停用源后新查询在撤销窗口内拒绝。

### FR-04 Schema 同步与对象版本

作为管理员，我要触发同步并查看任务进度、增删改差异及失败原因。同步为异步任务；相同版本并发更改返回冲突。无同步快照不能授权猜测出的表。删除、重建、视图定义变化更新资源版本；新对象需要明确确认与授权。

验收 AC-04：旧对象授权不转移给同名新对象；过期快照不能执行；页面刷新后可通过任务 ID 恢复进度；失败不把部分快照伪装为完整成功。

### FR-05 业务字典维护

作为管理员，我要在原始结构外补充业务别名与说明。原始表名、类型及数据库注释只读，业务说明单独保存。字典文字作为不可信内容纯文本展示，不被当成系统指令或 HTML。无 READ 的用户只见可披露的表级说明，不返回字段说明。

验收 AC-05：字典保存有版本冲突检查；字段隐藏在 API 层完成；恶意 HTML/脚本和提示词内容不能产生脚本执行或改写权限。

### FR-06 平台注册、Scope 与来源证明

作为平台管理员，我要区分可信后端、公开桌面端和个人终端。新 DCR/CIMD 客户端默认最小 Scope。Tier 1 每次 MCP 调用需 mTLS 或经核实的后端代理 secret + 网络约束；`private_key_jwt` 只认证 token 端点。桌面端不得配置共享 secret。token/PAT 固化的 platformId 不可被 Header 覆盖，冲突拒绝。

验收 AC-06：伪造 clientId、CIMD 域名、隐藏 Header 不能获得 Tier 1；平台停用、Scope 缩小触发失效；平台 Scope 永远不能扩张用户自身权限。

### FR-07 授权矩阵

作为组织授权管理员，我要针对个人、角色、部门及配置启用的上级部门，创建明确的 META/READ ALLOW/DENY，并设置起止时间和资源树继承。默认无授权；READ ALLOW 隐含 META ALLOW；META DENY 同时阻断 READ；READ DENY 不自动阻断 META。先展开继承、应用时间与 DENY，再与平台 Scope 相交。没有“父级勾选意味着子级 DENY 被覆盖”的行为。

授权目标只使用 DATASOURCE、NAMESPACE、OBJECT。NAMESPACE 是已发布的catalog+schema组合；PG的catalog分组不对应独立授权资源，页面不为该分组提供授权勾选框。

组织授权管理员不能通过本人/所在角色或部门的grant、成员变更，或移除命中本人的DENY增加自身META/READ，即使资源在委派内也不允许；此类增权须平台管理员另行操作。平台管理员显式授予自己业务READ必须留审计，不等于管理员自动有READ。

验收 AC-07：预览能解释命中来源、继承、DENY 和平台交集；有效区间为左闭右开；自然到期与未来 DENY 生效都无需新写操作；前端勾选不会直接产生未审阅的大批授权；主体和资源同时受委派检查，不能授予超出委派的动作或期限。

### FR-08 有效权限预览和撤销时效

作为管理员，我要按用户、平台、当前/指定时点预览有效权限，并在提交前看到变更差异。预览不是授权生效证明，真正调用按当前服务端状态判定。提交后显示权威版本与影响提示：新查询最大 5 秒生效；在途尽力取消，已返回数据无法收回。

验收 AC-08：MySQL 主库无法确认安全状态时拒绝新 SQL；Redis 命中和消息补扫不能延长权威核验时间；排队后重新复核；缓存不跨未来 validFrom/validTo 边界继续使用。

### FR-09 OAuth 首次接入

作为员工，我要复制通用配置，在支持的 Agent 中完成发现、登录、同意授权和调用。授权页清晰显示客户端、平台、请求范围与回调目标；仅支持精确 redirectUri 和 S256。拒绝授权后返回标准协议错误，不创建有效授权族。控制台和授权服务会话独立，一期不承诺跨应用免登录。

验收 AC-09：WorkBuddy、Cursor、Claude Code、VS Code 按实际版本记录注册、回调、首次登录、过期行为；未实测版本不得显示“已兼容”。M0 至少验证一个公开客户端和一个受信后端。

### FR-10 刷新轮换与授权撤销

作为员工，我要在兼容的客户端续期，也能撤销已授权客户端。Access JWT 10 分钟；Refresh family 绝对寿命 30 天、空闲寿命 7 天。每次刷新原子消费并轮换；并发只能一次成功，已消费令牌再用撤销整族，响应丢失或冲突后重新授权。公开客户端扩展在 M0 验收前默认关闭；不能续期时明确使用重新授权或 PAT。

验收 AC-10：不能只替换 generator 就宣称支持；token 端点完整链路、持久化、并发和重放全部验证；后台/个人页撤销后关联 JWT 也在状态核验窗口内失效。退出控制台不等于撤销所有外部授权，页面必须分别说明。

### FR-11 PAT 生命周期

作为员工，我要给个人终端创建命名 PAT，选择不超过 90 天有效期，并可撤销。完整值只展示一次；创建关闭后仅保留名称、指纹/前缀、到期时间与状态，不可找回。PAT 绑定个人终端平台，使用 `Authorization: Bearer`，禁止 URL 参数。撤销和到期后不能恢复原凭证，应新建。

验收 AC-11：列表/详情/刷新页面无法取回完整 PAT；只保存高熵值哈希；撤销按钮提示影响客户端；创建请求无自动重试，失败不重复发放未被用户看到的凭证。

### FR-12 目录检索

作为员工或 Agent，我要在指定 datasourceId 下检索库表。DISCOVER 展示平台范围内的表名、表注释及 authorized 标记，显式 META DENY 仍隐藏；HIDE 只显示有效 META/READ 表。没有权限的结构信息不从缓存或错误中泄露。分页用服务端 cursor，不能通过模糊库名跨所有源搜索。

验收 AC-12：相同库名不同源不混合；目录模式切换即时影响新请求；UI 明确“仅目录可见”和“可查询”；无可见资源时提供联系授权管理员提示。

### FR-13 结构详情

作为有 READ 的员工/Agent，我要一次读取 1～20 张表的字段、类型、主外键及说明。PG 必须指定 schemaName；MySQL 不接受非空 schemaName。无 READ 不披露列结构；批量请求存在无权对象时按接口约定拒绝，不能顺带回显其隐藏字段。外键指向无 READ 对象时省略该外键并标记受限，不通过键关系泄露隐藏对象。

验收 AC-13：绕过前端直接访问详情也拒绝；目录可见不代表可读取结构；同名 schema、引号大小写及已删除对象均绑定到准确资源。

### FR-14 只读 SQL 与对象一致性

作为 Agent，我只能提交单 SELECT 和已验证语法。网关递归校验 CTE/子查询/UNION/窗口表达式，自研作用域绑定器确定关系与列，验证权限，完全限定并同步关联列引用，收紧 LIMIT，再重解析核对。未知、歧义、系统对象、递归 CTE、写操作、锁、INTO、带路径/表函数、自定义类型/操作符均拒绝。仅执行不可伪造的 ApprovedQuery 对应 finalSql。

一期视图默认关闭；仅在依赖图完整可解析、定义hash与快照一致，并且视图本身及全部底层物理关系均具备READ、通过专项验收后开放。依赖未知、循环或指向外部表等未验证路径拒绝。数据库视图不作为绕过底层表ACL的授权入口。

验收 AC-14：R1 六例按各自正确预期验证；4 个反例必须保留 salary，2 个常规案例分别保留 orders/users 与 salary。静态拒绝业务连接借用为 0；授权对象与实际执行对象一致；无原文执行旁路。

### FR-15 输出预算、取消与失败

作为员工，我要收到可解释且有界的结果。SQL 64KiB UTF-8、AST 深度 64、物理关系引用 64；最多 500 行，maxRows 只能收紧；单格输出 4KiB、完整序列化响应 1MiB。截断标记通过元数据返回，不用真实单元格 `[TRUNCATED]` 字符串冒充数据。BIGINT/DECIMAL 使用字符串，NULL 保留 null，时间明确格式。

用户并发 3；每副本数据源并发 8、gateway 并发 16；每副本队列最多 32、等待最多 3 秒。SQL 15 秒、借池 3 秒、取消 3 秒、清理 2 秒、连接/网络兜底 20 秒。取消必须确认原任务终止、关闭语句、回滚和清理完成，否则淘汰连接。可变宽类型在数据库端安全限幅或拒绝，字符流 API 不等于驱动内存有界。

验收 AC-15：UI/Agent 区分行、单格、响应预算截断；超时不给出部分成功假象；大字段和迟到取消竞态有双引擎内存/零误杀证据；未通过的投影路径不开放。

### FR-16 管理审计与原 SQL 解密

作为安全审计员，我要按时间、用户、平台、源、工具、verdict/error 筛选脱敏记录，通过 requestId 查看流程、耗时和拒绝规则。原SQL解密要求独立 `ptmcp:audit:decrypt`、受控审计范围和填写理由；任何角色默认都无解密权，也不因是平台管理员自动获得。该操作本身审计、短期展示且不缓存。默认不保存结果集，不在日志中记录 token/密码/原始结果。

验收 AC-16：调用先持久 START，完成事件持久入库或加密 fsync WAL 才返回成功；持久通道不可用阻断新 SQL；requestId 幂等；180 天保留策略执行；解析失败只保留哈希/长度/错误码，不能伪称已可靠脱敏。

### FR-17 个人历史

作为员工，我要查看本人调用时间、平台、目标、脱敏 SQL、执行/拒绝结果和 requestId。服务器从会话取 userId，不接受客户端选择其他用户。列表与详情均检查所有权。列表不显示业务结果集，不提供无审查的批量原 SQL 导出。

验收 AC-17：修改路径、查询参数或 cursor 不能获取他人记录；权限变化后历史不能借此重新披露隐藏表列；失败信息提供下一步动作。

### FR-18 接入配置中心

作为员工，我要按已验证客户端版本复制通用 MCP 配置，查看 OAuth/重新授权/PAT 适用条件。个人接入上下文仅列服务端按平台Scope、目录模式及有效权限过滤后的可选平台、源和命名空间，不调用全局管理列表猜测ID。配置来自服务端部署参数，禁止硬编码假生产域名。OAuth 通用配置无个人凭证；PAT 配置显示安全占位符，用户自行在本地客户端粘贴一次性值。页面不读取 token 回显配置，不提供自动重放 SQL。

验收 AC-18：只出现 `/mcp` Streamable HTTP；错误、拒绝和过期给出标准处理指引；所有示例标注已验证/待验证，未配置域名时禁止复制貌似可用的地址。

### FR-19 运行状态与故障提示

作为管理员，我要看到数据源同步/连通状态、审计写入健康、容量风险和安全状态核验失败；指标与告警由后端/监控提供，前端不凭请求成功率推断安全健康。权限拒绝不计系统故障。告警不包含凭证、原 SQL 或业务结果。

验收 AC-19：401 重新登录、403 申请权限、409 重载差异、422 修正参数/语法、429 限次退避、503 可用性故障有不同提示；错误始终附 requestId；非 retryable 拒绝不自动重试。

### FR-20 文档、证据与发布声明

作为项目负责人，我要用需求、接口、测试和证据交叉追踪每个安全结论。参考源码保留许可与归属；内部私有夹具不进入开源包。29 条 VQ 的完整夹具、参数渲染器和预期结果当前尚未具备，必须向合法持有人获取并在内部模块验收，不能声称已通过。

验收 AC-20：证据包含版本、配置、用例 ID、预期/实际、命令与日志；未执行项标“待执行/阻塞”，不用设计评审代替集成测试；[测试报告](../test/test-report.md)以真实状态记录。
