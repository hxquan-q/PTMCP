# PTMCP 用户常见问题

版本：1.0-design · 日期：2026-10-23 · 状态：面向目标产品的说明，待实现与验收。

## PTMCP 会替我选择模型或理解业务问题吗？

PTMCP 负责权限、结构、只读执行和审计。外部 Agent 选择模型、生成 SQL 并解释结果；网关不调用大模型，也不将结果保存为训练语料。

## 一期支持哪些数据库？

支持通过验收的 MySQL 8 系列和 PostgreSQL 部署版本。候选集成环境为 MySQL 8.4、PostgreSQL 18，完整补丁和驱动由 M0 锁定。Oracle、SQL Server 属于二期。JDBC 能连接不代表已经支持。

## 为什么我能看到表名，却不能看字段或查询？

平台的 DISCOVER 模式可披露表名和表级说明并标记权限，显式 META DENY 仍隐藏。只有有效 READ 才能看到字段、键和字段说明及查询数据。HIDE 模式只显示有效 META/READ 表。请把数据源 ID、可见表名和 requestId 交给授权管理员核对；一期没有内置权限申请审批流。

## 我是管理员，为什么也查不了表？

管理菜单权限与业务表权限分开。管理员查询同样需要有效 READ，并与当前平台 Scope 取交集。安全审计员也不自动获得业务表 READ 或原 SQL 解密权。

## 在一个客户端可查，换另一个客户端为什么不行？

不同平台有不同 Scope 和启停状态。实际权限是平台上限与个人有效权限的交集。PAT 固定使用个人终端平台；复制其他平台 Header 不能提高权限，token 的 platformId 与 Header 冲突会被拒绝。

## 第一次怎样接入 Agent？

登录个人门户，在接入配置页选择已验证的客户端版本，复制通用配置并在 Agent 中连接。支持 OAuth 的客户端会打开授权服务登录和同意页。当前没有可复制的生产域名，部署后由服务端生成配置；见[业务流程](user_flow.md)和[用户手册](../ops/user-manual.md)。

## 为什么登录门户后，授权页面还让我登录？

管理会话和授权服务会话独立。一期共用账号认证规则，但不承诺跨应用 SSO。授权页应核对客户端、平台和范围后再同意。

## 是否所有客户端都能无感续期？

不能预先保证。公开客户端刷新扩展默认关闭，只有 M0 完整链路与相应客户端版本验收通过后开放。Access JWT 有效期 10 分钟；可刷新授权族绝对寿命 30 天、空闲寿命 7 天。不能刷新的客户端需要重新授权，或按兼容说明使用 PAT。

## 提示刷新失败、授权已撤销怎么办？

先重新走授权。每次刷新都会轮换 token；旧 token 再用、并发刷新冲突或响应丢失可能要求重新授权。不要连续重试旧凭证，也不要自行在桌面客户端填共享 clientSecret。管理员可通过 requestId 和授权族状态排查。

## PAT 是什么，能找回吗？

PAT 是个人终端使用的高熵凭证，默认 30 天、最长 90 天。完整值只在创建时展示一次，后台仅存哈希，之后不能找回。遗失时撤销旧 PAT 并新建；怀疑泄露时立即撤销。列表只展示名称、前缀、到期时间与状态。

## PAT 放在哪里？

放在客户端安全凭证位置，以 `Authorization: Bearer` 发送。禁止放在连接 URL、浏览器存储、截图、工单或聊天中。通用配置不包含个人凭证；PAT 示例使用占位符。

## 退出门户会终止所有外部 Agent 吗？

退出只结束当前控制台会话。要终止外部访问，在“我的授权”撤销对应 OAuth 授权族，在“PAT”撤销相应 PAT。改密会提升认证版本并撤销会话/令牌；正常账号不会因此被设为停用。

## 撤销和授权到期什么时候生效？

已提交撤销对新查询最大 5 秒生效；排队出队和 JDBC 提交前复核。自然到期及未来 DENY 按服务端时间边界生效。在途请求尽力取消，已经返回的数据无法收回。主库安全状态不能确认时会拒绝新查询。

## 支持哪些 SQL？为什么普通 SELECT 也被拒绝？

一期只放行已验证的单 SELECT，包括受支持的普通 CTE、子查询、JOIN、UNION 和窗口表达式。未知语法、歧义对象、系统对象、递归 CTE、锁、INTO、写操作、危险函数、带路径函数/表函数、自定义类型或操作符会拒绝。SHOW、DESC、EXPLAIN 不开放，结构查询请走目录/结构工具。

## 视图能否代替底层表授权？

不能。视图一期默认关闭，只有依赖图完整可解析、定义hash与快照一致，且视图本身与全部底层物理关系均有READ并通过专项验收时才开放。未知依赖、外部表或其他未验证路径拒绝；只给视图授权不能绕过底层表权限。

## 数据库和表同名时如何选择？

必须选择 datasourceId；同名库不跨数据源自动匹配。PostgreSQL 的结构与执行还必须指定 schemaName。原名、大小写和引号都参与对象绑定，业务别名不能替代物理对象身份。

## 最多能返回多少数据？截断是不是错误？

默认最多 500 行，用户只能收紧；单格输出最多 4KiB，完整响应最多 1MiB。成功响应携带是否截断及原因；不是完整数据时应缩小范围、选择必要字段或使用聚合。单格截断用元数据标注，不写入伪造的 `[TRUNCATED]` 值。未验证内存边界的大字段表达式可能直接拒绝。

## 为什么大整数和金额显示为字符串？

BIGINT、DECIMAL 以字符串传输，避免浏览器和客户端数值精度丢失。NULL 保留 null，日期时间有显式格式。客户端不应自动转成浮点数再计算财务金额。

## 遇到超时、忙碌或权限错误要重试吗？

权限、语法和非只读拒绝不重试；请修正问题。429 说明并发/队列限制，503 说明暂不可用，只有 `retryable=true` 时客户端才可限次退避。网关不自动重放 SQL。请保留 requestId，勿把凭证或原始结果附在工单里。

## 为什么审计故障会让我不能查询？

执行前必须持久记录开始事件，完成事件也要持久确认。数据库和加密 WAL 都不可写时，系统停止新 SQL，避免出现无法追踪的数据访问。崩溃时未确定结局的记录会标 UNKNOWN，不代表成功，也不会自动重跑。

## 谁能看到我的历史和原 SQL？

个人页只返回本人记录。获授审计权限的人可看其范围内脱敏调用；原 SQL 加密保存，需要独立 `ptmcp:audit:decrypt`、受控审计范围与理由，任何角色默认无权，该访问本身也审计。系统默认不记录业务结果集；审计保留 180 天，备份保留见[运维手册](../ops/operation-manual.md)。

## 当前文档说的能力已经可用吗？

没有。这是 1.0-design 设计基线，参考源码不等于 PTMCP 实现。29 条 VQ 私有夹具尚未齐备，客户端和性能也尚未实测；以[测试报告](../test/test-report.md)与正式发布记录为准。
