# PTMCP 测试计划

版本：1.0-design · 日期：2026-10-23 · 状态：测试设计，尚未执行全系统测试。

依据：[总体方案](../总体方案.md)、[PRD](../product/PRD.md)、[接口契约](../backend/api-spec.md)、[安全执行设计](../backend/datasource.md)、[SQL守门设计](../backend/sql-guard.md)、[认证设计](../backend/authentication.md)、[授权设计](../backend/authorization.md)和 [审计设计](../backend/audit.md)。若文件拆分或契约调整，以总体方案和正式接口的最新兼容版本为准，并同步本文用例映射。历史输入为 [review](../reviews/review.md)。

## 1. 测试目的与证明边界

验证外部 Agent 提交的 SQL 经过身份、平台、权限、AST 与执行约束后，只访问被批准的对象；验证拒绝不会取得业务连接，授权撤销有确定时限，失败不会留下可复用的脏连接或无持久记录的查询。业务数据库只读账号是额外边界，不能代替网关用户 ACL。

测试分成规则单元测试、真实 MySQL/PG 集成测试、OAuth 客户端互操作、控制台浏览器测试、故障注入与性能容量测试。解析通过、JDBC 可连接、容器存活均不能替代业务验收。回归集内无绕过只说明该威胁模型与构件组合的结果，不宣称证明任意 SQL 安全。

当前仓库主要提供参考项目与设计材料；不得把本计划标成已执行。实际状态集中记录在 [test-report.md](test-report.md)。

| 范围 | 本期验证项 | 主要责任 |
| --- | --- | --- |
| 产品业务 | 组织角色、Allow/Deny、平台 Scope、目录模式、个人历史、PAT | 产品负责人定义预期，QA执行 |
| SQL 内核 | 词法、只读、作用域、列绑定、系统对象、函数/类型、LIMIT、重解析 | 内核开发与安全评审 |
| 执行 | 双方言、事务、宽行预算、取消竞态、池生命周期 | 后端与QA |
| 认证 | 管理会话、AS登录、PKCE、公开刷新完整链、JWT/PAT撤销 | 认证开发与安全评审 |
| 运维 | 持久审计、WAL恢复、主库失联、扩缩容、备份恢复 | 运维与QA |

Oracle、SQL Server、列级/行级权限、SSO、ERP 同步不在一期通过声明内。对应入口应不存在或明确禁用；不能只跳过这些功能的测试后仍保留可选项。

## 3. 可复现测试环境

### 3.1 环境矩阵

| 环境 | 配置设计 | 用途与隔离 |
| --- | --- | --- |
| 单元 | JDK21、锁定 JSQLParser5.4、固定时钟、假池/执行器计数器 | 无业务数据库；精确断言拒绝路径连接数为0 |
| 集成 | MySQL8.4 元库、Redis、MySQL8.4 业务库、PostgreSQL18 业务库；三Boot进程 | 使用合成数据与独立网段；不得对生产库做攻击/断连测试 |
| 客户端互操作 | 测试HTTPS域名、受信证书、实际桌面客户端、受信后端客户端 | 域名与注册回调以环境清单记录；不能用模拟HTTP请求替代真实客户端 |
| 故障注入 | 与集成同构；可控制网络、进程、磁盘限额、数据库会话 | 每轮重置数据、持久卷与安全版本，保存注入时间线 |
| 性能 | gateway每实例2vCPU/4GiB；固定JVM、单副本先测；独立压测机 | 元库/Redis/业务库资源单列，避免把其扩容收益算成网关优化 |
| 恢复演练 | 隔离的新环境、备份副本、历史密钥与WAL副本 | 不覆盖正在服务的元库；执行恢复后账号/令牌安全检查 |

以上为候选目标版本。M0 必须保存完整补丁号、镜像 digest、驱动版本、effective POM、依赖树、提交 SHA、JVM 参数、字符集、SQL mode、MySQL `lower_case_table_names`、PG 编码/时区/角色权限。候选版本未锁定前，测试报告标注环境未就绪。

### 3.2 标准夹具

- 身份：普通员工 U-A/U-B、组织授权管理员 U-ORG、安全审计员 U-AUD、平台管理员 U-ADM、停用用户 U-OFF；研发只用合成账号。
- 组织：部门 D-PARENT、D-A、D-B；角色 R-READ、R-DENY、已停用角色 R-OFF；允许/禁止继承各一组。
- 平台：P-DESKTOP（Tier2）、P-PERSONAL（Tier3）、P-SERVER（有mTLS/后端证明的Tier1）、P-OFF。新DCR客户端未绑定额外Scope。
- 数据源：DS-MY-A 与 DS-MY-B 都有 catalog `erp`；DS-PG-A 的 catalog `ptmcp_fixture` 含 `sales`、`public` 两个schema，各有同名 `orders`，内容有不同标记。
- 普通表：`orders(id,customer_id,amount,tenant_marker)`、`users(id,name)`、`salary(id,user_id,pay)`；另有带引号大小写表、Unicode表名、宽行/LOB/JSON、NULL和精确数值夹具。
- 时间：固定 `T0`，创建 `[T0,T1)` Allow、未来生效 Deny、恰在 T1 到期的授权。接口持久化为 UTC，门户验证 Asia/Taipei 显示，不用测试机当地时区推断。
- 权限：U-A可读orders/users不可读salary；U-B能读salary；P-DESKTOP不含salary；配置 META Deny、READ Deny、父级Allow/子级Deny、角色/个人交叉授权。

所有创建/清理SQL、随机种子、fixture版本均应随测试模块入库。内部29条VQ没有拿到原始夹具前不得自行编造同名“29条已通过”；以 BLOCKED 记录并指定资产责任人。

## 4. 可观测断言与结果等价

每个用例至少保留 caseId、requestId、构件清单、输入哈希、预期/实测、执行时间、断言日志；不得在公开CI输出真实密码、token、原始业务结果或未脱敏SQL。

已认证且通过请求大小预算的工具调用应在guard运行前持久确认最小START（身份、输入哈希/长度），之后补充脱敏信息与对象；guard拒绝也必须有同requestId的TERMINAL。测试在guard中途杀进程确认已有可恢复记录，而不是只验证执行器前才写START。

静态否决使用双重证据：单元假池 `businessConnectionAcquisitions=0`，集成时业务库连接/语句计数或连接代理观测为0。元库审计连接不属于“业务连接”；不能因允许记录审计就误判失败。时间状态复核失败也不得提交业务SQL；若失败发生于已借连接之后，应清理归还并记录阶段。

改写等价必须在合成库执行两条查询：由测试专用隔离账号直接执行合法原SQL作为基准；再由PTMCP执行final_sql。对没有触发行数/字节限制的合法查询比较列序、列类型、NULL、精度和结果多重集合；只有明确ORDER BY时比较行序。对于 LIMIT 收紧、输出限幅或受支持的类型序列化变化，使用单独的转换预期，不能要求全部原始结果相等，也不能用转换差异掩盖对象绑定错误。需要确定截断前缀时夹具必须显式ORDER BY。

每条 ApprovedQuery 的关系绑定清单应与final_sql重新解析后的物理对象一致；测试连接应在目标表插入可识别的源/schema标记，以验证实际访问对象。不能只断言“SQL字符串含schema”。

## 5. 用例分层与门禁

| 层级 | 门禁内容 | 失败处置 |
| --- | --- | --- |
| 提交级 | 纯规则单元测试、六个Finder历史案例、未知AST fail-closed、DTO兼容、依赖边界 | 任一P0失败阻断合并；不得删测/放宽规则换绿 |
| 合并级 | MySQL/PG集成、对象/列改写等价、ACL组合、时间边界、审计持久准入 | 修改涉及安全链即运行全部对应矩阵 |
| 每夜 | ≥300条有来源与预期的参数化安全回归、确定随机种子的变异、刷新并发、取消竞态 | 固定失败种子入库，修复后加入提交级回归 |
| 里程碑 | 客户端真实联调、宽行内存、版本时效、UI权限、故障注入 | 未到退出条件不得把M0/M1标通过 |
| 发布级 | 全回归、容量、备份恢复、灰度/回滚演练、依赖与许可复核 | P0/P1未关闭或关键BLOCKED不得上线 |

`P0` 为越权、错误对象执行、可写语句、凭证/敏感信息泄露、失效边界突破、连接复用竞态或审计缺失等安全阻断项；`P1` 为核心业务/可靠性项；`P2` 为不影响安全边界的易用性项。P0与P1应100%通过。已知Finder反例作为历史缺陷证明，不计为PTMCP已通过或已失败。

### 5.1 M0 退出条件

1. gateway唯一JSQLParser5.4且无Sa-Token；common/guard依赖符合边界，三进程可启动。
2. 六个历史案例获得各自正确集合；四个越权反例执行器/业务池调用为0。
3. 单MySQL+PAT+平台交集+final_sql+持久START/结局审计纵切通过；完全限定和列引用改写结果正确。
4. 一个公开 `none+S256` 与一个机密后端客户端真实跑通发现、登录、过期与撤销；公开刷新扩展验证converter/provider/grant/generator/持久化，不通过则扩展保持关闭并记录产品降级。
5. 宽行/可变宽表达式处理策略有可测的内存预算；不能证明边界的路径拒绝并不开放。
6. 主库状态确认、丢事件与缓存嵌套下，撤销对新查询不超过5秒；无法确认时停止受理。

### 5.2 M1～M4 退出条件

M1通过双方言资源绑定、取消和池复用、Allow/Deny与时间组合以及≥300条回归。M2完成四类客户端指定版本与管理API。M3完成双视角UI、个人数据隔离、CSRF与入口权限。M4完成fuzz、容量、WAL/灾难恢复、灰度与回滚。29条VQ必须提供数据、参数渲染和业务预期后方能验收；缺失时明确BLOCKED，不能用普通SQL解析样例替代。

## 6. 性能与内存测试口径

性能按以下独立指标出报告，禁止只报一个“响应时间”：

| 指标 | 计时/统计范围 | 设计目标 |
| --- | --- | --- |
| gateway内部非数据库开销 | 输入处理、解析、绑定/授权、改写/复核、持久审计准入等内部处理；各span明细相加，包含元库/Redis依赖耗时 | 2C4G、50客户端并发、≤4KiB SQL、热权限缓存时P95<50ms |
| 准入队列等待 | 入队到获得执行槽位，含超时/拒绝样本单列 | 每副本最多32等待，最长3秒；超限明确拒绝 |
| 业务连接获取 | Hikari借出到获得连接 | 最多3秒，耗尽分位数/失败率单列 |
| 业务SQL执行与读取 | JDBC提交到结果读取停止，另列清理 | SQL15秒上限；实际性能随业务库而定 |
| 端到端 | HTTP请求到完成响应 | 报P50/P95/P99与错误分布，不用它替换50ms指标 |
| 宽行内存 | 进程RSS、JVM heap/direct buffer、分配/GC、并发与结果行宽 | 不得OOM；在M0写出经实测的每活动请求上界与全局安全余量 |

50个客户端并发不意味着同一时刻50条SQL：单副本执行16、排队32，其余应受限；同时报告429/工具限流错误比例、吞吐和已接纳样本数，不能把拒绝请求的低延迟算成执行成功P95。推荐10分钟预热、30分钟稳态、至少3轮；冷缓存/大SQL/Redis故障另成场景，不混入目标口径。具体持续时间为测试设计，尚无实测结果。

宽行分别覆盖单格10MiB、多个大列、500行、100行fetch批次、Unicode膨胀、JSON/LOB、聚合字符串与表达式放大、客户端提前断开。可设置受控JVM堆上限使潜在物化更早暴露，但容器被OOM Kill不算通过。取值API名称不作为流式证明；记录驱动源码/配置和实际分配轨迹。若数据库端限幅改变了输出，报告转换契约及应用截断标记。

1MiB响应预算针对最终完整JSON-RPC响应的UTF-8字节数，包含structuredContent与text双份内容、text中的二次JSON转义、字段与协议封装；抓包或最终编码器计数验证。不能只测data或把单份内容1MiB误称完整响应达标。

## 7. 故障注入与恢复

必测事件：Redis Pub/Sub丢失/重启；主库不可达超过5秒；数据库连接半断开；SQL刚完成后取消任务迟到；WAL磁盘满/只读；审计消费者停机；START写成功后gateway崩溃；结局WAL fsync后入库前崩溃；刷新事务提交后响应丢失；迁移失败；旧版本滚回；元库从备份恢复。

对每个注入场景画出提交、注入、请求准入、JDBC开始、取消确认、审计持久化的单调时间线。状态未知时允许UNKNOWN，不能用SUCCESS填平缺失。恢复后不自动重放业务SQL，不复活已撤销凭证，不清空WAL掩盖积压。

## 8. 缺陷与报告规则

状态使用 PASS、FAIL、NOT_RUN、BLOCKED、NOT_APPLICABLE。NOT_RUN是尚未执行；BLOCKED必须写缺少的构件/环境/资产和解除条件；不能将二者折算为PASS。缺陷记录 caseId、影响、复现条件、构件SHA、最小输入、脱敏证据与修复回归ID。安全缺陷在内部缺陷库处理，公开报告不包含真实凭证或攻击业务库数据。

报告采用 [test-report.md](test-report.md) 的结构：历史证据、当前执行、覆盖率与阻塞项分开。发布报告必须绑定实际commit、镜像digest、配置版本、客户端版本及执行日志，产品/安全/运维分别确认其领域。设计评审通过不等于测试通过。

## 9. 测试交付物

工程格式/命名由[工具门禁](../standards/quality-tooling.md)验证，使用故意错格式、错误组件名/Props、通配导入等正反例证明规则生效；不能用人工格式审查或配置解析代替。TC-API-009 验证 R<T>/模块码/协议隔离，TC-DB-001 验证实际 DDL 与自有 SQL 约束。安全变更同步[ASVS 5.0.0 清单](asvs-checklist.md)，未实现/未运行项保持 NOT_RUN，设计缺口单列 GAP。

交付可运行的单元/集成模块、合成数据seed、参数化case manifest、SQL变异种子、29条VQ内部资产位置、真实客户端矩阵、性能原始数据、故障时间线、恢复演练记录以及脱敏报告。构建脚本和一键测试命令是后续工程产物；在其真正入库前不向使用者提供假定可运行的命令。
