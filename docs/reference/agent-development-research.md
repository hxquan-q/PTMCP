## 取舍

| 参考实践 | 当前采用 | 适配原因 |
| --- | --- | --- |
| 根入口短、领域规范按需加载 | AGENTS + 现有 docs 路由，CLAUDE 仅发现入口 | 常驻规则与任务所需事实分开，避免全库塞上下文 |
| docs 描述事实，notes 保留因果 | 保留 docs 的显式设计状态；ADR 继续承载既有架构因果，notes 补独立流程/经验 | 当前还没有产品实现，不能把设计写成运行事实，也不能制造平行 ADR |
| 四生命周期、六分类、无逐篇总索引 | notes 路径表达状态；新建时查重与互链 | 减少并行索引冲突；不为分类预建空目录 |
| 被否方案先写最强理由 | 记录真实备选、放弃原因、重访条件、收益与代价 | 防止新 Agent 重走旧路线，同时允许约束变化后重新评估 |
| 写前确认门 | 已授权范围内写最小合同后继续；只对实质未决项提问 | 用户要 Agent 主导，流程记录不应再制造批准门 |
| open-forge 项目台账和验收分层 | 沿用 tasks，加独立工作项、验证和交接；区分工程/接受/集成/发布 | 当前阶段无需迁移到完整 project 管理树，也不继承自动提交/推送授权 |
| 外部自主控制器、签名租约和发布对账 | 不部署；当前会话自主推进，委派需满足本仓规则 | 缺少该产品运行环境和实际需求，文档不冒充已实现系统 |
| 归档 manifest + 上游 TS 工具链 | 自有标准库检查器，以 Git 基线比较冻结归档 | 现有仓库已有 Python 校验，避免为规范新增 Node 工程；自校验无身份保证，Git 比较也不是审批签名 |
| 图谱/看板 | 保留为未来可选导航 | 只有一篇过程笔记时先保证真实合同与证据，不用可视化代替执行闭环 |

## 采用后的检验

从新会话任务入口、轻量修改、安全修复、跨会话恢复、缺依赖、伪完成和归档损坏七类场景检验流程。结构性反例由脚本回归覆盖；语义场景由工作项中的自审记录说明，不把这次自审声称为多模型实验。

失效条件：M0 建立真实工程入口，团队开始持续并行，或任务量使现有检索难用。届时扩充同一检查入口、模块级 AGENTS 或调度机制，先证明实际收益；不要另起一套无法回溯的状态系统。
