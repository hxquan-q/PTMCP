# ADR-0005：隔离若依后台与网关的进程和依赖

状态：纳入设计基线，待依赖与启动验证。日期：2026-10-23。

## 背景

若依MyBatis模块传递依赖Sa-Token和另一解析器版本。若把实体/持久化/安全模块整个放进common，gateway即使配置Spring Security也可能引入另一套安全自动配置。

## 决策

三个Boot进程独立。common仅领域契约；guard不依赖Spring；datasource不依赖guard；gateway/authz使用独立persistence适配。admin通过自己的若依适配复用组织能力，连通性检查与Schema同步可依赖datasource，但不能提供原始SQL执行旁路。

每个运行进程依赖树独立收敛，gateway仅JSQLParser5.4且无Sa-Token。admin自身的MyBatis解析器不用为“全仓一个版本”被盲升；如未来同进程调用guard，先验证兼容或改变边界并新记ADR。

## 替代方案

- 全部放同一若依应用：运维单元少，但两套安全链和解析器耦合高。
- common共享ORM与若依所有实体：省少量适配，长期破坏模块独立性。
- 所有模块改成微服务：一期不需要，纯guard保持jar即可。

## 后果与验证

增加轻量实体映射和三进程发布工作，换取隔离的认证与升级边界。M0保存effective POM、dependency tree、自动配置报告与各应用启动证据；构建时禁止形成环状依赖。
