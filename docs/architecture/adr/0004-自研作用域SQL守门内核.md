# ADR-0004：JSQLParser 解析，自研作用域关系绑定与安全校验

状态：纳入设计基线，待SQL等价与安全回归。日期：2026-10-23。

## 背景

本地JSQLParser 5.4探针已证明原版TablesNamesFinder在同名派生表别名/嵌套CTE等情况下漏表；dbx只读证明自身也不声明是安全边界。只复制列表或工具函数不能形成PTMCP表级权限。

## 决策

使用单个JSQLParser版本完成解析/AST生成；独立纯Java guard提供词法预检、结构只读、表达式函数类型白名单、ScopedTableBinder、ACL、限定名/列引用联动改写、LIMIT/FETCH与输出计划。改写后重解析并验证绑定对象与预算不扩大，执行器只消费内部ApprovedQuery。

一期拒绝递归CTE、未知节点、表函数、限定路径函数、系统命名空间及自定义类型/操作符。普通CTE按方言作用域绑定；派生别名只参与列限定，不消除物理表。Schema快照、物理关系与列引用共同参与绑定，不能只改FROM字符串。

## 替代方案

- 原版Finder直接做ACL：已有反例，拒绝。
- 直接vendor dbx Rust：不符合Java后端约束，也不能免除权限语义自研。
- Druid WallFilter主判定：防注入能力不能等同只读/表ACL；仅可选旁路告警。

## 后果与验证

守门内核成为高风险自研模块，必须维护支持语法清单、未知节点默认拒绝、语义等价和变异回归。R1两个对照例与四个反例按各自预期集合测试；拒绝路径断言业务连接数0。dbx移植内容保留Apache-2.0归属，私有评测不混入开源包。
