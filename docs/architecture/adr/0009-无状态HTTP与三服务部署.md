# ADR-0009：一期采用无状态 Streamable HTTP 与三服务轻量部署

状态：纳入设计基线，待四客户端传输兼容验证。日期：2026-10-23。

## 背景

一期只提供三个请求式只读工具，不需要依赖跨请求会话保存用户身份或长事务。若任由MCP会话成为权限缓存，会增加多副本路由与撤销风险。运维规模尚不要求自建完整K8s/消息集群。

## 决策

MCP端点保持HTTPS Streamable HTTP `/mcp`；Spring AI候选使用protocol=STATELESS，每请求重新验证凭证与权限，不把Mcp-Session-Id当身份。兼容测试如发现必须采用stateful，需新ADR描述会话状态与每请求鉴权，不能暗中放宽。

运行三个Boot进程、Nginx、MySQL元库和Redis；UI由Nginx静态托管。默认VM/容器编排，已有K8s可按基础设施约束落地。旧SSE端点、公共CDN、Kafka、独立搜索引擎不作为一期依赖。

## 替代方案

- 默认stateful MCP：可支持更多通知能力，但一期无明显收益。
- 三应用合并：减少进程但引入认证和依赖耦合，见ADR0005。
- 为完整性强制K8s：增加部署门槛；先依据现有运维能力选择。

## 后果与验证

需要在WorkBuddy、Cursor、Claude Code、VS Code锁定版本测试初始化/列表/调用/过期与错误语义。生产拓扑、域名与镜像digest应进入部署证据；文档示例不代表服务已运行。无状态使横向扩容简单，但数据库池总预算、共享配额与持久WAL仍需跨副本管理。
