# ADR-0008：分层执行预算，取消清理完成前不复用连接

状态：纳入设计基线，待驱动/内存与竞争测试。日期：2026-10-23。

## 背景

SQL LIMIT不能限制所有计算量和大字段大小；JDBC的stream方法也可能先物化单元格。超时回调若晚到已归还的连接，会干扰后续请求。线程返回、HTTP断开、cancel返回都不等于数据库工作终止。

## 决策

SQL/AST、输出、排队、执行并发、连接与取消清理分别设预算。普通窄行fetchSize100；可变宽输出使用经过证明的数据库端限幅/投影或拒绝，按行宽调整批次。4KiB单格与1MiB响应仅是产品输出界限，内存安全另有驱动测试。

执行任务拥有连接直至结果关闭、原执行任务终止、取消任务终止、回滚与状态恢复全部确认；否则淘汰。PG使用有效只读事务中的SET LOCAL，MySQL使用其原生只读/超时/取消机制，不共用盲KILL逻辑。

## 替代方案

- Future超时后直接归还连接：数据库可能仍执行，拒绝。
- 仅getCharacterStream截断：不能保证驱动内存界限，拒绝。
- 仅容器内存上限：限制故障范围，不等于没有OOM或业务库DoS。

## 后果与验证

需要更多状态机和数据库侧测试，不能以mock证明驱动正确。宽行/LOB/JSON/Unicode、单格10MiB、50客户端、客户端断开、迟到取消、滚回失败必须可复跑。达不到预算的输出子集不开放；如未来需要任意复杂SQL，另评估隔离执行服务与更强预算机制。
