# ADR-0007：审计持久准入，首期使用非分区存储

状态：纳入设计基线，待崩溃恢复验证。日期：2026-10-23。

## 背景

“每次调用可追溯”不能由执行后的内存入队保证。MySQL按时间分区要求每个唯一键含分区列，与全局UNIQUE(request_id)存在设计冲突。当前尚无生产审计量证明一期必须分区。

## 决策

已认证且符合请求预算的Tool入口持久写入最小START outbox并确认，先于昂贵guard与业务连接；审批后补充信息并复用该START。结束事件持久入库或加密fsync WAL后再返回成功。消费者按request_id/事件阶段幂等落audit_log。崩溃遗留记录恢复UNKNOWN，不自动重跑SQL。

audit_log与audit_outbox首期不分区，保留全局请求幂等约束。按时间索引分批清理180天数据；归档、备份与密钥生命周期一致。默认sql_masked/指纹，原SQL密文保存，解密有独立权限与访问审计。

## 替代方案

- 仅异步内存队列：进程退出即丢，拒绝。
- Redis Stream即视作绝对持久：未指定AOF与确认语义，不足以支撑该承诺。
- 一期月分区：可用独立全局幂等表解决，但增加复杂度；按量再演进。

## 后果与验证

审计持久确认增加准入开销且纳入性能测量；不可写时牺牲新SQL可用性。验证START前后杀进程、WAL损坏/重放、重复事件、磁盘满、DB故障和终态未知，不把UNKNOWN统计成成功。
