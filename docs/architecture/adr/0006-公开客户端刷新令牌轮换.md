# ADR-0006：公开客户端刷新采用完整认证扩展与严格轮换

状态：设计采用；扩展默认关闭，M0通过后按客户端开放。日期：2026-10-23。

## 背景

Spring Security默认不会为授权码公开客户端签发RT。公开refresh请求的转换/认证入口也需要适配，只替换token generator不能证明全链路可用。用户希望一次授权后续期，不能用桌面共享secret冒充机密客户端。

## 决策

为受管客户端实现converter、NONE认证provider、refresh grant provider、generator与事务存储。授权码必须PKCE S256。每个refresh family绑定用户、client、平台、audience、auth_version，绝对30天/空闲7天。

标准撤销端点同样定义PUBLIC NONE转换/认证与token-client-family归属校验；未知token使用防枚举响应，不能仅client_id就撤销别人授权。introspection仅受信机密客户端。refresh与revoke分别做协议验证。

旧token哈希及消费墓碑留到family过期；同事务锁/CAS完成消费、代次递增、新RT与授权持久化。只有一次消费成功。旧RT再用撤销整族，所有JWT通过sid状态检查失效。不采用基于短时间窗口的无条件豁免；客户端single-flight，响应丢失需要重新授权。

## 替代方案

- 桌面下发共享client_secret：不能保密，拒绝。
- 仅无限延长JWT：延长盗用与权限陈旧窗口，拒绝。
- 仅重新授权/PAT：保留兼容路径，但不能冒称满足已验证无感续期。

## 后果与验证

这是安全敏感扩展，不是框架配置开关。每个客户端记录真实版本与能力，完成首次授权、过期、并发刷新、旧RT重放、丢响应、数据库回滚、吊销后的新旧JWT检查。未通过的客户端不启用扩展，不默默放宽安全规则。
