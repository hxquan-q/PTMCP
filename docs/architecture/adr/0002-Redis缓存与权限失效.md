# ADR-0002：Redis 做缓存，主库保证权限失效时限

状态：纳入设计基线，待故障注入验证。日期：2026-10-23。

## 背景

物化权限集合可以减少重复展开组织/角色/资源树。Redis Pub/Sub 可能丢消息，时间授权到期也不会产生数据库写事件；只靠消息失效不能满足撤销要求。

## 决策

MySQL主库保存安全状态、auth_version、策略epoch及事件outbox。Redis保存可重建权限集合、快速通知和限流状态；本地缓存最多1秒。权威安全确认最大陈旧5秒，期限从最后主库成功确认起算，缓存命中不续期。过期且主库不能确认则拒绝新查询。

权限缓存TTL不超过300秒和最近未来有效期边界，命中时仍检查绝对nextBoundaryAt与版本。30秒补扫事件是恢复机制，不用于证明5秒撤销。新查询在排队后、JDBC提交前再次检查；已返回数据不可撤回。

## 替代方案

- 仅Pub/Sub：丢消息会无限持有旧权限。
- 仅JWT权限claims：长效表集合无法及时反映组织/表变化。
- 每次重算全部权限：正确但成本高；采用短时权威版本核验和按版本缓存。

## 后果与验证

增加主库版本读取和缓存重建逻辑；容量测试须包含这些开销。Redis恢复不能覆盖更高版本状态。丢通知、主库故障、时钟偏差、缓存热命中及自然到期必须做跨副本测试，不能只测主动清缓存。
