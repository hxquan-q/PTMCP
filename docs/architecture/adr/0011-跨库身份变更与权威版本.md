# ADR-0011：权威用户版本与可恢复的跨库改密

状态：纳入设计基线，实施与故障验证进行中。日期：2026-10-30。

## 背景

ADMIN 与 AS 可以读取独立宿主身份库的 `sys_user`；元库拥有授权、会话索引和安全事件。
旧[认证设计](../../backend/authentication.md)把密码与撤销描述为同库原子事务，无法覆盖宿主提交失败、
提交回包丢失或迟到重试。[ADR-0003](0003-独立Web会话与MCP-JWT.md)的独立安全域继续成立，
本篇替代其中隐含的跨库原子写假设，细化共享账号状态的持久契约。

## 决策

`sys_user_security` 是 auth_version 与 identity_version 的唯一权威。凭证只保存签发快照，
不得从 OAuth family、PAT 或浏览器会话反推当前版本。登录先捕获 READY/版本，再读取宿主 hash，
签发时依全局→用户锁序重新比较；不能给旧密码的验证结果附上新版本。

改密采用两个独立存储的可恢复协议，不使用分布式事务：

1. 在元库全局→用户事务中，核对已捕获的 READY/auth_version、用户 aggregate version 与有效状态，
   更新 profile 版本、提升 auth_version/identity_version，记录唯一不可变 operation，置 CHANGE_PENDING，
   撤销 ADMIN/AS 索引、OAuth 授权族及 PAT，并写安全事件和脱敏管理记录。
2. 只有元库提交确认才尝试宿主写。operation 保存宿主旧 BCrypt hash 的 SHA-256 字节摘要和独立生成的目标
   BCrypt hash。宿主以用户 ID、active 状态及 expected-hash 作条件更新；更新为零时在同一事务 current read
   锁定并精确比较目标 hash 和 active 状态，只有已写入同一目标才是幂等成功。
3. 宿主提交确认后，在元库全局→用户事务中核对当前 operation、版本与 CHANGE_PENDING，CAS 恢复 READY，
   同事务标记 operation COMPLETED 并清除 expected/target hash，只保留 operation、归属与版本墓碑。不能在迟到失败分支撤销新凭证或恢复旧状态。
4. 任何提交结果不明都用新连接读取持久状态。begin 不明不得继续宿主写；宿主失败或结果不明保持 Pending；
   complete 不明不能把已提交的 READY 改回 Pending。恢复重试只使用已持久化的目标，不能提供新密码、
   覆盖/取消 Pending 或靠超时放行。完成后的重复恢复不再写宿主、提升版本/epoch 或追加事件；并发输家回滚后用新连接核对同 operation 完成状态。

宿主 expected digest 使用 BINARY(32)，与 `UNHEX(SHA2(hash,256))`比较。每次 operation 的目标 BCrypt
独立生成；旧 A 只可匹配 H0，A 完成后为 H1，新 B 完成后为 H2，迟到 A 无法覆盖 H2。
宿主管理员直接修改 hash 会导致安全冲突并保留 Pending，需运维处理，不自动覆盖外部更新。
本协议假设宿主不会被其他受信管理工具主动恢复为历史 hash；该类恢复须先隔离写方并按事故恢复流程处理。

恢复接口仅平台管理员可用，保留 CSRF、Origin、If-Match 和幂等要求；读取状态只返回 READY/CHANGE_PENDING、
用户 aggregate version 与是否可恢复，不返回 hash、摘要或其他恢复材料。普通用户改密失败后由管理员恢复。

V11 回填版本使存量凭证失效，V12 引入恢复 operation。升级需停旧身份/OAuth 写方；不支持旧新混跑，
回退镜像不能回退权威版本或释放 Pending。恢复材料、备份及读取账号按身份敏感资产管理。profile 遗留 hash 列在改密时改为 external 哨兵，认证只读宿主；Pending 不清理，完成时原子清除恢复 hash，历史备份依密码资产生命周期退役。

## 替代方案

- 同库事务：最简单且可完全原子；独立宿主部署不满足同一连接条件，不作为通用实现。
- XA/两阶段提交：可提供跨库原子性，但增加协调器和运维依赖，当前只需单用户可恢复变更，不采用。
- 宿主单用户 GET_LOCK：能围住宿主写与元库完成窗口，但锁随连接存活、代理连接管理及异常释放更复杂；
  expected-hash CAS 可直接证明迟到写安全，选择 CAS。
- 先写宿主再撤销：代码少，但元库失败会留下旧凭证有效窗口，不采用。
- 仅元库完成 CAS：不能阻止已通过检查的旧宿主写迟到覆盖新密码，不采用。

## 后果与验证

收益是跨库异常期间拒绝认证，并支持幂等恢复；代价是保留 Pending、敏感恢复材料和管理员恢复入口。
版本和撤销即时生效，清缓存只是加速，不承担正确性。认证主库/宿主不可确认时拒绝签发。

真实双 MySQL 测试覆盖宿主提交前失败/回包丢失、元库 begin/complete 回包丢失、同 operation 并发、
旧 A 跨越新 B 后迟到、hash 不匹配和停用拒绝。执行结果与独立评审见
[主工作项](../../../tasks/work-items/DEV-20261028-gateway-completion.md)；测试定义本身不代表通过。
