# ADR-0001：一期元数据库选用 MySQL 8.4

状态：纳入设计基线，待 M0 验证。日期：2026-10-23。

## 背景

review 允许 MySQL 或 PG 在 M0 定案。完整表、索引、事务、备份和审计设计需要先确定一个实现目标，不能让每份文档分别选择。业务库同时支持两种方言，不要求元数据库也支持可切换双实现。

本地若依包含 MySQL 和 PostgreSQL 初始化脚本；选 MySQL 的理由是缩小本期验证组合，不是因为认为若依没有 PG 脚本。

## 决策

一期元库固定 MySQL 8.4/InnoDB，utf8mb4，时间以UTC保存，事务与索引设计按MySQL验证。业务PG数据源独立于元库。采用版本化增量迁移；不自动将参考仓SQL整库覆盖生产。

audit_log 首期不分区，request_id 全局唯一；按create_time索引归档和分批清理。安全版本、refresh轮换和outbox与相关变更使用同一元库事务。

## 替代方案

- PG：可行，也有若依脚本；本期不增加第二套元库集成测试和部署矩阵。
- 双元库运行时适配：增加DDL、事务、审计与恢复组合，收益不足。
- 每个服务独立元库：不利于一期授权族与安全变更的原子性；未来拆分需专门迁移设计。

## 后果与验证

共享物理实例但分别授予服务最小表权限；不能把整个元库管理员账号用于所有服务。M0锁定补丁号、JDBC驱动、字符序/时区，并在MySQL实际执行迁移、唯一键竞争与恢复演练。日后改用PG需新增替代ADR及迁移/回滚计划。
