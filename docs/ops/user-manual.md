# PTMCP 用户操作手册

版本：1.0-design · 日期：2026-10-23 · 状态：基于产品设计编写；部分界面已实现，真实接入和完整验收仍待证据。

本文页面名称表达设计中的功能入口；当前不提供可用生产站点或已验证客户端配置。实际菜单、环境地址、支持客户端版本应由交付版本补充。`*.example.com`是须替换的示例域名。相关常见问题见 [FAQ](../product/faq.md)。

## 1. 你能使用PTMCP做什么

PTMCP让外部Agent在组织规定的范围内查看数据字典、获取有权表的结构并执行只读SQL。Agent负责理解问题和生成SQL；网关负责权限、SQL校验、资源限制与审计。一期支持经测试的MySQL与PostgreSQL，不支持Oracle/SQL Server、写数据、存储过程、行级/列级权限、企业SSO或跨数据源联合查询。

每次查询的实际范围是“个人/角色/部门有效授权”与“当前平台Scope”的交集，并应用显式Deny、有效期和停用状态。即使在一个客户端可以查询，换到Scope较小的平台也可能被拒绝。平台管理员或审计员身份本身不会自动获得业务表读取权限。

页面时间按Asia/Taipei显示；授权和审计持久化为UTC。申请权限时写明业务理由、数据源、数据库/schema、表与有效期，避免只写一个重名库表。

## 2. 账号与角色

| 角色 | 主要入口 | 不自动拥有的能力 |
| --- | --- | --- |
| 普通员工 | 我的字典、接入配置、PAT、我的查询历史 | 管理其他用户、扩大平台Scope、查看他人历史 |
| 组织授权管理员 | 授权矩阵、部门/角色与有效权限预览 | 跨管理范围操作、默认读取所有业务表 |
| 平台管理员 | 数据源、平台、客户端绑定、运行配置 | 绕过员工ACL、自动解密原SQL |
| 安全审计员 | 全局审计和安全事件 | 查询业务数据、未经专门授权解密原SQL |

网页登录与外部Agent OAuth共用账号规则，但一期使用独立会话，不承诺登录一次在所有应用无感通行。连续密码错误5次锁定10分钟；遇锁定按页面提示等待或联系组织账号管理员。不要多客户端反复尝试导致锁定延长。

改密会撤销旧会话/令牌，需要重新登录和授权；正常账号不会因改密自动变成停用。停用/删除后所有新查询和刷新应在约定5秒边界内停止；已发送给Agent的数据无法被网关收回。

## 3. 管理员首次配置

### 3.1 配置数据源与字典

1. 在“数据源管理”新增支持的MySQL或PostgreSQL源，填写唯一显示名、受批准主机/端口、数据库及专用只读账号。PG明确数据库与schema，不能把schema当数据库。
2. 使用“连通测试”核验网络、凭证、只读权限和方言支持；未通过安全执行组合验证的源不能启用。密码以受控方式保存，列表不回显。
3. 执行Schema同步，检查表/列注释与对象状态；完善业务字典说明。避免在注释中写密码、token或真实敏感样本。
4. 新表同步不会自动授予员工READ。表删除重建或视图定义变化需要管理员核对对象版本和授权，不能认为旧同名表的权限当然延续。

### 3.2 配置平台Scope与信任

平台Scope定义该平台最多可以使用哪些数据源/对象。桌面公开客户端、CIMD或动态注册客户端默认最小Scope，管理员核验后显式绑定策略。相同client_id、平台名称或隐藏Header不证明来自受信后端。

Tier1仅用于能验证服务端凭证/网络或mTLS的后端平台；桌面配置不能存组织共享secret冒充该级别。平台关闭、Scope收紧或证明不一致时请求被拒绝；不要让用户修改Header去扩大权限。

### 3.3 配置组织与授权

1. 创建或核对部门、上级关系和角色，将用户加入实际组织；确认是否启用上级部门授权继承。
2. 在“授权矩阵”选择主体（用户/角色/部门）、资源（源/数据库/schema/表）、动作（META或READ）、Allow/Deny、有效起止时间和必要说明。
3. READ Allow包含META；META Deny同时禁止目录/结构/读取；READ Deny仅取消读取，可保留目录可见。Deny优先于任何Allow，默认无授权。
4. 在“有效权限预览”选择具体员工和平台，检查最终可读表、Deny原因、平台限制与生效/到期时刻，不能只看刚添加的一条Allow。
5. 用该员工的实际接入方式测试目录、有权查询和无权拒绝，再完成交付。授权变更对新查询最大5秒生效；若后台提示状态确认故障，应等待恢复，不能让员工绕过网关直连。

部门迁移、角色停用、授权自然到期均可能改变有效权限。审批和业务理由保留在授权记录；需要临时访问时使用明确有效期，不把平台Scope扩大当成个人授权。

组织授权管理员还须由平台管理员授予管理委派：明确可管理的部门根、资源范围、动作上限和到期时间。只能在这些范围内维护授权/组织，不能给自己扩大委派、跨部门管理、授予高于动作上限的权限或延长超过委派期限；菜单可见不代表具有所有组织管理能力。委派本身也不赋予读取业务表的数据权限。

## 4. 员工查看数据字典

登录门户进入“我的数据字典”，选择数据源，再选择数据库；PG还需选择schema。列表上的数据库/表显示名可能重名，复制问题或提交工单时带完整源与命名空间。

目录有两种组织配置：DISCOVER可显示平台内允许披露的表名/表注释，并标记是否能查询；HIDE只显示你具备META/READ的表。显式META Deny优先，因此DISCOVER也不表示全公司所有表可见。

只有具备READ的表才能查看字段名、类型、主外键和字段注释。能看到表名不表示能查看列结构或执行查询；看不到字段时按权限申请流程处理。列级权限一期未实现：申请整表READ前管理员应判断该表是否适合整体披露，不承诺系统会自动屏蔽某些列。

## 5. 通过OAuth接入外部Agent

1. 在门户“接入配置”选择客户端与批准的MCP地址，例如`https://mcp.example.com/mcp`；该地址仅是格式示例，实际地址由管理员提供。
2. 按客户端支持的HTTP MCP配置添加服务器。填写门户生成的非敏感地址/资源信息；不要在URL中添加token、密码或共享client_secret。
3. 客户端发起OAuth后在组织AS页面登录，检查授权平台和Scope后确认。公开客户端使用S256 PKCE；不要把浏览器授权码、回调参数或完整日志截图发给他人。
4. 返回客户端后先查看有权目录/结构，再做一条小查询；保留requestId以便问题定位。网关只注册三个工具：`list_databases_and_tables`、`get_table_schema`、`execute_readonly_sql`。
5. Access Token有效期10分钟。通过验证的公开刷新扩展可在绝对30天/空闲7天内轮换续期；不兼容/未启用的客户端需要重新授权，也可使用组织允许的PAT路径。

**WorkBuddy、Cursor、Claude Code、VS Code的具体版本与公网联调尚未完成。** 本手册不声称四者已经支持自动续期，也不提供未经验证的专有配置片段。正式交付时在门户按真实联调结果展示“已验证OAuth刷新/需重新授权/仅PAT”等状态。旧SSE端点与未验证会话模式不会自动开启。

同一授权的刷新需由客户端串行完成。如果网络丢响应后重新提交旧RT或多个进程并行刷新，安全策略可能撤销整条授权链；重新授权恢复，不反复重试旧token。管理员排障时不需要你的完整令牌。

## 6. 使用和管理PAT

PAT适合组织允许的个人终端或OAuth尚不兼容的客户端，代表你的个人身份，不能作为部门共享账号。默认30天、最长90天，绑定个人终端平台及对应Scope，仍受用户权限、Deny和有效期限制。

1. 进入“我的PAT”，填写可辨认的设备/用途和到期时间，确认当前平台范围后创建。
2. 明文只展示一次。即时保存到客户端支持的凭证库或组织批准的秘密存储；关闭弹窗后无法再次查看，不要要求管理员找回明文。
3. 按实际客户端文档在受控配置中使用`Authorization: Bearer <PAT>`；不放URL、Git、群聊、普通工单、截图或共享网盘。尖括号内容只是占位符，不是实际token。
4. 丢失、离职、更换设备或怀疑泄露时立即在列表撤销；旧PAT在最大5秒边界后不能发起新查询。需要继续使用则新建，不能恢复已撤销token。

PAT不可由`X-Platform-Id`或其他Header提升至更高信任平台。若某客户端只能把secret放在不受控位置，应先联系管理员选择批准接入方式，不能复制其他人的PAT解决。

## 7. 查询、限制与拒绝提示

向Agent提出问题时尽量明确数据源、时间范围、业务口径与需要的列。Agent生成的SQL仍要经过安全检查。工具拒绝通常带错误码、可重试标记和requestId；表越权、语法、危险函数等返回`isError=true`，不是查询成功但没有数据。

| 情况 | 表现与处理 |
| --- | --- |
| TABLE_NOT_AUTHORIZED或明确Deny | 停止重复尝试；向授权管理员申请对应表/平台权限，提供requestId与业务理由 |
| 能看表名但取不到列 | 当前仅META或目录展示；申请READ，不通过猜列名绕过 |
| 账号/平台/令牌无效 | 重新登录/授权；确认平台未停用、PAT未到期或被撤销 |
| 不支持SQL/函数/类型 | 简化为受支持只读SELECT，结构读取使用专用工具；不使用SHOW/EXPLAIN/递归CTE等未开放语法 |
| 查询超时/排队或并发限制 | 缩小时间范围/返回列，稍后按retryable提示限次重试；不让多个Agent无限并发 |
| truncated=true | 达到行数、单格或总字节预算；查看截断原因，收紧查询；不能把截断数据当完整统计 |
| 系统无法确认安全状态/审计不可写 | 服务会拒绝新查询，联系运维；重复换token不会解决 |

默认最多500行、单格4KiB、完整响应1MiB；单用户最多3个活动查询。调用者可收紧行数，不能提高上限。大字段、复杂JSON/LOB或无法安全限幅的表达式可能被拒绝；输出限制不保证所有原始值都返回。截断标记在元数据中，不会把字面字符串`[TRUNCATED]`伪装成真实字段值。

DECIMAL和BIGINT为保持精度以字符串输出，NULL保留null；字段名重复时按列序理解结果。需要完整报表/导出或长时间查询时按组织既有报表渠道处理，一期网关不是无限量数据导出工具。

## 8. 查看历史与审计

“我的查询历史”只能查看本人调用，包含时间、平台、数据源、脱敏SQL/指纹、结局、耗时、行数/截断与requestId；它不是长期查询结果备份。客户端断开/服务崩溃导致结局无法确认时可显示UNKNOWN，不能理解成数据库没有执行，也不要自动重跑可能高成本的查询。

普通员工不能通过修改userId或链接获取别人历史。管理员审计列表默认展示脱敏SQL；原SQL可能含姓名、证件等字面量，只有专门授予解密能力的安全人员可按规定查看，解密行为也被审计。审计在线/归档保留180天；封存备份按运维保留政策到期销毁。

## 9. 提交问题与使用边界

提交问题时提供requestId、发生时间（标注Asia/Taipei）、客户端名称/版本、所选源与数据库/schema、错误码、是否重现和脱敏后的业务描述。不要提交密码、完整Authorization头、PAT、RT、原始敏感结果或包含这些信息的配置文件。

身份问题联系账号管理员；表授权/目录问题联系组织授权管理员；平台Scope和接入配置联系平台管理员；超时、状态确认或审计故障联系运维。真实支持通道由上线环境交付，不编造邮箱/群号。
