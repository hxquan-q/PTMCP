整个系统的技术路线和业务边界已经非常清晰了。我们将这套系统定名为 **PTMCP（Permission-controlled Text-to-SQL MCP Gateway，权限管控型问数 MCP 安全网关）**。

它的核心定位是：**一个轻量级、中心化的“薄网关（Schema 过滤 + AST 静态安全拦截 + 只读 SQL 执行器）”**，不捆绑大模型推理，专门为各类 Agent 平台（如 Workbuddy、自研 Agent 平台、Cursor/Claude 等）提供带权限隔离的数据底座。

# PTMCP 企业级问数安全网关 — 完整需求规格书

## 一、 系统总体架构与核心交互流

系统采用 **“双层凭证校验（平台级 Header + 用户级 OAuth/Token） + AST 语法树静态拦截”** 的架构设计：

```
[外部 Agent 平台: Workbuddy / 自研平台 / IDE]
       │
       │ 1. 携带【平台 Header 凭证】(X-Platform-Key) 
       │ 2. 携带【用户级凭证】(OAuth2 AccessToken 或 个人专属 MCP Token)
       ▼
┌─────────────────────────────────────────────────────────────┐
│                   PTMCP 远程网关服务 (SSE / HTTP)            │
│  ┌──────────────┐   ┌────────────────┐   ┌───────────────┐  │
│  │ 平台与身份鉴权 │──▶│ 权限矩阵取交集  │──▶│  MCP Tools    │  │
│  │ (OAuth2/Key) │   │ (平台 ∩ 用户)   │   │  暴露与路由    │  │
│  └──────────────┘   └────────────────┘   └───────┬───────┘  │
│                                                  │          │
│  ┌───────────────────────────────────────────────▼───────┐  │
│  │            SQL 安全沙箱与 AST 静态拦截引擎              │  │
│  │  1. 只读校验 (仅 SELECT)   2. 库/表越权静态拦截并提示    │  │
│  │  3. 字段级/行级过滤(二期)  4. 强制分页与超时熔断         │  │
│  └───────────────────────────────────────────────┬───────┘  │
└──────────────────────────────────────────────────┼──────────┘
                                                   │
                     动态路由至对应连接池            ▼
       ┌──────────────────────┬────────────────────┴───┐
       ▼                      ▼                        ▼
 [ERP 数据库 (只读)]    [业务库 MySQL]          [数仓 PostgreSQL]
```

## 二、 功能模块需求详述

### 模块 1：双重认证与“平台驱动”接入管理（核心机制）

为了同时管控“哪个 Agent 平台连过来的”以及“具体是哪个员工在问数”，系统采用**平台凭证 + 个人凭证取交集**的机制：

1. **平台级管控（Platform Header 驱动）**
   - **需求描述**：管理员在后台为不同的外部 Agent 平台（如 `Workbuddy`、`自研Agent平台`）注册【平台应用】，分配专属 Header 凭证（例如 `X-Platform-Id` 和 `X-Platform-Secret`），并圈定该平台允许访问的**最大数据源集合**。
   - **作用**：即便某个高管拥有全库权限，如果他在一个被限制只能访问“测试库”的外部第三方 Agent 平台上提问，最终也只能查测试库的数据（**最终权限 = 平台允许范围 ∩ 用户个人权限范围**）。
2. **用户级认证（OAuth 2.0 首次登录授权 + 个人专属 Token 双模式）**
   - **模式 A（MCP 标准 OAuth 2.0 授权流 — 主推）**：
     - 管理员给所有员工下发**完全相同的原始通用 MCP 配置地址**。
     - 当员工在 Agent 平台首次发起调用连接时，触发 MCP 的 OAuth 2.0 认证流程，弹出 PTMCP 登录页。
     - 员工输入管理员预先分配好的**账号密码**完成登录，网关自动签发绑定该员工身份的 `Access Token`（支持 Refresh Token 自动续期），后续无感调用。
   - **模式 B（个人专属静态 Token — 兼容兜底）**：
     - 针对部分不支持弹出 OAuth 登录框的简易 Agent 客户端，允许员工登录 PTMCP 网页后台，手动生成/复制自己的 `Personal-MCP-Token`，直接拼接在连接 URL 或 Header 中使用。

### 模块 2：多数据源连接池与元数据（Schema）中心

1. **多异构数据源管理**
   - 支持动态添加、编辑、启停主流数据库（MySQL、SQL Server、PostgreSQL、Oracle 等）。
   - **连接池管理**：配置连接地址、端口、数据库账号密码、最大连接数、空闲超时时间，支持一键“测试连接”。
2. **Schema 元数据同步与字典维护**
   - 自动抓取并缓存已接入数据库的：库名（Database/Schema）、表名（Table）、字段名（Column）、字段类型及原始注释（Comment）。
   - 支持管理员在后台手动补充/修改表的“业务别名”和“问数业务说明”（帮外部 Agent 的大模型更准确地理解表含义，比如给 `t_sal_order` 补充说明“销售订单主表”）。

### 模块 3：分阶段权限管控体系（RBAC + 数据范围）

根据你的规划，权限体系按 **两期演进** 落地，确保一期快速上线，底层表结构预留二期扩展能力：

| **阶段**         | **组织与账号来源**                                           | **数据权限颗粒度**               | **静态拦截与检索表现**                                       |
| ---------------- | ------------------------------------------------------------ | -------------------------------- | ------------------------------------------------------------ |
| **一期（MVP）**  | **内置账密体系**：管理员在后台创建部门、角色与员工账号密码，支持按“部门/角色”批量授权，或按“个人”单独授权。 | **数据源级 + 库级 + 表级**       | **元数据可见但数据拦截（或按配置隐藏）**：Agent 探查结构时能读到表名，但一旦生成的 SQL 包含未授权表，AST 引擎直接静态拦截，不查数据库，返回标准提示：*“权限不足：当前账号无权查询表 `[xxx]`，请联系管理员申请权限。”* |
| **二期（进阶）** | **ERP 组织架构同步**：定时同步或 Webhook 接入现有 ERP 系统的【组织-部门-人员-岗位】，自动映射权限。 | **字段级（列级） + 行级（RLS）** | **列级拦截**：SQL 中若 `SELECT` 或 `WHERE` 包含了敏感未授权字段（如 `salary`），直接拦截并提示字段越权。 **行级注入**：AST 自动改写 SQL，强制注入过滤条件（如 `WHERE dept_id = '当前用户部门'`）。 |

### 模块 4：薄网关 MCP Tools 接口设计与安全沙箱

PTMCP 作为薄网关，本身不调用大模型，而是向外部 Agent 暴露以下 **3 个核心标准 MCP Tool**：

1. `list_databases_and_tables`（获取库表目录）
   - **入参**：可选搜索关键字。
   - **逻辑**：根据当前上下文的【平台权限 ∩ 用户权限】，返回数据库中所有的表清单、表注释，并明確标记每张表当前用户的访问状态（`authorized: true/false`）。
2. `get_table_schema`（获取表结构详情）
   - **入参**：`database_name`, `table_name` 列表。
   - **逻辑**：返回指定表的字段名、类型、主外键关系及注释（二期在此处过滤掉完全保密的敏感列，或标记为无权查询）。
3. `execute_readonly_sql`（安全执行只读 SQL）
   - **入参**：`database_name`, `sql_query`。
   - **安全沙箱执行流水线（重点）**：
     - **Step 1 语法树解析（AST Parsing）**：使用 SQL 解析器（如 Python 的 `sqlglot` 或 Java 的 `JSQLParser`）将传入的 SQL 解析为抽象语法树。
     - **Step 2 只读红线校验**：严格校验语句类型，**仅允许 `SELECT`（及必要的 `SHOW`/`DESC`/`EXPLAIN`）**；凡包含 `INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE / GRANT` 或多语句拼接（`;` 注入）的，一律阻断并记录高危告警。
     - **Step 3 越权表静态拦截**：提取 AST 中所有的 `Table` 节点（含 `JOIN`、子查询、`CTE` 中的表），与当前用户的授权表清单比对。一旦发现未授权表，**立即中止执行（不触达真实数据库）**，返回友好的结构化拒止提醒，引导 Agent 告知用户缺哪张表的权限。
     - **Step 4 性能保护改写**：若 SQL 未包含 `LIMIT` / `TOP`，AST 自动在最外层追加默认限制（如 `LIMIT 500`），并设置数据库连接级 Timeout（如 15 秒超时自动熔断），防止慢 SQL 拖垮业务库。

### 模块 5：Web 双视角后台看板（账密登录）

系统提供统一的 Web 登录入口，根据登录账号的角色自动渲染对应的工作台：

#### 1. 管理员视角（Admin Console）

- **数据源管理台**：增删改查数据库连接、测试连通性、触发 Schema 同步、维护表/字段业务注释。
- **组织与账号管理**：创建部门树、添加员工账号（生成初始密码）、管理角色组（预留 ERP 组织同步按钮）。
- **平台驱动管理**：注册外部 Agent 平台（如 Workbuddy、自研平台），生成 `Platform Header Key`，配置该平台可访问的数据源白名单。
- **权限配置矩阵（核心交互）**：
  - 左侧选择【部门 / 角色 / 具体人员】，右侧以树状结构勾选【数据源 -> 数据库 -> 数据表】（二期展开到字段与行级规则）。
- **全局问数审计日志（Audit Log）**：
  - 记录每一次 MCP 工具调用：调用时间、来源 Agent 平台、提问员工账号、目标数据库、**实际执行的 SQL 语句**、拦截状态（成功 / 越权拦截 / 语法错误 / 非只读阻断）、耗时及返回行数。支持按人员或越权告警筛选。

#### 2. 普通用户视角（User Portal）

普通员工使用自己的账密登录后台后，界面极简清晰，聚焦于两件事：

- **我的数据字典（被授权范围看板）**：
  - 直观查看自己当前拥有哪些数据库、哪些数据表的查询权限，支持搜索表名和查看表内的字段字典与业务含义（方便员工自己在向 Agent 提问前，知道有哪些数据可问）。
- **MCP 接入凭证中心**：
  - **一键复制通用 MCP 配置**：展示标准 JSON 配置块（含 OAuth 地址），供员工直接粘贴到支持 OAuth 的 Agent 客户端。
  - **个人专属密钥管理（Personal Token）**：支持生成、查看、重置、吊销个人的静态 `MCP Access Key`，并展示自己近期通过各个 Agent 平台发起的 SQL 查询历史记录（方便自我排查刚才 Agent 为什么报权限不足）。
