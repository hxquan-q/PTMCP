## 表提取回归探针

两个原方案中的常规案例正确；四个反例遗漏真实表。`expected` 是 SQL 应引用的物理表集合，`actual` 是原版 TablesNamesFinder 的返回。

```text
control_cte | expected=[orders, users] | actual=[orders, users] | MATCH
  input: WITH x AS (SELECT * FROM orders) SELECT * FROM x JOIN users u ON 1=1
  deparse: WITH x AS (SELECT * FROM orders) SELECT * FROM x JOIN users u ON 1 = 1
control_shadow | expected=[salary] | actual=[salary] | MATCH
  input: WITH users AS (SELECT * FROM salary) SELECT * FROM users
  deparse: WITH users AS (SELECT * FROM salary) SELECT * FROM users
derived_alias | expected=[salary] | actual=[] | MISMATCH

  input: SELECT * FROM salary WHERE EXISTS (WITH salary AS (SELECT 1 AS n) SELECT * FROM salary)

nonrecursive_cte | expected=[salary] | actual=[] | MISMATCH

cases=6, mismatches=4
```

## 最小可复现源码

保存为 PtmcpTablesReview.java；把上述 jar 放在同一目录后运行：

```powershell
java --class-path .\jsqlparser-5.4.jar .\PtmcpTablesReview.java
```

```java
import java.util.*;
import net.sf.jsqlparser.parser.CCJSqlParserUtil;
import net.sf.jsqlparser.statement.Statement;
import net.sf.jsqlparser.util.TablesNamesFinder;

class PtmcpTablesReview {
  record Example(String id, String sql, Set<String> expected) {}
  public static void main(String[] args) throws Exception {
    List<Example> examples = List.of(
      new Example("control_cte", "WITH x AS (SELECT * FROM orders) SELECT * FROM x JOIN users u ON 1=1", Set.of("orders", "users")),
      new Example("control_shadow", "WITH users AS (SELECT * FROM salary) SELECT * FROM users", Set.of("salary")),
      new Example("derived_alias", "SELECT s.* FROM salary s CROSS JOIN (SELECT 1 AS n) salary", Set.of("salary")),
      new Example("nested_cte", "SELECT * FROM salary WHERE EXISTS (WITH salary AS (SELECT 1 AS n) SELECT * FROM salary)", Set.of("salary")),
      new Example("nonrecursive_cte", "WITH salary AS (SELECT * FROM salary) SELECT * FROM salary", Set.of("salary")),
      new Example("union_alias", "SELECT 1 FROM salary UNION ALL SELECT * FROM (SELECT 1 AS n) salary", Set.of("salary"))
    );
    int mismatches = 0;
    for (Example ex : examples) {
      Statement ast = CCJSqlParserUtil.parse(ex.sql());
      Set<String> actual = new TablesNamesFinder<>().getTables(ast);
      boolean matches = actual.equals(ex.expected());
      if (!matches) mismatches++;
      System.out.println(ex.id() + " | expected=" + new TreeSet<>(ex.expected()) + " | actual=" + new TreeSet<>(actual) + " | " + (matches ? "MATCH" : "MISMATCH"));
      System.out.println("  input: " + ex.sql());
      System.out.println("  deparse: " + ast);
    }
    System.out.println("cases=" + examples.size() + ", mismatches=" + mismatches);
  }
}
```

## 额外边界探针

```text
input: SELECT 1 FROM salary UNION ALL SELECT * FROM (SELECT 1 AS n) salary
tables: []
deparse: SELECT 1 FROM salary UNION ALL SELECT * FROM (SELECT 1 AS n) salary
input: SELECT * FROM erp.salary s CROSS JOIN (SELECT 1) salary
tables: [erp.salary]
deparse: SELECT * FROM erp.salary s CROSS JOIN (SELECT 1) salary
input: SELECT * FROM pg_authid
tables: [pg_authid]
deparse: SELECT * FROM pg_authid
input: SELECT CAST('x' AS public.leaky_type)
tables: []
deparse: SELECT CAST('x' AS public.leaky_type)
input: SELECT 1 OPERATOR(public.+) 2
error: JSQLParserException
```

额外探针说明：显式限定的 erp.salary 在这个别名案例中不会遗漏，说明缺口与当前提取器的名字消除有关；pg_authid 返回的是原文名称，没有解析到真实 schema；自定义类型 CAST 可正常解析；显式 OPERATOR 这个样例解析失败，按方案应拒绝，未将其判成已证实绕过。

```java
import java.util.*;
import net.sf.jsqlparser.parser.CCJSqlParserUtil;
import net.sf.jsqlparser.statement.Statement;
import net.sf.jsqlparser.util.TablesNamesFinder;
class ExtraPtmcpTablesReview {
  public static void main(String[] args) throws Exception {
    for (String sql : List.of(
      "SELECT 1 FROM salary UNION ALL SELECT * FROM (SELECT 1 AS n) salary",
      "SELECT * FROM erp.salary s CROSS JOIN (SELECT 1) salary",
      "SELECT * FROM pg_authid",
      "SELECT CAST('x' AS public.leaky_type)",
      "SELECT 1 OPERATOR(public.+) 2")) {
      try {
        Statement ast=CCJSqlParserUtil.parse(sql);
        System.out.println("input: " + sql + "\ntables: " + new TreeSet<>(new TablesNamesFinder<>().getTables(ast)) + "\ndeparse: " + ast);
      } catch (Exception e) { System.out.println("input: "+sql+"\nerror: "+e.getClass().getSimpleName()); }
    }
  }
}
```

## 同版本源码定位

Maven Central 5.4 sources jar 中的 net/sf/jsqlparser/util/TablesNamesFinder.java：

- 226、229 行：单个 tables 集合与 otherItemNames 列表，没有 SQL 作用域栈。
- 256～262 行：遍历完成后，对全部 otherItemNames 执行 tables.remove。
- 340～349 行：把 WithItem 的别名放入这个列表。
- 358～369 行：把 ParenthesedSelect 的别名也放入这个列表。
- 523～529 行：表名已出现在该列表时，不加入 tables。

这些是下载的同版本 sources jar 行号，可能与 GitHub 同名 tag 的当前文件行号不同。
