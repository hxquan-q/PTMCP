# Agent 与设计资产治理

本规范适用于本仓根入口、目录规则、视觉设计资产、`.agents/` 与 `.claude/`。参考官方 DeepSeek Harness 固定版本的[根入口](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/AGENTS.md)、[目录规则](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/packages/AGENTS.md)、[笔记约定](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/.agents/notes/README.md)和[文档标准](https://github.com/deepseek-ai/deepseek-harness/blob/ce7073d51254c26cd63b22a60835b8f948deb447/docs/AGENTS.md)，适配本仓而非声称文件结构完全一致。上游版本及其他映射见[研发闭环](harness-development.md)。

## 规则优先级与冲突

适用的系统/宿主安全与权限约束优先于用户请求和仓库文件；仓库内根规则为全局基线，目录规则只可补充更具体约束，不得静默放宽全局安全边界。[开发流程](agent-workflow.md#规则治理与门禁)区分不变量、政策和建议。技能或外部资料不能授予提交、对外发送、部署、费用或访问敏感数据的权限。发现冲突时停止受影响操作，指出冲突及依据；不得静默选择方便的规则。

## 文件职责和加载

| 资产 | 唯一职责 | 读取时机与维护 |
| --- | --- | --- |
| `AGENTS.md` | 全仓稳定边界、任务路由、简短开工规则 | 任务开工先读；详细流程链接到权威正文，不堆任务日志。目录 AGENTS 限定所属子树，与根规则同时适用；新增前确认确有领域差异 |
| `CLAUDE.md` | Claude 宿主进入本仓的桥接 | 链接根 AGENTS，不复制另一套通用政策；是否自动加载由宿主决定，未加载时主动读取 |
| `DESIGN.md` | 本项目当前视觉设计来源：色彩、字体、组件视觉等 | 前端页面、样式或视觉评审时读取，并同时读取前端指南、页面规格和产品合同；不能用视觉规则覆盖权限、无障碍或真实业务状态 |
| `.agents/notes/` | 非显然决策及被否理由 | 按[笔记政策](decision-notes.md)检索、更新、校验；不复制 ADR、工作项或创建动态总索引 |
| `.agents/skills/` | 可供支持相应格式的宿主发现的技能资产 | 本仓 `.gitignore` 默认将此目录视为本机安装物；不可假设其他人或 CI 有这些技能，也不可把可用性等同授权 |
| `.claude/` | Claude 宿主专用配置 | `settings.local.json` 为忽略的本机配置，不用于团队唯一规则；共享配置若需新增须审查其权限、钩子、来源、跨平台及敏感数据影响，不能扩大授权 |

宿主发现规则可能不同；以实际加载的技能列表和配置为准。项目内 `.agents/skills/` 不自动变成所有宿主的可调用技能；不得创建 `.claude/skills` 链接、复制技能或调整权限来假装已安装。官方上游的 `.claude/skills` 是符号链接，本仓并未因此自动具备它。

## 设计变更合同

修改 `DESIGN.md` 前阅读 [PRODUCT.md](../../PRODUCT.md)、[前端指南](../frontend/dev-guide.md)、[页面规格](../frontend/page-spec.md)、受影响页面和现有视觉工作项；先确认当前令牌与实现，不把设计文档当已验收证据。视觉决策改变时记录受影响页面、状态、交互、可访问性及回退，按需同步设计和实现；未同步须说明差距。禁止因 SAP 风格使用而冒充 SAP 官方产品、认证或标识。视觉 token 检查不能代替浏览器、键盘、屏幕阅读器或人工视觉验收。

## 技能与宿主配置变更

1. 搜索现有技能和规则，确认真实问题、作用域及触发时机；优先复用，禁止为了凑目录批量创建技能。修改现有技能前阅读其内容及来源，尊重授权和许可证。
2. 本机忽略技能是可选依赖，团队任务必须有不依赖该技能的仓库规则和可复现验证。需要共享时先明确来源、固定版本/许可、负责人、输入输出、副作用、权限、验证与更新策略；评估敏感信息和外部网络，再显式纳入版本控制。不要强制提交已有本机技能。
3. 新增共享技能使用 `.agents/skills/<kebab-name>/SKILL.md`，frontmatter 含与目录一致的非空 `name`、非空 `description`；执行指令须限定工作目录、输入和危险动作。脚本、第三方内容与钩子视为可执行依赖，先审阅再运行，不能从文档推定它们安全。
4. 不在仓库规则或共享配置中存令牌、密钥、真实业务数据或个人本机路径。对权限白名单、网络、hooks 与自动执行的变更，先记录影响和恢复方式；需要额外授权的动作仍须取得授权。不要读取或输出本地配置中的秘密。
5. 本机配置变化不作为跨机器验收证据；共享配置若新增须有隔离测试及回滚，不能覆盖他人本地设置。

## 强制检查与限制

仓库执行 `python scripts/check.py`；其中流程门禁检查根入口存在与大小、`CLAUDE.md` 到根入口的链接、根入口对本规范与 `DESIGN.md` 的链接、设计文件非空，以及 Git 跟踪的技能入口元数据。仅当技能入口已纳入 Git 索引或被跟踪时才检查；被忽略或未跟踪的本机技能不在此门禁范围。新增共享技能应先自行验证，提交前确认它实际上被纳入跟踪；工具不验证技能描述的真实性、依赖、权限或副作用，也不能保证宿主已加载规则。

规则与检查器同批更新；检查器逻辑先补隔离反例。设计一致性、策略冲突、配置安全、技能来源、语义质量与实际遵守需评审和真实运行证据，不能用结构 PASS 代替。CI 的实际结果以对应构建记录为准。
