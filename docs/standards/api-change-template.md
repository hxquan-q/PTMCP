# 接口变更合同模板

本模板用于新增或变更 REST、OAuth、MCP 接口，也适用于行为不变但外部可观察格式变化的迁移。开发者在相关工作项中填写并链接到现有权威契约；内容简单时直接写入工作项，不复制整份 API 文档。已有事实填真实值，不适用写原因；不能用占位符作为完成证据。

## 基本信息和状态

- 需求与工作项：关联 FR、工作项、关联 ADR/Note、调用方及负责人。
- 协议和边界：REST 方法/完整路径，或 OAuth 标准端点，或 MCP 方法/工具名；明确服务、认证域、功能码/作用域及资源范围。
- 状态分别注明：设计（目标/已裁决）、实现（代码版本与入口）、验证（PASS/FAIL/NOT_RUN/BLOCKED、环境与证据）、人工接受和发布。不能用“已完成”覆盖全部状态。
- 权威合同位置：REST/OAuth/MCP 在 [API 契约](../backend/api-spec.md)对应章节维护；MCP 输入同步 [机器可读 Schema](../backend/mcp-tools.json)；不另造第二份冲突基线。

## 输入与输出

| 项目 | 必填内容 |
| --- | --- |
| 认证与授权 | 身份来源、动作权限、资源/委派范围、平台与用户权限交集；拒绝时的可见性 |
| 输入 | 路径、查询、头和正文各字段类型、必填、空值/默认、长度/字节、枚举、校验和敏感级别；请求示例仅用合成数据 |
| 输出 | HTTP 状态及协议响应形状；字段类型、可空性、顺序/分页、截断/版本；成功及代表性失败示例 |
| 错误 | 稳定业务码与 HTTP/协议状态、重试条件、requestId；不得输出凭据、真实 SQL、连接串或栈 |
| 并发与副作用 | CSRF、If-Match/ETag、幂等键、原子性、冲突、超时、取消、未知结局；不适用说明原因 |
| 生命周期 | 创建/撤销/删除语义、过期、密钥一次展示、审计和保留要求（按适用范围） |

REST 遵循目标 `R<T>`、HTTP 状态、分页与幂等约定；现有裸 DTO 是待收敛的实现差异，不能把目标示例写成现网响应。OAuth 使用其标准请求/错误和发现响应；MCP 使用 JSON-RPC/工具结果，不能套 REST 外壳。详细参数和协议规则以 API 契约及 ADR 为准。

## 兼容与迁移

- 写明旧/新行为、受影响调用方、字段和错误码兼容性、版本策略、部署顺序、回滚或收窄方案；不兼容变化须先更新相应设计并处理调用方。
- 对权限、安全、数据格式或持久化不变量的变化，明确反例及恢复策略；不得静默降低已有边界。
- 不输出真实个人信息、凭据、业务查询或结果。日志、示例及证据采用合成数据。

## 实施与验证

- 列出相关后端、前端、调用方、Schema、测试、文档的更新位置，以及可复现的最小验证命令、环境、结果和未测项。
- 至少覆盖成功、未认证/无权、输入非法、边界与协议错误；适用时覆盖并发、版本冲突、重复请求/未知结局、取消、超时、撤权与敏感数据泄漏。真实数据库/客户端或独立安全评审是否必要，按[研发流程](agent-workflow.md)和[测试计划](../test/test-plan.md)判断。
- 同批同步权威契约、调用方和测试；不能同批完成时记录不兼容风险、限制开关/发布条件及未完成项。设计变更本身不证明代码或部署已完成。
