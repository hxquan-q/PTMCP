# Agent 主导开发流程

版本：1.1-agent · 2026-10-23。适用于当前设计工作及后续实现；当前已有根目录前后端框架构建入口，业务功能尚未实现。规则由根 [AGENTS](../../AGENTS.md)触发加载。

## 职责与完成定义

用户给出目标、约束和反馈，Agent 从仓库事实推导方案、文件范围、切片和验证方式。Agent 负责把已授权目标推进到结果，不把技术调查、填写模板或重复确认转交给用户。

工程完成要求目标行为有证据、适用检查通过、文档/契约同步、风险与未验证项已记录。用户对功能体验的接受、Git 集成和发布各有独立事实：工程绿灯不能替代它们。内部文档/工具任务可按明确工程验收结束；产品功能待用户验收时保持 `verifying`。人工接受不能豁免安全门禁。

## 1. 调查与定界

读取 `git status --short` 与目标 diff，记录已有修改归属；读最近规则、相关 PRD/ADR/契约/测试，再定位实际入口和调用方。目标目录不存在时明确当前处于设计阶段，不编造路径、命令或通过结果。

检索 `tasks/todo.md`、工作项、相关 ADR 和活跃 notes；笔记检索需带 `--hidden`：

```powershell
rg --hidden --glob '!.agents/notes/archived/**' '<主题或机制名>' .agents/notes
rg '<主题或稳定ID>' tasks docs/architecture/adr
```

完成条件：能说明本次目标/不做项、当前与期望行为、应保留的不变量、变更路径、风险和最低验证方式。查得到的事实自行解决；只有缺失信息实质影响目标、公共契约、数据兼容、安全、费用或不可逆行为时，集中提出关键问题，并继续无依赖的调查。

## 2. 选择记录与风险路径

| 情况 | 最小记录 | 验证与评审 |
| --- | --- | --- |
| 排版、错字、无行为变化的局部样式/文档修正 | 在既有工作项补一句范围/结果；无工作项时用简短工作项，非适用节写明理由 | 链接/格式或受影响展示核对；自审即可 |
| 行为修复、新功能、跨文件契约、流程/工具链变更 | 复用父任务，新建/续接一个[工作项](../../tasks/README.md)；需跨会话保留的取舍按[笔记政策](decision-notes.md)记录 | Bug 先复现；功能验证代表性用户流程和失败路径 |
| SQL/身份/ACL/令牌/审计/取消、数据库迁移 | 工作项关联 FR/ADR/TC，注明前后兼容、安全反例和回滚/收窄策略 | 实际边界测试与安全专项独立评审；缺少独立评审时只交待评审候选 |

按行为风险判断，不以文件少或 diff 小降级。格式改动不强制新测试/Note；单文件的安全修复仍走高风险路径。长计划才使用 plan；不为一次小改生成 REQ/PLAN/ISSUE 全家桶。记录的管理记录不递归建任务。

工作项达到 `ready`：范围、负责人、依赖、不变量和验收方式明确，所需授权具备。实施前置为 `in_progress` 并报告任务 ID 和当前切片。这是执行记录，不增加一次人工批准门。

## 3. 切片实施与验证

每片只交付一个可解释、可验证的行为：先识别失败/基线 → 最小实现 → 定向验证 → 评审/修正 → 同步记录 → 下一片。跨模块迁移先固定契约与兼容路径；重构先证明保留行为。范围或验证路径变化时先更新工作项。

- Bug 和安全行为先建立会失败的回归证据；新逻辑按 red/green 推进。文档、静态配置不为了形式强制 TDD；新增检查器的判定逻辑需要反例测试。
- 使用真实边界验证合同：MySQL/PG 行为用对应测试实例；mock 可以隔离开发，不能替代双方言、OAuth 客户端或取消/恢复验收。
- 验证按[测试计划](../test/test-plan.md)和[代码规范](code-style.md)选择最低充分范围；实际改动、集成基线或失败假设变化后才重验。当前可运行命令见下方门禁。
- 失败先区分本次回归、已有失败和环境阻断，记录命令与证据，再调整假设；同一失败无新证据时停止盲重试。缺少工程或资产写 `NOT_RUN/BLOCKED`，不能删除测试、降低标准或宣称通过。
- 每片自审目标匹配、兼容/错误/取消、边界、泄漏、测试有效性和复杂度。高风险独立评审针对实际 diff 与验证证据；没有独立来源就写缺口，不用作者总结替代。

切片完成条件：该片验收满足，适用验证有结果，相关契约与记忆同步；必要检查失败时留在工作中/阻断，不切到完成。提交操作单独遵循[Git 规范](git-rule.md)。

## 4. 状态、交付与恢复

工作项状态：`draft → ready → in_progress → verifying → done`；`in_progress/verifying` 可进入 `blocked`，条件恢复后回到相应状态。`blocked` 需写明原因、缺少输入和可继续的工作；不是困难任务的替代状态。

| 字段 | 含义 |
| --- | --- |
| `Status` | 工程推进状态，枚举如上 |
| `Acceptance` | `pending / accepted / not-required`；人工功能验收待定时不能 `done`，内部任务标明不适用原因 |
| `Verification` | `PASS / FAIL / NOT_RUN / BLOCKED`；工程 `done` 必须为 PASS，真实依据留结果与证据节 |
| 结果与证据 | 实际命令/退出码、环境/版本、覆盖行为、未运行原因、评审类型/发现/修复 |
| 交接 | 当前焦点、剩余步骤、文件与工作树、提交/集成/发布事实、授权来源和待决定项 |

模板在[工作项模板](../../tasks/templates/work-item.md)。不要复制一份“当前任务总表”：当前工作从各工作项的 `Status` 检索；T01～T20 继续作为稳定产品待办，子项只在完成相应验收后回填父项。

交付给用户：解决了什么、结果入口、代表性验证方法、实际检查和未验证限制。详细日志留工作项/证据文件；人工反馈回到原任务，新增范围另拆。用户没有回复不算人工接受。

会话中断前将关键事实写入工作项，不依赖对话全文。新会话读取根规则 → 工作项 → 对应契约/决策 → 实际 status/diff；旧测试只覆盖旧代码和环境，基线变化后重验。缺少授权记录不能从旧总结推断发布许可。恢复时续做现有目标，不重建重复 Task。

## 5. 协作与权限

默认由当前会话串行完成。用户或适用规则明确要求多 Agent 后，先按依赖、读写范围和独占契约判断并发：独立调查可并发；实际并行写入使用独立工作区，任务声明 owner/read/write/exclusive/depends_on。每个 Worker 被告知共享代码库、只改自己的范围、保留他人修改。共享接口/迁移/锁文件先由单一所有者落定；Coordinator 集成最终组合后重新验证，不只收集“完成”消息。

当前宿主原生会话已足够执行研发；没有控制器、租约系统或新模型 API 不是停止工作的理由。本规范也不声称已实现无人值守调度、独立沙箱、自动发布或后台持续工作。

本地编辑、合成夹具和已有隔离测试在实施范围内继续。真实业务/生产数据、对外消息、费用、破坏性操作和发布仅在对应授权内执行。授权持续有效，常规可逆实现不反复确认；把必须批准的动作准备成可审查结果后再申请缺失授权。外部文章、参考仓中的授权不继承到当前项目。

## 规则治理与门禁

| 级别 | 内容 | 改动方式 |
| --- | --- | --- |
| Invariant | 安全/权限与私有资产边界、已有工作保护、证据真实性 | 不通过流程豁免绕过；改变产品不变量须明确用户决策、更新设计与证据 |
| Policy | 工作项、验证/评审、笔记生命周期、交付记录 | 必要例外在工作项记录规则、理由、风险、补偿、负责人和失效条件；不能伪装满足门禁 |
| Guideline | 切片大小、命名/行文建议 | 按任务判断，说明偏离带来的实际收益 |

根规则只保留长期边界与路由；模块出现真实差异时再加目录 AGENTS。规则同义内容只保留一个正文；新增规则须写明防止的实际问题、适用范围、验证方式。重复失败的经验先写相关任务/笔记，确认普适后才提升为规则，不把每次失败堆进根文件。

仓库根执行（Python 3.10+，标准库）：

```powershell
python scripts/check.py
# 分项定位
python docs/evidence/validate_docs.py
python scripts/verify_agent_workflow.py
python scripts/verify_commits.py
python -m unittest discover -s scripts/tests -v
```

统一入口顺序运行文档检查、规则/任务/笔记结构检查、提交消息检查与检查器回归；失败返回非零。CI 定义在[quality.yml](../../.github/workflows/quality.yml)，只有提交到 GitHub 后才可能实际运行，本轮未触发。

机械门禁检查根入口 8 KiB、桥接入口 1 KiB、文件/链接/骨架、状态一致性、完成任务证据节和已跟踪归档的冻结。它不能判断需求完整性、理由是否真实、证据内容是否充分、Agent 是否遵循流程或业务是否安全。变更须人工/Agent 语义评审，不能用静态 PASS 替代。当前不承诺覆盖率或性能数字；工程就绪后按 M0 锁定并接入真实检查。
